# Regular MUD 상호작용 해결책·게임성 아이디어 옵션

> 상태: `exploration` — 확정 요구사항·구현 계획이 아니다.
> 근거: [`regular_interaction_diversity_audit.md`](../audits/regular_interaction_diversity_audit.md), [`regular_gameplay_red_team_audit.md`](../audits/regular_gameplay_red_team_audit.md)
> 원칙: 실제 구현은 우선순위 승인과 별도 `implementation_plan_*.md` 작성 후 진행한다.

## 1. 설계 목표

문제는 원을 사용한다는 사실보다 **원을 누른 뒤 무엇을 판정하는가**에 있다. 새 설계는 상호작용을 세 층으로 나눈다.

```text
입력: 무엇을 눌렀는가
추론: 단서 사이에 어떤 관계를 만들었는가
결과: 그 판단 때문에 무엇이 달라졌는가
```

현재 Regular는 첫 층만 강하다. 해결책은 두 번째와 세 번째 층을 추가하는 방향이어야 한다.

## 2. 문제별 해결 아이디어

| 문제 | 해결 아이디어 | 기대 효과 | 주의점 |
|---|---|---|---|
| 세 원만 누르면 완료 | 핫스팟 확인 뒤 `주장을 가장 잘 뒷받침하는 단서`를 한 번 더 선택 | feedback을 읽고 근거를 구별해야 완료 | 매 단계 퀴즈처럼 만들지 않기 |
| 오입력이 상태에 남지 않음 | `firstAttempt`, `misconceptionFlags`, `hintLevel`을 세션 메모리에만 기록 | 오개념별 대조 피드백 제공 | 개인정보·장기 저장 금지 |
| 실패 비용이 없음 | 감점 대신 첫 판단을 잠시 고정한 뒤 추가 근거로 수정하게 함 | 실패가 학습 서사가 됨 | 수정 자체를 실패로 낙인찍지 않기 |
| 함정 단서 0개 | 역사적으로 그럴듯하지만 현재 주장에는 부족한 자료를 포함 | 무작위 클릭보다 자료 범위 판단 유도 | 억지 오답·사실 오류 금지 |
| 순서가 불필요한 자료에도 ordered 사용 | 실제 시간·절차·인과 순서일 때만 ordered 허용, 나머지는 분류·연결로 전환 | UI 순서를 역사적 순서로 오해하는 문제 방지 | 전수 변환 전 콘텐츠 검토 필요 |
| 좌표·모양 반복 | 카드·지도·축·저울 등 의미에 맞는 표현 사용, 좌표는 보조적으로 섞음 | 시각·운동 기억만으로 통과하기 어려움 | 무작위 위치 변경만으로 끝내지 않기 |
| interaction 이름과 실제 행동 불일치 | `resource-allocation`·`reflection`을 실제 동작으로 구현하거나 이름을 정직하게 변경 | 데이터 계약의 의미 회복 | 기존 데이터 일괄 동작 변경 금지 |
| 모든 단계 난이도 유사 | 한 MUD 안에서 관찰→정리→추론→논증으로 상승 | 짧은 활동 안에서도 숙련감 형성 | 시대순 전역 난이도와 혼동 금지 |

## 3. 우선 검토할 상호작용 메커닉

### A. 판단–공개–수정

1. 자료를 보기 전에 첫 판단을 고른다.
2. 단서 두세 개를 연다.
3. 판단을 유지하거나 수정한다.
4. 결과 화면에서 무엇 때문에 생각이 바뀌었는지 보여 준다.

게임성의 핵심은 감점이 아니라 **처음 선택에 대한 약속과 새 정보로 인한 긴장**이다. 정적 협동 MUD에서 이미 사용한 최초 판단→공유→재검토 구조를 개인형 MUD에 축소 적용할 수 있다.

### B. 주장–근거 배치(`card-placement` 후보)

- 상단에 주장 2개, 하단에 근거 카드 3~5개를 둔다.
- 카드를 주장 아래에 탭하여 배치한다.
- 정답 하나만 찾기보다 `직접 근거`, `간접 근거`, `관련 없음`을 구분한다.
- 캔버스 드래그 대신 선택→배치 버튼으로도 동일하게 동작한다.

하나의 범용 계약으로 분류, 인과 연결, 주장–근거 매칭을 표현할 수 있어 interaction 타입의 무분별한 증가를 막는다.

### C. 의미 있는 순서화

다음 조건 중 하나를 만족할 때만 사용한다.

- 제작 절차
- 사건의 시간 순서
- 원인→변화→결과
- 관찰→해석→판단

틀리면 처음부터 초기화하지 않고, 충돌한 두 카드만 표시하며 역사적 이유를 설명한다.

### D. 지도 근거 선택

기존 `hotspot-choice`를 재사용할 수 있다.

- 모든 지점을 누르는 대신 목적에 맞는 지점 하나 또는 경로를 선택한다.
- 선택 후 지형·교역·방어 같은 근거를 붙인다.
- 두 개 이상의 타당한 경로가 있다면 각각 다른 장단점을 보여 준다.

### E. 실제 자원 배분

현재 이름뿐인 `resource-allocation`을 실제 게임으로 만든다.

- 제한된 사람·시간·재료 토큰을 2~3개 선택지에 나눈다.
- 모든 목표를 동시에 최대화할 수 없게 한다.
- 결과는 성공/실패 대신 `빠르지만 불안정`, `느리지만 안전`, `교류에 유리`처럼 trade-off로 보여 준다.

역사적 사실을 바꾸는 샌드박스가 아니라, 당시 사람들이 마주한 제약을 이해하는 활동으로 한정한다.

### F. 반례 찾기

- 화면에 주장 하나와 자료 4개를 제시한다.
- 주장을 지지하는 자료가 아니라 **주장의 범위를 제한하는 자료**를 고른다.
- “한 사례를 전체 시대에 일반화할 수 없다”는 사료 비판 능력을 게임화한다.

## 4. 게임성을 강화하는 별도 아이디어

### 4-1. 근거 충분도 등급

속도 점수 대신 결과의 질을 세 단계로 보여 준다.

```text
관찰자: 관련 단서를 찾음
연결자: 단서 사이 관계를 설명함
역사가: 반례·한계까지 검토함
```

등급은 학생 서열이 아니라 같은 학생의 사고 깊이를 보여 주며 공개 순위표에는 사용하지 않는다.

### 4-2. 제한된 힌트와 추가 자료

- 기본 힌트 2개를 제공한다.
- 오개념을 선택하면 정답을 바로 밝히지 않고 대조 자료를 하나 연다.
- 힌트를 적게 쓴 경우 작은 배지를 줄 수 있지만, 힌트 사용으로 기본 보상을 잃지는 않는다.

이는 목숨·감점 없이도 선택의 무게를 만든다.

### 4-3. 여러 타당한 해결 경로

예를 들어 문화 발전을 설명할 때 기술, 교류, 국가 지원 중 어느 축을 먼저 고르더라도 충분한 근거를 붙이면 타당한 결론으로 인정한다. 결과 화면에서는 “정답” 대신 선택한 설명의 강점과 놓친 관점을 보여 준다.

### 4-4. 유물을 도구로 재사용

현재 유물은 주로 수집 보상이다. 해금한 유물을 다음 탐구의 능력으로 사용한다.

- 지도 유물: 지리 단서 하나 추가 공개
- 기록 유물: 문서 출처·작성 목적 확인
- 생활 유물: 일반인의 관점 카드 추가
- 과학 유물: 제작 원리 또는 측정 단서 확인

강력한 아이템이 정답을 대신하는 것이 아니라 **새로운 질문을 열어 주는 도구**가 된다.

### 4-5. 탐구 덱과 재플레이 변형

역사 사실은 고정하되 다음을 바꾼다.

- 이번 판에 제시되는 자료 조합
- 학생이 맡는 관점
- 마지막에 검토할 주장
- 사용할 수 있는 유물 도구

첫 플레이는 핵심 자료를 고정하고, 완료 뒤 `다른 관점으로 다시 보기` 모드만 변형한다.

### 4-6. 작은 보스 관문

각 MUD의 마지막 단계는 앞의 세 단계에서 모은 근거를 다시 사용한다.

- 박물관 전시 설명 완성
- 왕에게 올릴 정책 보고서 작성
- 사료의 신뢰도 판정
- 역사 주장에 반례 붙이기

새 문제를 푸는 것이 아니라 이전 행동이 마지막 판단의 자원이 되게 한다.

### 4-7. 개인형 비대칭 정보

재플레이 때 한 번에 모든 자료를 주지 않고 `기록`, `유물`, `지도`, `생활상` 관점 중 하나를 고르게 한다. 완료 후 다른 관점으로 다시 플레이하면 처음에 보지 못한 자료가 열린다.

### 4-8. 선택형 도전 모드

기본 학습 모드를 완료한 뒤에만 연다.

- 힌트 없이 해결
- 이전에 쓰지 않은 근거 사용
- 반례까지 포함
- 제한 시간은 학생이 직접 선택할 때만 사용

속도는 필수 성취 기준이나 공개 경쟁 점수로 사용하지 않는다.

## 5. `regular_goryeo_culture` 파일럿 예시

| 단계 | 역사적 사고 | 상호작용 아이디어 | 게임적 긴장 |
|---|---|---|---|
| 1 팔만대장경 | 자료 관찰 | 세 특징을 확인하고 핵심 목적을 뒷받침하는 특징 선택 | 첫 판단 후 실제 단서 공개 |
| 2 직지 | 절차·기술 변화 | 제작·인쇄·확산 카드를 의미 있는 순서로 배열 | 충돌한 두 단계만 대조 피드백 |
| 3 벽란도 | 공간·교류 | 교역 지점과 교류 근거를 선택 | 다른 경로의 장단점 비교 |
| 4 문화 종합 | 주장·근거·반례 | 앞서 모은 카드를 전시 설명에 배치 | 근거 충분도 3단계 결과 |

### 재플레이

- 첫 판: “고려 문화가 발전한 까닭”
- 두 번째 판: “고려 문화가 주변 지역과 연결된 방식”
- 세 번째 판: “한 자료만으로 고려 전체를 설명할 수 없는 이유”

같은 사실을 외우는 재시험이 아니라 질문 관점이 깊어지는 구조다.

## 6. 비용별 실행 후보

### 저비용 — 기존 계약 활용

- `ordered-hotspot`을 실제 순서가 있는 단계에만 남긴다.
- 기존 `hotspot-choice`를 Regular 한 단계에 시험한다.
- 핫스팟 완료 뒤 근거 선택 질문을 추가한다.
- 오입력·힌트 사용을 현재 세션에서만 기록한다.

### 중간 비용 — 범용 계약 1개

- `card-placement` 하나로 분류·순서·주장–근거 연결을 지원한다.
- DOM 우선 UI와 캔버스 보조 표현을 제공한다.
- 검증기에서 카드 ID, 허용 배치, 복수 정답, 피드백을 검사한다.

### 높은 비용 — 파일럿 성공 후

- 자료 조합·관점이 바뀌는 재플레이 덱
- 유물을 탐구 도구로 사용하는 시스템
- 개인·협동 MUD 사이의 근거 카드 연계
- 여러 MUD를 관통하는 역사 탐구자 숙련도

## 7. 권고 우선순위

| 순위 | 아이디어 | 이유 |
|---:|---|---|
| 1 | 판단–공개–수정 | 새 그래픽 없이도 선택의 무게와 학습 증거를 만든다. |
| 2 | 한 MUD 내부 난이도 곡선 | 현재의 네 단계 반복을 직접 해결한다. |
| 3 | 범용 `card-placement` | 적은 엔진 확장으로 여러 사고 행동을 표현한다. |
| 4 | 오개념 기반 대조 피드백 | 무의미한 함정·감점 없이 실패를 학습으로 바꾼다. |
| 5 | 다른 관점 재플레이 | 고정 좌표 암기 대신 새로운 근거 사용을 유도한다. |

## 8. 피해야 할 해결책

- 102개 핫스팟 좌표만 무작위화하기
- 역사적 의미가 없는 가짜 원 추가하기
- 첫 학습부터 타이머·콤보·목숨 적용하기
- interaction 타입을 시대마다 하나씩 새로 만들기
- 전체 Regular JSON을 한 번에 변환하기
- 공개 점수판이나 학생 간 속도 경쟁 도입하기

이 아이디어들은 증상을 가리거나 구현량만 늘릴 뿐, 역사적 근거를 사용하게 만드는 핵심 판정을 해결하지 못한다.
