# 선택 모둠 교사 마스터 1단계 진행 체크리스트

> 계획: [`implementation_plan_teacher_master_advance.md`](./implementation_plan_teacher_master_advance.md)
>
> 기준: 승인된 master 진행은 선택 모둠 1단계씩, 교사 확인·사유 기록, 개인 학습 완료 값 보존이다.

## 승인·기준선

- [x] 사용자 인터뷰로 범위를 승인받음: 선택 모둠을 한 번에 한 단계씩 진행.
- [x] 진행 사유 기록과 개인 미완료 상태 유지가 권장안에 포함됨.
- [x] 격리 작업공간·브랜치 생성: `.worktrees/codex-teacher-master-advance` / `feat/cooperative-teacher-master-advance`.
- [ ] 2명 이하 잔류 모둠의 최소 인원·공통 자료 정책에 대한 인터뷰 답변 반영.
- [ ] 기존 도움 요청의 대시보드 처리 방식은 별도 인터뷰로 결정하고 본 작업에서 변경하지 않음.

## P0 — master mutation·기록

- [ ] task claim과 승인 범위를 `BACKLOG.md`에 반영한다.
- [ ] 진행 사유 코드를 정하고 서버 입력 검증을 추가한다.
- [ ] 세션·모둠·현재 단계·다음 단계·사유·시각을 기록하는 세션 한정 감사 테이블을 추가한다.
- [ ] 종료 시 master 진행 기록도 함께 삭제한다.
- [ ] `teacherMasterAdvanceGroupStage`가 소유자·활성 세션·일시정지·모둠·단계·한 단계 전진을 서버에서 검증하게 한다.
- [ ] 개인 제출·공유·revision 확인 값을 절대로 완료 상태로 덮어쓰지 않는다.
- [ ] 일반 진행 mutation의 기존 검증 동작은 유지한다.

## P0 — 교사 대시보드

- [ ] 모둠 카드에 `마스터 다음 단계`를 일반 진행 버튼과 구분해 추가한다.
- [ ] 확인 UI에 모둠·현재/다음 단계·미완료 수·완료 처리되지 않는다는 안내를 표시한다.
- [ ] 교사가 모둠 학생 동의를 확인하고 진행 사유를 선택한 뒤 실행한다.
- [ ] 성공/실패 상태와 최근 master 진행 이력을 해당 모둠 카드에 표시한다.
- [ ] 키보드·터치 조작과 작은 화면 레이아웃을 점검한다.

## P0 — 회귀·검증

- [ ] 미완료 gate에서 master 1단계 이동 성공, 같은 입력으로 두 단계 건너뛰기 불가.
- [ ] `submittedAt`, `sharedAt`, `confirmedRevision`와 미완료 집계 보존.
- [ ] 이력에 모둠·단계·사유·시각만 저장하고 학생 식별·답 내용은 저장하지 않음.
- [ ] 다른 모둠의 플레이어·방·초안·확인 수가 그대로임.
- [ ] 일시정지·종료·타 모둠·역행·유효하지 않은 사유 요청 거부.
- [ ] 세션 종료 시 감사 이력 삭제.
- [ ] Convex 통합 테스트와 `npm run check`, production build 통과.
- [ ] Preview 대시보드 확인 뒤 교사 1명+학생 역할 4~8대 리허설 체크리스트에 포함.
- [ ] 구현 중 별도 발견은 BACKLOG로 분리하고, 결과와 검증을 `walkthrough.md`에 기록.
