# interrogate — 다중 모델 교차 검토

출처: cursor/plugins의 `pstack` 중 `/interrogate` 개념을 이 저장소에 맞게 새로 쓴 것이다(원문 복사 아님). 모델이 다르면 놓치는 곳도 다르다는 점으로 적대적 신호를 얻는다.

이 스킬은 **audit** 역할이다. 직접 고치지 않고 결과만 보고한다(AGENTS.md의 역할 구분).

## 절차

1. **대상 확정**: 검토할 범위를 한 줄로 정한다. `git status --short`로 미추적 파일까지 포함해 파일 목록을 만든다.
   - 기본 범위는 미커밋 변경이다. 이미 커밋된 변경이면 사용자가 지정한 `<base>..HEAD`를 쓴다. 이 저장소는 main에서 직접 작업하는 일이 많아 `main...HEAD`는 대개 비어 있다.
   - 미추적 새 파일은 `git diff`에 나오지 않으므로 파일 전체를 읽게 한다.
   - 콘텐츠·활동이면 해당 경로를 넘긴다: `data/mud/*.json`, `cooperative-mud/<편>/scenario.js`, 공용 `cooperative-mud/episode.js`·`cooperative.css`.
   - 완료 기준: 파일 목록과 변경 의도(관련 D-번호·BACKLOG 항목, 없으면 "없음")를 말할 수 있다.
2. **검토자 구성**: Agent 도구로 서로 다른 모델의 서브에이전트를 병렬로 띄운다. `subagent_type`은 반드시 `Explore`, `model`은 `opus`·`sonnet`(필요하면 `haiku`).
   - Codex 검토가 이미 지정돼 있으면 그 결과를 검토자 하나로 포함한다.
   - 완료 기준: 검토자별 `model`을 확인했다.
3. **공통 프롬프트**: 모든 검토자에게 같은 문장을 준다. 대상, 의도, "이 변경을 깨뜨릴 방법을 찾아라, 칭찬하지 마라, 근거 `파일:줄`을 대라"를 넣고, 아래 제한을 **그대로** 적는다.
   - 파일 생성·수정·리다이렉트 금지, `scripts/` 실행 금지, `git checkout`·`switch`·`stash`·`reset` 금지. 읽기와 grep만 허용한다.
   - 이유: `scripts/`의 일부(02, 07, 10, 11, 13, 14, 17, 18)는 실행하면 데이터나 보고서 파일을 다시 쓴다. 검토자 여럿이 동시에 돌리면 서로 덮어쓴다.
   - 검토 렌즈는 아래 셋을 모두 열어 둔다.
     - **정확성**: 깨진 참조·`next` 누락, 상태 전이, 모바일 터치, 검증 스크립트 회귀.
     - **교육 내용**: 역사 서술 오류, 근거 없는 설명, 5학년 수준에 맞지 않는 어휘, 선택지 편향(`scripts/12`·`17`이 일부 잡는다).
     - **코드 품질**: 불필요한 추가, 기존 구조·스타일과 어긋남, 요청 밖 재작성.
   - 완료 기준: 검토자 전원에게 같은 프롬프트와 같은 제한을 보냈다.
4. **실행 후 확인**: 검토자가 모두 끝나면 `git status --short`와 `git rev-parse --abbrev-ref HEAD`로 검토 전과 같은지 확인한다. 달라졌으면 보고하고 멈춘다.
   - 완료 기준: 변경 없음을 확인했다.
5. **합치기**: 같은 문제를 독립적으로 둘 이상이 지적하면 가장 강한 신호로 본다. 지적마다 누가 말했는지 적는다.
   - **Act on**: 근거가 확인되고 영향이 큰 것. 직접 `파일:줄`을 열거나 명령으로 확인한 뒤에만 넣는다.
   - **Consider**: 타당하지만 취향·범위 판단이 필요한 것. 역사 사실 판정은 근거 자료(`primary_data`)를 검토자가 볼 수 없으므로 여기에 두고 content 역할(사용자) 확인을 요청한다.
   - **Noted**: 맞지만 지금 작업 밖인 것 → BACKLOG 후보.
   - **Dismissed**: 틀렸거나 이미 확정된 결정(D-번호)과 충돌하는 것. 이유를 한 줄로 적는다.
   - 완료 기준: 모든 지적이 네 묶음 중 하나에 들어갔다.
6. **보고**: 종합 판정(진행 가능 / 수정 후 진행 / 중단)과 네 묶음을 낸다. 변경을 자동 적용하지 않는다.
   - Noted 항목은 현재 작업에 섞지 않고 BACKLOG 등록을 제안한다.

## 주의

- 서브에이전트 결과는 근거가 아니라 단서다. Act on에 올리기 전에 직접 확인한다.
- 검증은 메인 에이전트가 `project_context.md`의 검증 절과 `.github/workflows/quality-gate.yml`을 따라 돌린다. 02는 실행하지 않는다. 보고서를 다시 쓰는 스크립트를 돌렸다면 `git status`로 생긴 diff를 확인하고 되돌린다.
