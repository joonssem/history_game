# Claude 후속 전달 — 역사 여정·유물 증거·협동 해석 연결

> 작성: 2026-09-18, Codex 기획·점검 세션  
> 성격: 사용자 대화 기록 및 후속 검토 메모. 구현 승인서가 아니다.  
> 선행 작업: [`claude_four_track_round8_instruction.md`](./claude_four_track_round8_instruction.md)

## 1. 배경

사용자와 함께 외부 참고 사례 [史뿐史뿐 — 시간이 쌓이는 지도](https://so0yeon.github.io/sbbsbb/)를 검토했다. 첫 화면, 개인정보 안내, 이름 생략, 역사 가방 온보딩, 구석기 탐험 도입·임무 목록, 시대·세기별 지도 전환을 직접 확인했다.

검토 결과, 현재 프로젝트의 다음 문제는 콘텐츠 부족보다 이미 있는 48차시·32개 MUD·유물 도감·시뮬레이터·협동 활동이 학생에게 하나의 연속된 역사 경험으로 느껴지지 않을 수 있다는 점으로 정리됐다. 다만 이는 제품 설계 가설이며, 외부 사례의 학습 효과를 실제 수업에서 검증한 결과는 아니다.

## 2. 현재 작업과 연결할 세 관점

### 관점 A — 제품 연결: 개별 활동을 하나의 역사 여정으로

- 현재의 차시 선택 → MUD → 유물 획득 → 포털 복귀 흐름 위에 현재 시대, 이번 탐구 질문, 획득 유물, 앞뒤 변화를 보여 주는 연결층을 검토한다.
- 새 공간 탐험 게임이나 전국 시대 지도를 먼저 만들지 않는다.
- 가장 작은 후보는 MUD 시작·완료 화면에 `이번에 밝힐 질문`, `획득 유물이 보여 주는 증거`, `다음 시대에 달라지는 점`을 연결하는 것이다.

### 관점 B — 학습 연결: 유물을 수집 보상에서 증거 자원으로

- 유물을 `발견 → 관찰 → 비교 → 해석`에 다시 쓰는 자료로 본다.
- 기존 inquiry task와 유물 2개 비교·주장–근거 실험을 연결한다.
- 학생이 유물 이름을 기억하는 것보다, 관찰 가능한 특징을 근거로 역사적 주장을 설명하는지를 본다.

### 관점 C — 교실 연결: 개인 증거를 공동 해석으로

- 개인이 발견한 서로 다른 자료·유물을 협동 MUD의 비대칭 정보로 연결한다.
- 목표 흐름은 `개인 최초 판단 → 말로 증거 공유 → 공동 주장 → 다른 질문·반론 → 수정된 해석`이다.
- 개인 도감과 실시간 앱을 당장 기술적으로 연동할 필요는 없다. 역할별 증거 카드와 교사 운영으로 먼저 검증할 수 있다.

## 3. 현재 로드맵에 놓는 방법

### NOW — 현재 승인된 작업을 그대로 우선

- 라운드 8의 조선 후기 콘텐츠 앱 계약 이관을 완료한다.
- 고려 초기 실시간 협동 MUD의 실제 기기 리허설을 준비한다.
- 조선 후기 공개수업 수직 슬라이스의 역할별 근거, 공동 주장, 한계, 질문·수정 흐름을 검증한다.
- 기존 MUD·시뮬레이터·유물의 안정성과 역사 정확성을 유지한다.

### NEXT 후보 — 대표 활동 한두 편의 작은 수직 슬라이스

```text
탐구 질문 한 문장
→ 핵심 증거 2~3개 확인
→ 기존 선택·시뮬레이터
→ 유물 획득
→ 그 유물이 질문에 제공한 근거 확인
→ 앞뒤 시대 또는 협동 활동으로 연결
```

다음 행동을 관찰한다.

- 학생이 탐구 질문을 기억하는가?
- 유물의 특징을 근거로 말하는가?
- 정답 문구가 아니라 자료를 보고 판단하는가?
- 친구에게 자신의 근거를 설명하고 다른 근거를 받아 해석을 수정하는가?

### LATER 후보 — 역사 여정 화면

작은 실험의 수업 근거가 확보된 뒤 현재 시대·완료한 탐구·획득 유물·남은 질문·앞뒤 변화를 묶는 `나의 역사 여정` 화면을 검토한다. 대규모 자유 이동형 공간은 이 단계에서도 필수가 아니다.

## 4. 조선 후기·고려 초기 작업과의 구체적 접점

- 조선 후기 역할별 `evidence`는 단순 제출용 항목이 아니라 각 역할이 공동 해석에 가져오는 서로 다른 역사 증거의 최소 단위로 본다.
- `limitations`는 답을 방해하는 요소가 아니라 “이 증거만으로 어디까지 말할 수 있는가”를 학습시키는 장치다.
- `connections`는 변화의 목록이 아니라 “누구에게 어떤 영향이 있었는가”를 여러 증거로 연결하는 공동 해석이어야 한다.
- 고려 초기 리허설에서는 기능 정상 작동뿐 아니라 각 학생이 자신의 근거를 한 번 이상 설명했는지, 다른 역할의 근거 때문에 최초 판단을 바꿨는지를 관찰 후보로 둔다.
- 현재 앱 계약과 라운드 8 산출물에는 이 메모를 이유로 새 필드를 추가하지 않는다. 필요한 데이터 구조 변경은 수업 관찰과 별도 구현 계획 승인 뒤 결정한다.

## 5. 통합 제품 문장 초안

> 학생은 시대별 MUD에서 역사적 질문을 만나고, 자료와 유물을 증거로 모아 자신의 해석을 만든다. 개인이 발견한 서로 다른 증거는 교실 협동 활동에서 공유되며, 질문과 반론을 거쳐 더 나은 공동 해석으로 수정된다. 각각의 활동 결과는 하나의 연속된 역사 여정으로 남는다.

## 6. Claude에게 요청하는 현재 범위

1. 라운드 8의 기존 범위와 파일 소유권을 그대로 지킨다.
2. 현재 만들고 있는 역할별 `evidence`, `limitations`, `connections`가 위 세 관점과 충돌하는지만 점검한다.
3. 충돌이나 자연스러운 연결점이 있으면 구현에 섞지 말고 완료 보고에 `후속 제품 연결 메모`로 남긴다.
4. 새 역사 여정 화면, 도감 연동, 신규 필드, 새 게임 시스템은 구현하지 않는다.
5. 라운드 8 완료 뒤 가장 작은 검증 후보 1개를 제안한다. 기존 활동 하나를 재사용하며 학생 행동으로 성공 여부를 관찰할 수 있어야 한다.

## 7. 주의할 위험

- 긴 도입 문장과 손글씨 본문으로 태블릿 가독성을 낮추지 않는다.
- WASD 중심 탐험을 현재 터치 완료 기준에 그대로 가져오지 않는다.
- 많은 수집 항목을 전부 필수화해 증거 읽기를 클릭 노동으로 만들지 않는다.
- 지도·시대·세기·필터를 한 화면에 한꺼번에 노출하기보다 관찰 질문 하나를 먼저 제시한다.
- 외부 사례의 구조를 학습 효과가 입증된 방식처럼 단정하지 않는다.
