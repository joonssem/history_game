# 사용자 흐름 및 플로우차트

## 학생 전체 흐름

```mermaid
flowchart TD
    A[포털 진입] --> B[단원 선택]
    B --> C[차시 선택]
    C --> D{활동 선택}
    D -->|Regular MUD| E[MUD 시작]
    D -->|Deep-dive| F[확장 탐구 시작]
    D -->|골든벨| G[퀴즈 시작]
    E --> H[자료 읽기·시뮬레이터 상호작용]
    F --> H
    H --> I[선택지 선택]
    I --> J{진행 결과}
    J -->|정상 진행| H
    J -->|IF 재시도| K[역사적으로 어긋난 결과 확인]
    K --> H
    J -->|엔딩| L[성찰 기록]
    L --> M[유물 해금·진행 저장]
    H -.-> O[선택 탐험: 주변 조사·추가 단서 발견]
    O -.-> H
    G --> N[문항 풀이·점수 확인]
```

## Regular MUD 흐름

```mermaid
flowchart LR
    A[차시 카드] --> B[MUD JSON 로드]
    B --> C[필수 단서·시뮬레이터]
    C --> D{완료 조건 충족?}
    D -->|아니오| C
    D -->|예| E[선택지 활성화]
    E --> F{선택 결과}
    F -->|정답| G[다음 단계]
    F -->|오답| H[IF 스테이지]
    H --> I[자료·결과 확인]
    I --> G
    G --> J[엔딩·성찰·유물 해금]
```

## 시스템 흐름 원칙

- 포털은 `_index.json`을 우선 사용한다.
- MUD 본문과 시뮬레이터 계약은 JSON에 선언한다.
- 필수 상호작용을 완료하기 전에는 다음 선택지를 진행시키지 않는다.
- 클리어 보상과 즉시 진행 상태는 localStorage에 저장한다.
- 선택 탐험은 필수 경로를 막지 않는 선택적 자료 발견으로 설계한다. 현재 구현 대상이 아니라 최소 실험 후보이다.
- 현재는 서버 계정이나 교사 대시보드로 데이터를 전송하지 않는다. 향후 Supabase를 도입하더라도 첫 단계는 익명 플레이 이벤트로 제한하며, 핵심 흐름은 네트워크 장애 시 유지한다.
