## 목적·순서

1. 기존 고려 문화·생활 구현을 보존하고 `387dabe`의 입장 멱등 처리를 통합한다.
2. 교사는 선택 모둠만 한 단계씩 진행하며, 현재 단계 확인·사유·학생 동의 확인을 서버에서도 요구한다. 중복 요청은 기대 단계 비교로 거부한다.
3. 대시보드에서 모둠 단계·개인 판단·공유·초안 확인의 완료 수와 막힌 이유를 보여 준다. 도움 요청 때 힌트·교사 진행·해결 완료 처리를 제공한다.
4. 부족 인원은 교사의 명시적인 복구 모드로 해결한다. 시작 편성은 기존 3~5인 그대로 유지한다. 활동 도중 1~2명만 남으면 기존 역할을 유지하고, 빠진 원래 역할의 근거 요약을 공동 초안 자료로 제공한다. 비공개 본문은 제공하지 않는다. 0명 모둠 진행은 차단한다.

## 자료·진행 계약

- 복구 모드는 교사가 실제 잔류 학생을 확인한 뒤 선택 모둠에서 켠다. 참가자 제외는 자동 heartbeat 삭제가 아니라 기존 교사 확인 동작을 유지한다.
- 마스터 진행은 `submittedAt`, `sharedAt`, `confirmedRevision`를 만들어 주지 않는다. 개인 학습 완료와 교사에 의한 단계 이동을 분리한다.
- 공유 단계를 교사가 넘긴 경우 해당 모둠에만 근거 요약을 열어 공동 초안 작성을 가능하게 한다. 원래 개인 공유 값은 보존한다.
- 공동 초안의 두 주제·서로 다른 두 역할 근거·자료 한계·연결 설명 검증을 유지한다. 부족 인원 복구에서는 빠진 원래 역할의 요약도 근거로 선택할 수 있다.
- 초안 없이 확인·종료 단계로 넘어갈 수 없다. 초안을 교사가 대신 만들거나 학생 동의를 자동 기록하지 않는다.
- 교사 진행 이력은 세션·모둠·종류·이전/다음 단계·사유 코드·시각만 저장하고 세션 종료 시 삭제한다.
- 멈춤·다른 교사·종료·잘못된 단계 요청은 거부한다. 다른 모둠의 역할·진도·초안·확인은 바꾸지 않는다.

## 검증·경계

- 입장 QR/코드 중복, 고려 문화 3/4/5인, 기존 21명 복구·고조선·조선 후기 회귀.
- 2명·1명 복구, 0명 제외 거부, 빠진 역할 요약의 비공개 본문 경계와 공동 초안 근거 검증.
- 교사 1단계 CAS·일시정지·소유권·사유·동의·개인 완료값 보존·다른 모둠 격리·종료 이력 삭제.
- `npm run check`, `git diff --check` 및 가능한 로컬 화면 확인.
- 이번 승인 범위는 구현·검증이다. 기존 merge·배포·실제 학생 현장 관문을 유지한다.
