- 대상: `apps/cooperative-live`
- 목적: QR 링크의 추측 가능성과 6자리 수업 코드 반복 시도를 막되 학생 계정·이름·기기 고유 ID를 새로 만들지 않는다.

## 1. 위협과 설계 원칙

현재 QR은 수동 입력과 같은 6자리 `code`를 URL에 담는다. 코드는 교실에서 읽기 쉬운 대신 추측 가능하고, URL은 브라우저 기록·서버 요청 경로·공급자 로그에 남을 수 있다.

- 6자리 코드는 수동 입력용 식별자로만 사용하고 인증 비밀로 취급하지 않는다.
- QR에는 최소 128비트의 별도 난수 입장키를 사용한다.
- QR 난수는 URL query/path가 아니라 fragment(`/join#entry=...`)에 넣어 Vercel 요청 경로와 Referer로 전송되지 않게 한다.
- 서버에는 QR 난수와 복구 토큰의 SHA-256 해시만 저장한다.
- 학생 이름·학번·이메일·장기 계정·기기 고유 ID·원시 IP를 앱 DB에 저장하지 않는다.
- 요청 본문, QR 난수, 수동 코드, 호, 역할, 개인 선택을 `console`이나 감사 로그에 출력하지 않는다.

## 2. 입장 자격과 수명주기

| 자격 | 전달·저장 | 만료 |
|---|---|---|
| QR 입장키 | 128비트 이상 난수, URL fragment로 전달, Convex에는 SHA-256 해시만 저장 | 입장 잠금, 활동 시작, 교사 종료, 생성 후 15분 중 가장 빠른 시점 |
| 6자리 수업 코드 | 학생이 직접 입력하고 POST/Convex 함수 인자로만 전송. URL에 넣지 않음 | 입장 잠금·활동 시작·종료 또는 생성 후 15분 |
| 학생 복구 토큰 | 서버 발급 난수, 기기 `sessionStorage`, 서버에는 SHA-256 해시 | 활동 종료·2시간 TTL·교사 강제삭제 |
| 교사 세션 | Auth0 Google 로그인과 서버 `sub` 허용목록 | Auth0 세션 만료·로그아웃·허용목록 제거 |

QR 입장키는 화면에 QR을 다시 만들 때 회전할 수 있어야 한다. 회전 즉시 이전 해시는 무효화한다.

## 3. 수동 코드 시도 제한

수동 코드 입장은 정상 학급 24명의 동시 입장을 막지 않으면서 자동 대입을 제한한다.

1. 브라우저별 임시 `attemptId`를 발급하고 `sessionStorage`에 저장한다. 원문 대신 서버 비밀키로 HMAC한 버킷만 짧게 보관한다.
2. 동일 버킷은 5분 동안 실패 5회까지 허용하고 이후 10분 차단한다.
3. 동일 수업 코드는 전체 실패 30회/5분을 넘으면 5분 동안 수동 입장만 잠근다. QR 입장은 유지해 공격자가 수업 전체를 막지 못하게 한다.
4. 성공 여부와 관계없이 응답 문구와 지연을 최대한 같게 해 존재하는 코드 탐색을 어렵게 한다.
5. 시도 버킷에는 코드 원문·IP·User-Agent를 저장하지 않고 `deleteAfter`를 두어 15분 안에 삭제한다.

`attemptId`만으로는 저장소를 지우는 공격자를 완전히 막지 못하므로, Preview 검증에서 우회가 확인되면 Vercel POST Route에서 원시 IP를 저장하지 않는 일일 회전 HMAC 버킷을 추가한다. 이 경우 IP 처리 범위가 넓어지므로 개인정보 처리표와 권한 시험을 먼저 갱신한다.

## 4. 예상 변경 범위

- `convex/schema.ts`: QR 해시·만료, 코드 만료, 시도 제한 버킷/정리 인덱스
- `convex/sessions.ts`: 세션 생성 시 QR 난수 발급·해시 저장, 회전, 입장 잠금 시 폐기
- `convex/students.ts`: QR 입장과 수동 코드 입장 분리, 만료·레이트리밋·정원 검증
- `convex/cleanup.ts`: 입장키·시도 버킷 자동 정리
- `lib/convex-api.ts`, `components/LiveJoinForm.tsx`, `components/LiveTeacherConsole.tsx`: fragment 파싱, QR/수동 입장 분리, 안전한 오류 표시
- `shared/scenario.test.ts` 또는 별도 보안 테스트: 난수·해시·만료·시도 제한·회전·로그 금지 계약
- `README.md`, 개인정보 감사서, `walkthrough.md`: 환경·운영·검증 결과

새 외부 패키지는 추가하지 않는다. Web Crypto/Node `crypto`와 현재 Convex 함수·스케줄러만 사용한다.

## 5. 수용 기준

- QR 소스·브라우저 주소창·Vercel 요청 경로에 6자리 코드와 QR 원문이 나타나지 않는다.
- QR 난수는 128비트 이상이고 원문이 Convex 테이블에 저장되지 않는다.
- 만료·잠금·종료·회전된 QR로 입장할 수 없다.
- 수동 코드 실패 제한이 브라우저 버킷과 코드 전체 버킷에서 각각 작동한다.
- 제한 상태에서도 기존 정상 참여자의 복구 토큰은 영향을 받지 않는다.
- 학생 24명이 정상적으로 입장할 수 있고 25번째 입장은 거부된다.
- 교사 외 사용자가 QR 회전·입장 잠금·세션 조회를 호출할 수 없다.
- 로그 정적 검색과 Preview 로그 확인에서 토큰·코드·호·역할·답변이 발견되지 않는다.
- 종료 후 세션 하위 데이터, 입장 해시, 시도 버킷, 기기 `cooperative-live:` 키가 제거된다.

## 6. 구현·배포 순서

1. 가상 데이터 테스트로 토큰 생성·만료·시도 제한 계약 구현
2. Convex 개발 배포 연결 후 권한·동시성·삭제 통합 시험
3. Vercel Preview 연결 후 URL·Runtime Logs·Build Logs에 비밀값이 남지 않는지 확인
4. 실제 학생 데이터 없이 교사 기기와 테스트 기기로 QR·WebSocket·탭 복구 시험
5. 개인정보·국외 처리 게이트를 통과한 뒤에만 Production과 실제 학생 리허설 진행

## 7. 이번 계획에서 하지 않는 것

- 학생 로그인·명단 업로드·장기 식별자
- IP·기기 지문 기반 장기 차단
- CAPTCHA 또는 외부 봇 방어 서비스
- 기존 정적 `cooperative-mud/` 입장 흐름 변경
- 개인정보 게이트 해제 전 Production 배포와 실제 학생 접속
