- 범위: `apps/cooperative-live/**`와 관련 계획·운영 문서

- 상태: 주요 지적과 최종 비차단 지적 수정, 자동 회귀 통과. 기술 Preview·성인 리허설용 main 병합 Go

## 발견 및 조치

### A-01 — 확인 화면에 공동 초안 내용이 보이지 않음

- 심각도: 높음
- 문제: revision 번호와 확인 버튼만 보여 학생이 정책·근거·한계·연결 설명을 실제로 검토하지 않고 확인할 수 있었다.
- 조치: 확인 화면에 정책 2개, 서로 다른 역할 근거 2개, 함께 필요한 까닭, 자료의 한계를 모두 표시했다. 완료 발표 문장에도 선택한 역할 근거를 포함했다.

### A-02 — 동시 편집 시 오래된 입력이 최신 초안을 덮어쓸 수 있음

- 심각도: 높음
- 문제: 저장 시점의 실시간 구독 revision을 `expectedRevision`으로 사용해, 편집을 시작한 뒤 다른 기기가 초안을 바꿔도 오래된 로컬 입력이 최신 revision 위에 저장될 수 있었다.
- 조치: 편집 시작 revision을 별도 상태로 고정하고 서버 인자를 필수값으로 바꿨다. 첫 초안은 `0`, 기존 초안은 편집 시작 revision과 서버 최신 revision이 정확히 같을 때만 저장한다. 충돌 시 편집 화면을 닫고 최신 초안을 다시 검토하게 한다.
- 회귀: revision 1 확인 뒤 revision 2로 수정하면 확인 수가 0/N으로 돌아가고 revision 1 확인이 거부되는 통합 테스트를 추가했다.

### A-03 — 최초 판단·말하기 단계에서 자기 역할 자료가 사라짐

- 심각도: 중간
- 문제: 역할 확인 단계를 넘으면 자기 비공개 본문과 근거를 다시 읽을 수 없어, 최초 판단과 실제 말하기가 기억에 의존했다.
- 조치: 자기 역할 카드만 `역할 확인`, `개인 최초 판단`, `말로 공유` 세 단계에서 계속 보이게 했다. 다른 역할 비공개 본문은 반환하지 않는다. 말하기 화면에는 모둠 완료 n/N도 표시한다.

### A-04 — 서버의 “2개” 검증이 추가 항목을 허용할 수 있음

- 심각도: 중간
- 문제: 정책은 고유값 수만, 역할 근거는 최소 고유값 수만 확인해 조작된 클라이언트가 중복이나 세 개 이상의 항목을 보낼 여지가 있었다.
- 조치: 배열 길이와 고유값 수가 모두 정확히 2인지 서버에서 확인한다. 정책 3개와 역할 근거 3개를 각각 거부하는 통합 회귀를 추가했다.

### A-05 — 21명 회귀가 기본 시나리오 변경을 따라 고려로 바뀜

- 심각도: 중간, 비차단
- 문제: 첫 통합 테스트가 세션 생성 인자를 비워 두어 기본 시나리오가 고려 초기로 바뀐 뒤에도 문서에서는 “기존 고조선 21명 회귀”라고 설명했다.
- 조치: 21명 테스트에서 `gojoseon-eight-laws`와 version 1을 명시하고 대시보드의 시나리오 ID도 확인한다. 4명 고려 전체 흐름 테스트와 분리해 두 시나리오를 실제로 각각 관통한다.

### A-06 — QR을 “일회 입장키”로 설명함

- 심각도: 낮음, 문서
- 문제: 교실 QR은 한 학생만 쓰는 일회 키가 아니라 대기실에서 여러 학생이 제한 시간 동안 공유하는 키다.
- 조치: README를 “256비트 대기실 입장키”로 고치고 15분, 미리보기 전환·만료 시 무효화, 서버 해시 저장을 명시했다.
