# 구현 계획 — 선사 시대 협동 MUD 파일럿

상태: `deferred` / 고조선 8조법 아이패드 협동 MUD의 핵심 메커니즘 검증으로 막 1 종이 리허설 보류

## 1. 목적

구석기·신석기·청동기·고조선 자료를 역할별로 나누고, 학생 4명이 정보를 말로 모아 근거 있는 공동 설명을 만드는지 검증한다.

```text
중심 역사 상황 → 역할별 한정 정보 → 모둠 정보 공유 → 공동 판단 → 자료 해석 성찰
```

목표는 빠른 정답 선택이나 시대의 단순한 발전 서사가 아니다. 유물·기록이 알려 주는 범위 안에서 당시 생활을 설명하고, 단정할 수 없는 부분도 구분하는 역사적 사고를 확인한다.

## 2. 첫 파일럿 시나리오

가제: **《강가에 남은 세 시대의 흔적》**

| 막 | 공통 상황 | 공동 질문 | 자료 해석 원칙 |
|---|---|---|---|
| 구석기 | 해 지는 강가에서 먹을거리·바위 그늘·이동 흔적을 살핀다 | 오늘 밤 어떤 정보를 더 살펴야 할까? | 도구 하나로 생활 전체를 단정하지 않는다 |
| 신석기 | 움집 자리·빗살무늬토기·간석기·강가 흔적을 본다 | 이 자료는 생활 모습의 변화를 어떻게 보여 줄까? | 지역·시기별 생활을 하나로 일반화하지 않는다 |
| 청동기·고조선 | 민무늬토기·고인돌·비파형 동검·남은 법 조항을 비교한다 | 전시 문장으로 사회 모습을 어디까지 설명할 수 있을까? | 기록에 없는 내용을 사실처럼 덧붙이지 않는다 |

## 3. 역할 구조

기준 모둠은 4명이지만, 실제 21명 학급 운영에서는 3인 또는 5인 모둠도 가능해야 한다. 역할은 직업놀이가 아니라 서로 다른 자료를 책임지는 관찰 창구다.

| 역할 | 주로 보는 자료 | 모둠에 제공할 말 |
|---|---|---|
| 먹거리 조사관 | 강가 자원·식물·조개·농경 흔적 | 먹을거리와 환경 조건 |
| 도구 관찰관 | 뗀석기·간석기·토기·청동기 | 유물의 쓰임과 한계 |
| 터전 기록관 | 동굴·바위 그늘·움집·무덤 | 머무름·공동 작업·환경 조건 |
| 증거 점검관 | 자료의 출처·남은 기록·해석의 한계 | 단정할 수 있는 것과 없는 것 |

| 모둠 인원 | 운영 방식 |
|---|---|
| 3인 | 먹거리 조사관과 터전 기록관을 한 학생이 겸임한다. 겸임자는 두 카드의 단서를 각각 설명해야 한다. |
| 4인 | 기준 역할 네 개를 한 명씩 맡는다. |
| 5인 | 다섯째 학생은 공통 상황을 다시 읽고, 역할별 근거가 두 가지 이상 언급됐는지 확인하는 `모둠 진행·근거 기록관`을 맡는다. 정답 판정권이나 단독 선택권은 주지 않는다. |

공통 화면은 역사 상황과 선택지만 보여 준다. 각 역할의 핵심 단서는 종이 역할 카드 또는 역할별 화면 순서로 물리적으로 분리한다. 한 학생이 모든 카드를 읽는 방식은 협동 실험으로 인정하지 않는다.

## 4. 첫 운영 형태 — 서버 없는 1기기 실험

- 3~5인 익명 모둠당 태블릿 1대와 역할 카드(기준 4장, 5인일 때 근거 기록 카드 추가)
- 한 막의 흐름: 공통 상황 읽기 → 각자 카드 읽기 → 역할별 설명 → 모둠 선택 → 결과·자료 해석 확인
- 앱은 공동 세계를 동기화하지 않는다. 교사가 역할 발언과 근거 설명을 관찰하고, 모둠은 한 기기로 결과를 확인한다.
- 모둠은 다른 모둠과 독립적으로 진행하고, 마지막에만 전시 문장 또는 근거를 학급과 비교한다.

향후 다중 기기 Room에서도 실제 대화가 핵심이므로, Room 배정과 역할 공개를 분리한다.

```text
교실 공통 상황 안내 → QR 입장 → 교사 배정 → Room 자리 이동·착석 → 교사 탐사 시작 → 역할별 단서 공개·토의 → 교실 전체 정리
```

- `교사 배정`: 그 시점의 입장 인원을 3~5인 Room으로 나누고, 학생 화면에는 익명 모둠명·색/상징·이동할 자리만 표시한다.
- `Room 자리 이동·착석`: 학생은 iPad에 크게 표시된 Room 번호와 색/상징을 보고 배정된 실제 자리로 모인다. 역할별 비밀 정보와 선택지는 이 단계에서 열지 않는다.
- `교사 탐사 시작`: 모든 모둠이 모인 뒤 역할별 정보·공유판·공동 선택을 동시에 연다.

자리 고정 상태에서 채팅·퀵챗·정해진 선택지로만 정보를 교환하는 화면 기반 Room은 별도 후속 후보로 둔다. 실제 모둠 대화를 검증하는 이 파일럿에는 포함하지 않는다.

## 5. 장기 기술 경계

기존 GitHub Pages 앱·`js/mudEngine.js`·도감 저장값·기존 MUD JSON은 첫 파일럿에서 수정하지 않는다.

| 단계 | 배포·상태 | 진입 조건 |
|---|---|---|
| 0. 종이 리허설 | 역할 카드와 교사 진행 | 역할별 설명과 근거 토의가 실제 발생하는지 확인 |
| 1. 독립 정적 파일럿 | 같은 저장소의 향후 `cooperative-pilot/` 폴더, 별도 Vercel 프로젝트 후보 | 종이 리허설 통과 및 별도 구현 승인 |
| 2. 다중 기기 Room | 별도 Supabase 프로젝트 후보, 익명 임시 Room만 사용 | 1기기 방식이 학습 효과는 있으나 화면 동기화가 꼭 필요하다는 관찰 |
| 3. 장기 연동 | 기존 앱·도감과의 선택적 연결 | 반복 수업 효과와 개인정보·운영 기준을 별도 승인 |

Vercel은 파일럿 화면을 독립 배포하는 용도이며 기존 GitHub Pages를 대체하지 않는다. Supabase 도입 시에도 이름·학번·자유 대화·기기 식별자를 저장하지 않으며, Room 접근 제어와 만료·삭제 규칙을 먼저 설계한다.

## 6. 성공 관찰 기준

- 각 역할이 자신의 단서를 한 번 이상 설명한다.
- 특정 학생이 네 역할의 정보를 독점하지 않는다.
- 모둠이 선택 전에 두 가지 이상 자료를 언급한다.
- 학생이 “알 수 없다” 또는 “자료만으로 단정하기 어렵다”를 실패가 아닌 자료 해석으로 사용한다.
- 교사가 20분 안팎의 활동을 운영할 수 있다.

## 7. 이번 단계의 제외 범위

- 코드·새 웹 폴더·Vercel/Supabase 프로젝트 생성 또는 배포
- 다중 기기 접속, 실시간 채팅, 계정, 영구 데이터베이스
- 자유 입력 답안 저장, 점수·순위·경쟁 요소
- 기존 MUD의 완료 흐름이나 유물 도감에 자동 연결

## 8. 2026-09-04 진행 결정

사용자가 선사시대 협동 MUD 파일럿 진행을 승인했으나, 이후 고조선 8조법 아이패드 협동 MUD를 실제 수업에 적용해 핵심 협동 메커니즘을 먼저 검증했다. 이에 따라 준비 부담과 중복 검증을 줄이기 위해 **막 1 ‘강가의 흔적: 구석기’ 종이 리허설은 보류**한다. 막 2·3 카드 초안과 막 1 자료는 삭제하지 않고 보존하며, 선사시대 콘텐츠 자체를 다시 검토할 필요가 생길 때 재개 여부를 결정한다.

- 실행 방식: 종이 역할 카드 + 공동 기록지 + 교사 진행, 앱·서버·DB 미사용
- 모둠: 기준 4인, 3인·5인 변형은 기존 역할 운영표를 따름
- 목표 시간: 교사 안내를 포함해 약 20분
- 실행표: [`cooperative_prehistory_paper_rehearsal_execution.md`](../handoff/cooperative_prehistory_paper_rehearsal_execution.md)
- 카드 원문: [`cooperative_prehistory_content_draft.md`](./cooperative_prehistory_content_draft.md) §9~§12

종이 리허설에서 역할별 설명·근거 연결·불확실성 표현이 실제로 발생하는지 확인한 뒤에만 막 2·3 운영 또는 독립 정적 파일럿 구현을 결정한다. 기존 GitHub Pages 앱과 MUD JSON은 이 단계에서 수정하지 않는다.
