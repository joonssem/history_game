# 고려 초기 실시간 협동 활동 운영 체크리스트

대상은 1단원 13차시 “새 고려의 첫 회의”다. 첫 실행은 학생 수업이 아니라 교사 1명과 성인·교사 역할 참가자 4~8명의 기기 리허설로 한다.

## 시작 전

- [ ] 사용할 Vercel·Convex·Auth0 환경이 개인정보 운영 문서에 확인한 환경과 같은가?
- [ ] 실제 학생 이름·학번·계정·자유 대화 원문을 입력받지 않는가?
- [ ] 교사 화면, 학생 기기 4대 이상, 학교 Wi-Fi 또는 실제 수업과 같은 네트워크를 준비했는가?
- [ ] 교사가 고려 초기 시나리오와 version을 확인했는가?
- [ ] 아래 장애 시 대체 절차를 교사가 열어 두었는가?

## 8~10분 진행

1. **입장·편성**: QR과 수동 코드 입장을 확인하고 3~5명 모둠을 미리 본 뒤 시작한다.
2. **역할 확인**: 각자 자기 역할 자료에서 말할 근거 한 가지를 찾는다. 다른 역할의 비공개 본문을 화면으로 보여 주지 않는다.
3. **개인 최초 판단**: 친구 답을 듣기 전에 선택과 까닭을 적는다. 내용은 현재 탭에만 저장된다.
4. **말로 공유**: “내 자료에는…”으로 시작해 한 명씩 말하고, 말한 뒤에만 `설명했어요`를 누른다.
5. **공동 초안**: 정책 2개, 서로 다른 역할 근거 2개, 둘을 함께 써야 하는 까닭, 자료의 한계 1개를 고른다.
6. **전원 확인**: 모든 사람이 같은 revision을 확인한다. 수정하면 전원이 새 revision을 다시 확인한다.
7. **인계·종료**: 발표 문장을 읽고 교사가 활동을 종료한다.

## 리허설 관찰표

- [ ] 4~8명이 2분 안에 입장했다.
- [ ] 역할별 비공개 본문이 자기 기기 외에는 노출되지 않았다.
- [ ] 최초 판단 전에 다른 역할 근거가 화면에 나타나지 않았다.
- [ ] 전원이 말로 공유해야 공동 초안 단계가 열렸다.
- [ ] pause 중 학생 변경이 거부되고 resume 뒤 이어졌다.
- [ ] 새로고침·탭 복귀 뒤 호·모둠·역할·초안·확인이 복구됐다.
- [ ] 초안 수정 뒤 이전 확인이 모두 무효화됐다.
- [ ] 전원이 같은 revision을 확인해야 발표 문장이 열렸다.
- [ ] 도움 요청과 교사 해제가 정상 표시됐다.
- [ ] 종료 뒤 기존 학생 토큰이 거부되고 세션 하위 데이터가 삭제됐다.
- [ ] 전체 흐름이 8~10분 안에 끝났다.

관찰 결과는 `EXPERIMENTS.md`의 `EXP-009`에 기록한다. 실패는 학생 반응과 기능 결함을 구분하고, 바로 요구사항으로 승격하지 않는다.

## 장애 시 대체 절차

1. 교사가 `잠시 멈춤`을 누르고 참가자에게 화면을 유지하게 한다.
2. 1분 안에 새로고침과 네트워크 재연결을 한 번 시도한다. 같은 탭의 세션 토큰으로 복구되면 이어서 진행한다.
3. 복구되지 않으면 교사가 활동을 종료해 서버 데이터를 정리한다.
4. 교사가 다음 다섯 관점을 한 줄씩 읽어 준다: 신라계 귀족은 예우와 기존 질서, 후백제 지역 농민은 과도한 수취 완화, 발해 유민은 안전과 수용, 지방 호족은 지역 자치와 책임, 고려 관리 지망생은 공통 법과 관직 기준을 중시한다.
5. 모둠은 종이 또는 화이트보드에 정책 2개, 서로 다른 관점의 근거 2개, 자료의 한계 1개를 적고 한 사람이 발표한다.
6. 학생 이름·개인 선택·대화 원문은 별도로 수집하지 않는다.

이 대체 절차는 리허설과 수업의 학습 흐름을 보존하기 위한 교사 진행안이다. 독립 정적 웹 대체판이 아니므로 실제 학생 사용 전 리허설에서 교사가 직접 실행 가능성을 확인해야 한다.
