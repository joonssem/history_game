# Convex 기반 초등학교 수업 개인정보 보호 선행 감사

- 감사일: 2026-09-07 · 공급자 공개 문서 재검토: 2026-09-08
- 담당 역할: audit agent
- 적용 범위: Vercel 화면 + Convex 실시간 백엔드로 운영하려는 협동 MUD
- 결론: **P1 개인정보 차단 게이트** — 이 프로젝트는 사용자 확인에 따라 교사 제작 교육용 저작물로 분류하므로 학습지원 소프트웨어 선정·학교운영위원회 심의 게이트는 적용하지 않는다. 다만 가상 데이터 개발은 가능하지만, 개인정보·국외 처리 확인과 문서화가 끝나기 전에는 실제 학생을 접속시키거나 학생 관련 데이터를 Convex에 보내지 않는다.
- 주의: 이 문서는 법률 자문이 아니라, 현행 법령·교육부 기준과 Convex 공식 문서를 바탕으로 만든 프로젝트 착수 점검표다. 최종 판단은 학교 개인정보 보호책임자·담당자와 관할 교육청 지침을 따른다.

## 1. 핵심 판단

1. **이름을 받지 않아도 개인정보일 수 있다.** 모둠·역할·호(號)·제출 여부·시각 정보가 교사가 가진 좌석표나 모둠표와 쉽게 결합되어 학생을 알아볼 수 있다면 개인정보에 해당할 수 있다. 따라서 현재 설계 데이터는 익명정보로 단정하지 않고 개인정보로 취급한다.
2. **만 14세 미만 동의는 조건부 의무다.** 처리 근거가 동의인 경우에는 법정대리인 동의와 확인 절차가 필요하고, 아동에게는 쉬운 말로 알려야 한다. 반대로 학교 교육업무의 다른 적법 근거가 인정되는지는 교사가 임의로 정하지 말고 학교 담당자가 확인해야 한다.
3. **Convex 사용은 처리위탁과 국외 처리 검토가 필요하다.** Convex DPA는 고객을 controller, Convex를 processor로 규정한다. Convex 리전은 현재 미국 동부와 아일랜드뿐이므로 어느 쪽도 국내 보관이 아니다. 하위처리자 목록에는 미국 등 다른 지역에서 처리하는 업체도 포함되어 있다.
4. **수업 종료 즉시 DB 행을 지우는 것만으로 파기 검증이 끝나지 않는다.** 애플리케이션 데이터 외에 로그·백업·지원 도구·하위처리자 잔존 여부와 삭제 일정을 계약·운영 문서로 확인해야 한다. Convex DPA는 계약 종료 시 고객 개인정보를 삭제하되 백업·보관 사본은 Convex 보존 일정에 따라 삭제한다고 적고 있다.
5. **프로젝트 분류는 교사 제작 교육용 저작물이다.** 2026-09-08 사용자는 이 프로젝트가 학교 교육과정 운영 지원을 목적으로 외부에서 개발·보급된 것이 아니므로 심의 대상이 아니라고 재확인했다. 학습지원 소프트웨어 선정·학교운영위원회 심의 항목은 개인정보 게이트에서 제외한다. 이 분류는 Convex·Vercel의 임시 식별정보 처리·처리위탁·국외 처리 의무까지 없애는 것은 아니다.

분류 근거로 사용자가 제시한 자료는 [KDI 경제교육·정보센터 정책자료 첨부](https://eiec.kdi.re.kr/policy/callDownload.do?num=275455&filenum=2&dtime=20260516215955), [에듀집 안내](https://edzip.kr/main-notice/6a4de3afa450e64b79a52ce4), [한국교총 안내](https://www.kfta.or.kr/usr/wap/detail.do?app=16527&seq=270003468225)다. 교육자료 분류 결정은 [D-022](../../DECISIONS.md), 활동별 식별정보 수명주기는 [D-023](../../DECISIONS.md)에서 관리한다.

## 4. 학교에 그대로 물어볼 질문

1. 이름·학번·계정은 받지 않지만, 모둠/역할/호/제출 상태가 수업 중 교사의 모둠표와 연결될 수 있습니다. 이를 학생 개인정보로 보고 처리해야 하나요?
2. 이 처리의 적법 근거는 무엇이며, 별도 동의를 근거로 삼아야 한다면 만 14세 미만 학생의 법정대리인 동의·확인 방식은 무엇인가요?
3. Convex가 미국 동부 또는 아일랜드 리전에 저장하고 미국 등의 하위처리자를 이용할 수 있습니다. 학교·교육청의 국외 처리 또는 외국산 SaaS 제한이 있나요?
4. Convex와 Vercel을 개인정보 처리 수탁자로 등록하고 DPA·재위탁 목록을 검토하는 내부 절차는 무엇인가요?
5. 수업 종료 즉시 운영 DB를 삭제해도 공급자 로그·백업은 별도 보존될 수 있습니다. 학교가 허용하는 최대 보유기간과 필요한 삭제 증빙은 무엇인가요?

## 5. 구현 시 고정할 개인정보 보호 기본값

- 학생 계정, 이름, 학번, 이메일, 자유서술형 개인정보 입력을 만들지 않는다.
- 서버의 학생 식별자는 수업별 무작위 값으로 만들고 다른 수업에서 재사용하지 않는다.
- QR에는 짧은 순차 코드 대신 충분히 긴 무작위 세션 토큰을 넣고, 수업 종료 또는 짧은 제한시간 후 만료한다.
- 개인 선택과 이유는 기기 메모리에만 유지한다. 서버에는 모둠 합의에 필요한 최소 상태만 보낸다.
- 교사 화면은 개인별 답이 아니라 `미제출 인원 수` 등 집계 중심으로 설계한다.
- 서버 로그에 요청 본문, 토큰, 호, 역할, 답변을 출력하지 않는다.
- 수업 종료 시 앱 데이터 자동 삭제와 교사 강제삭제를 모두 제공하고, 삭제 실패를 교사에게 알린다.
- 개발·미리보기·운영 환경을 분리하고 운영 데이터를 개발 환경으로 복사하지 않는다.
- 실제 학생 적용 전에는 가상 학생 데이터만으로 삭제·재접속·권한·동시접속 시험을 한다.
- 개인정보 처리방침과 아동용 안내문에는 목적, 항목, 보유기간, 처리 국가, 수탁자/하위처리자, 권리행사·삭제 방법을 쉬운 말로 적는다.

## 6. Convex에 대해 확인된 사실과 남은 공백

### 확인됨

- 관리형 Convex Cloud는 AWS에서 운영되고 저장 데이터는 AES-256, 전송 데이터는 TLS/SSH 등으로 암호화한다고 밝힌다.
- 새 배포 생성 시 미국 동부(N. Virginia) 또는 EU 서부(Ireland) 리전을 선택할 수 있다. 기존 배포의 리전은 바꿀 수 없어 새 배포 생성·데이터 이전이 필요하다.
- DPA상 고객은 controller, Convex는 processor이며, Convex는 하위처리자를 사용할 수 있다. 고객은 신규 하위처리자 통지 뒤 10일 안에 이의를 제기할 수 있다고 되어 있다.
- DPA는 고객에게 적법 근거·고지·동의 확보 책임을 두며, 국제 이전과 계약 종료 후 백업/보관 사본의 잔존 가능성을 명시한다.

### 계약·지원 문의로 확인해야 함

- 무료/Starter 요금제에서도 학교가 요구하는 형태로 DPA가 유효하게 체결되는지와 체결 주체
- 선택 리전 밖의 지원·관측·분석 하위처리자가 실제 학생 데이터 또는 식별 가능한 로그에 접근하는 범위
- 문서에 수치로 공개되지 않은 로그·백업·삭제 대기기간과 삭제 증명 제공 가능 여부
- 한국 「개인정보 보호법」 및 학교의 위탁 계약 필수 조항을 Convex 표준 DPA만으로 충족하는지
- 사고 통지 시간, 국내 담당 연락처, 정보주체 권리 요청 처리시간이 학교 요구조건을 만족하는지

### 공급자 계약·감독 기록

- Convex는 미국 동부·아일랜드 중 새 배포 생성 시 리전을 선택한다. 실제 학생 운영 리전은 학교의 국외 처리 허용 확인 뒤 결정한다.
- Vercel DPA에서 고객은 Customer Data의 controller, Vercel은 Pro·Enterprise 고객에 대한 processor로 규정된다. Service-Generated Data는 Vercel이 controller로 처리할 수 있다.
- Vercel은 하위처리자 목록을 Trust Center에서 관리한다. 변경 통지는 자동이 아니며 `privacy@vercel.com`으로 구독해야 하고, 통지 후 5일 이내 합리적 개인정보 우려를 제기하는 절차가 있다.
- Convex 하위처리자 변경 통지와 이의 절차는 기존 DPA 기록을 유지하되, 운영 직전 실제 목록·적용 요금제·계약 주체를 다시 캡처한다.
- 공급자 문의 전까지 “수업 종료 즉시 삭제”는 운영 DB 행에 대한 앱 수용 기준일 뿐, 공급자 로그·백업까지 즉시 파기된다는 의미로 사용하지 않는다.

### 아직 필요한 확인

1. 학교가 개인정보처리자인지, 교사의 수업 운영상 처리 근거가 무엇인지, 동의가 필요한 경우 법정대리인 절차가 무엇인지
2. 학교·교육청이 미국 또는 아일랜드 및 하위처리자 지역으로의 처리를 허용하는지
3. Convex Starter/무료 계약에서 DPA 체결 주체, 로그·백업 보존기간, 삭제 증명, 지원 인력 접근 범위
4. Vercel Hobby는 공개 DPA 적용 대상이 아니므로 실제 학생 운영 시 Pro 이상 계약과 학교의 위탁 절차가 필요한지
5. 두 공급자의 하위처리자 목록·변경 통지를 누가 구독하고 검토할지

## 7. 진행 판정

### 2026-09-08 가상 데이터 기술 통합 결과

- Auth0는 Google 연결만 활성화한 SPA로 구성했고, localhost와 Vercel 고정 주소의 callback·logout·web origin만 허용했다.
- Vercel GitHub App은 `joonssem/history_game` 한 저장소에만 접근하도록 제한했고, 프로젝트 루트는 `apps/cooperative-live`로 설정했다.
- Vercel에는 공개 클라이언트 변수 4개만 등록했다. 실제 교사 Auth0 `sub` 허용목록은 Convex 배포 환경변수에만 두었다.
- 가상 학생 8명으로 입장·편성·시작을 검증한 뒤 세션을 정리했다. 이후 Convex 개발 배포의 `sessions`, `players`, `rooms`, `interventions`가 모두 비어 있음을 확인했다.
- 이 결과는 운영 DB 행 삭제와 권한 경계의 기술 검증이며, 공급자 로그·백업까지 즉시 파기됐다는 증명이나 실제 학생 사용 승인을 뜻하지 않는다.

### 2026-09-09 입장 자격·시도 제한 구현 결과

- QR 입장을 6자리 코드와 분리해 `/join#entry=...`의 256비트 난수키로 바꿨다. Convex에는 SHA-256 해시와 만료 시각만 저장하며, 학생 화면은 fragment를 읽은 즉시 주소창에서 제거한다.
- QR·수동 코드는 생성 또는 재개방 후 최대 15분, 학생 복구 토큰은 최대 2시간만 유효하다. 미리보기 진입·활동 시작·종료 시 입장 자격을 폐기하고, 예약 정리 함수가 만료 QR 해시와 시도 버킷을 제거한다.
- 수동 코드 실패는 서버 비밀키 HMAC 버킷으로만 센다. 브라우저 버킷은 5분 5회 뒤 10분, 코드 버킷은 5분 30회 뒤 5분 차단하며 코드·IP·User-Agent 원문은 저장하지 않는다.
- Convex 개발 배포에서 존재하지 않는 코드로 5회 실패시켜 브라우저 버킷의 `failedAttempts=5`·`blockedUntil`과 코드 버킷의 `failedAttempts=5`를 확인했다. 저장된 두 식별자는 모두 64자리 HMAC 해시였고 원문은 없었다.
- 이 결과는 가상 데이터 보안 기능의 개발 검증이다. Vercel Preview의 요청·Runtime·Build Logs 검증과 실제 학생 운영 승인은 별도다.

```text
가상 데이터 로컬/클라우드 개발: 가능
실제 학생 데이터 없는 네트워크·동시접속 시험: 가능
학생이 실제로 접속하는 Convex 시험: 보류
실제 수업 운영·교사 대시보드 사용: 보류
```

**해제 조건:** 3절 1~2번의 개인정보·계약 게이트가 문서로 확인되고, 3~4번 기술 통합 테스트가 통과되어야 한다. 학교가 국외 처리 또는 해당 외부 SaaS를 허용하지 않으면 Convex 결정(D-019)을 다시 열고 국내 리전/기관 승인 서비스 또는 교실 내 로컬 방식으로 전환한다.
