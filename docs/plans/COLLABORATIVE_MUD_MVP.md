# 고조선 8조법 실시간 협동 MUD — MVP·화면·개발 순서

2026-09-06 · TASK-20260906-01 · 상태: 설계 검토안. [전체 계획](./COLLABORATIVE_MUD_PLAN.md), [아키텍처·스키마](./COLLABORATIVE_MUD_ARCHITECTURE.md).

> 후속 운영 검토: [전체 계획 §10](./COLLABORATIVE_MUD_PLAN.md)에서 Vercel로 복습·협동 앱의 화면 호스팅을 통일하는 안을 설명한다. 별도 저장소·GitHub Pages 유지는 MVP의 필수 조건이 아니다. 기존 복습은 짧은 활동이며 아래 40분은 협동 수업 전체의 설계 예산이다.

## 1. 한 문장 목표

학생 21명이 40분 수업 안에 서로 다른 자료를 말로 공유하고, 개인 판단을 근거로 검토한 뒤 모둠 법을 만들어 실제 고조선 범금 8조와 비교한다. 무작위 4·4·4·4·5인 편성을 기본 제안으로 삼고 3/4/5인 모두를 지원한다.

## 2. 기능 범위

| 영역 | MVP 필수 | 다음 버전 | 장기 아이디어 |
|---|---|---|---|
| 입장·권한 | 교사 1명 인증·소유권, 학생 가입 없는 입장, 일회 코드·복구·입장 잠금 | 다른 교사 초대·자기 학급 개설 UI | 학교·조직별 권한 관리 |
| 편성 | 참석 수 입력, 3/4/5인 배열, 무작위 배정·교사 확인·수정·확정 | 이전 조합 중복 완화 검토 | 학생 장기 기록 기반 최적화는 필요성과 개인정보 범위부터 검토 |
| 학생 학습 | 역할별 단서, 개인 최초 판단·이유, 실제 공유, 새 증거, 재판단, 공동 법 확인, 역사 비교 | 사건 2 확장, 자유 문장형 법 | 한산도·위화도 등 후속 시나리오 |
| 공동 상태 | 서버 기준 단계·응답·초안·전원 확인, 중복 입력 방지, pause·복구 | 모둠별 진행 방식 세분화 | 여러 시나리오 공통 엔진 |
| 교사 운영 | 모둠 현황, 기본 힌트, 전체/모둠 pause·resume, 시작·역사 공개·종료 | 자유 사건 보내기, 다중 교사 개입 | 수업 간 종합 통계 |
| 결과·로그 | 최초/수정 선택·이유, 공유 자기 보고 시각, 단계·pause 시각, 최종 법·확인자, 힌트 이력, 삭제 | 연구 목적·보관 승인 후 내보내기 | 장기 종단 연구 |
| 소통 | 대면 대화, “내 자료에는…”, “왜 그렇게 생각했어?” 안내, 도움 요청 | 접근성 필요에 따른 대체 의사표현 | 자유 채팅은 현재 도입 계획 없음 |

제외: 레벨·경험치·체력·재화·인벤토리·전투·자유 탐험·LLM NPC·순위표·음성 녹음·모든 클릭 수집·학생 계정 가입·기존 유물 보상 연동. 기술 확인용 개발 환경은 만들 수 있지만, 전체 제품 마이그레이션이나 공개 배포는 이번 설계 산출물에 포함하지 않는다.

## 3. 학생·교사 사용자 흐름

학생: 허브 링크 → 수업 코드/입장 코드 → 가명 코드 확인 → 대기 → 배정 모둠으로 이동 → 역할·비밀 단서 → **혼자 최초 판단·이유 제출** → 말로 정보 공유 → 새 증거 → 판단 유지/변경·이유 → 공동 법 확인 → 교사 전체 공개 대기 → 실제 역사 비교 → 종료.

교사: 로그인 → 수업 생성(21명·3/4/5인 제안·40분) → 코드 배부 → 참석 확인 → 무작위 편성 미리보기·교사 수정 → 편성 확정·착석 확인 → 시작 → 도움 필요한 모둠 확인 → 필요 시 힌트·pause/복구 → 법 준비 상태 확인 → 역사 자료 전체 공개 → 결과 확인·종료.

최초 판단 전에 다른 역할의 단서를 모둠에 설명하지 않도록 교사도 안내한다. 앱은 공유 단계 전 남의 최초 응답을 보여 주지 않는다. 화면 공유를 막는 시험 감독 도구로 만들지는 않는다.

교사는 게임 도중 계속 태블릿만 볼 필요가 없어야 한다. 개별 학생 상세는 눌러 펼치고 기본 화면에서는 막힌 모둠·도움 요청·전체 공개 준비 상태가 먼저 보이게 한다.

## 4. 정보 구조와 화면

| 경로 | 핵심 컴포넌트·정보 |
|---|---|
| `/` | 소개, 학생 입장, 교사 로그인 |
| `/join` | 수업 코드·일회 코드, 입장 오류·재시도, 복구 안내 |
| `/play/[sessionId]` | SessionStatus, RoleCard, PrivateClue, PersonalDecision, DiscussionPrompt, NewEvidence, LawReview, HistoryComparison |
| `/teacher` | 내 수업 목록·새 수업 |
| `/teacher/sessions/new` | 참석 인원·크기 배열·세션 옵션 |
| `/teacher/sessions/[sessionId]` | 대기 명단·무작위 편성·모둠 카드·개입·최종 결과 |

학생 학습은 단계마다 URL을 바꾸는 대신 서버 상태에 맞는 컴포넌트를 표시한다. 로딩 중, 저장 대기, 저장됨, 재접속 중, 교사 일시정지, 권한 만료를 구별한다.

```text
학생: 최초 판단
┌──────────────────────────────────────┐
│ 2모둠 · S07      나의 역할: 증거 확인 │
│ 사건: 곡식이 사라졌어요              │
│ [내 정보 다시 보기]                  │
│ 지금 어떻게 해결하면 좋을까요?       │
│ [선택 A] [선택 B] [선택 C] [선택 D]   │
│ 내 판단의 근거: [단서/관점 선택]      │
│ [내 생각 제출]      저장 상태         │
│ 제출 뒤 친구의 정보 공유를 기다려요.  │
└──────────────────────────────────────┘

학생: 모둠 법 확인
┌──────────────────────────────────────┐
│ 우리가 만든 법 · 수정 2              │
│ 피해 / 대응 / 적용 조건              │
│ 초안을 읽고 각자 답해 주세요.         │
│ [이 초안에 동의해요] [더 이야기해요]  │
│ 확인: 4/5명         [도움 요청]       │
└──────────────────────────────────────┘

교사: 진행 화면
┌──────────────────────────────────────┐
│ 수업: 고조선     [전체 멈춤] [종료]   │
│ 21명 중 최근 접속 20명 · 확인 필요 1  │
│ 1모둠 4명 | 공유 3/4 | 도움 요청      │
│ 2모둠 4명 | 새 증거 확인             │
│ 5모둠 5명 | 법 확인 4/5              │
│ [모둠 상세·힌트·접속 복구]            │
```

비밀 단서는 공용 교사 화면에 자동 노출하지 않는다. 교사가 개별 확인할 때만 펼친다. 본문 크기 조정, 터치 버튼 44 CSS px 이상을 설계 목표로 두고 색상만으로 상태를 표현하지 않는다. 드래그는 필수 조작으로 쓰지 않으며 아이패드 세로·가로·화면 키보드 상태를 확인한다.

## 5. 교사 대시보드의 최소 데이터

모둠별 예정/참여/최근 접속 수, 단계와 경과 시간, 역할 배정 여부, 읽기 확인 수, 공유 자기 보고 수, 개인 판단 제출 수, 판단 유지/변경, 법 초안·확인 수, 도움 요청을 표시한다. 최초·수정 선택과 이유는 모둠 상세에서 본다.

필수 개입은 시작, pause/resume, 정해진 문구 힌트 2~3종, 입장 재발급/이탈 처리, 역사 공개, 종료다. 자유 텍스트 돌발 사건은 후속으로 미룬다. 전원 미응답을 교사가 임의로 ‘동의’로 바꾸는 기능은 만들지 않는다. 시간이 부족하면 ‘합의 미완’ 상태를 남기고 역사 비교로 간다.

## 6. 수업 성공 기준과 관찰

아래 기준은 파일럿의 제안 수용 기준이며 검증된 효과나 이미 측정한 결과가 아니다.

| 질문 | 수집·관찰 | 해석 원칙 |
|---|---|---|
| 자기 정보를 읽고 말하는가? | 자기 보고+교사 표본 관찰, 모둠당 실제 정보 발화 확인 | 버튼만으로 읽기·발화를 증명하지 않음 |
| 모두 판단에 참여하는가? | 참석 학생의 최초/수정 응답, 5인 E의 발화·법 확인 | 미제출·이탈은 별도 표시, 100% 수치 맞추기 위해 대리 제출하지 않음 |
| 서로 다른 관점이 드러나는가? | 법 선택의 근거에 두 관점 이상 연결되는지 교사 확인 | 의견 충돌을 억지로 유도하거나 학생 갈등 자체를 보상하지 않음 |
| 새 정보로 재검토하는가? | 최초·수정 선택과 이유 비교 | 선택 유지도 근거가 있으면 성공 |
| 한 학생이 독점하는가? | 입력 담당 외 학생이 설명·확인하는지 관찰 | 전원 동의 클릭은 대화의 질을 대체하지 못함 |
| 실제 역사와 비교하는가? | 공통점/차이 1개와 궁금한 점 표본 확인 | 학생 법의 역사 정답 일치율로 채점하지 않음 |

운영 수용 조건: 40분 안에 역사 비교 시간을 포함해 마무리할 수 있음, 모든 참석자가 역할과 개인 판단 기회를 얻음, 3/4/5인 어디에서도 핵심 단서가 사라지지 않음, 네트워크 복구·동시 제출 때문에 수업이 진행 불가가 되지 않음. 실제 관찰 전 완료했다고 표시하지 않는다.

새 가설: ‘무작위 4인 중심+5인 1모둠에서도 모두 고유 단서를 설명한다.’ 작은 실험은 첫 수업의 모둠별 관찰이며, 실패하면 다음 활동에 3인 포함 편성 또는 5인 단서·발언 구조를 조정한다. 결과와 다음 결정은 추후 EXPERIMENTS에 기록하며 이번에는 결과를 만들지 않는다.

## 7. 로그 최소 범위

- 필수: 세션 한정 참가 코드, 역할, 최초/수정 선택·이유·서버 제출 시각, 공유 자기 보고 시각, 방 단계 진입·pause/resume, 최종 법·확인 revision, 힌트 이력.
- 파생: 판단 변경 여부, pause 제외 단계 시간, 법 결정까지 시간. 별도 중복 저장보다 필수 기록에서 계산한다.
- 나중: 사건별 모든 수정 과정, 장기 통계, 연구용 export. 연구 목적·보관 범위를 정한 뒤 추가한다.
- 미수집: 음성, 화면 녹화, 이름·학번·이메일, 기기 고유 ID, 위치, 개인을 추적하는 IP 기반 분석. 서비스 제공자 운영 로그는 별도 범위로 확인한다.

최초 판단은 공유 이전의 기준점으로 보존한다. 브라우저 네트워크 지연 때문에 제출 시각은 실제 생각한 시각과 다를 수 있다. 행동 시간이나 선택 변화만으로 학습 성과를 단정하지 않는다.

## 8. 가장 먼저 만들 수직 슬라이스

**교사 1명+서로 분리된 학생 세션 4개로 ‘세션 생성→가입 없는 입장→역할별 정보→비공개 최초 판단→교사 제출 수 갱신→새로고침 복원’까지 연결한다.**

역할 카드만 먼저 대량 작성하거나 교사 화면을 마지막에 붙이지 않는다. 이 작은 경로에서 입장·정보 분리·실시간 갱신·저장 복구를 먼저 증명한다. 서로 다른 탭만 사용하면 인증 저장소가 공유될 수 있으므로 독립 브라우저 컨텍스트와 실제 별도 기기로 검증한다.

## 9. 개발 단계

| 단계 | 목표·구현 | 완료 조건 |
|---|---|---|
| Phase 0 — 내용·정적 제작 | 아이디어 확장·고도화 → 정적 협동 MUD 제작·수업 검증. 최초 판단 순서 정렬, 3/4/5인 단서, 타이머 페이싱 값 확정 | 40분 배분 가능, 정보 누락·후속 증거 중복·정답 유도 문구 검토. 현재 코드 수정과 혼동하지 않음 |
| Phase 1 — 첫 수직 슬라이스 | 신규 앱·개발 Convex·인증·교사 최소 화면·입장·역할·최초 판단 | 4개 독립 학생 세션에서 역할 분리, 남의 응답 접근 거부, 교사 실시간 표시, 새로고침 복원 |
| Phase 2 — 학급 편성 | 가변 N·크기 배열·무작위 편성·교사 수정/확정, 3/4/5인 자료 분배 | 19/21/22/25명 합계·중복 없는 배정, 시작 후 재편성 제한, 5번째 학생 고유 단서 |
| Phase 3 — 학습 루프 | 공유→새 증거→재판단→법 초안·전원 확인→역사 공개 | 서버 전이 규칙·revision, 이중 탭·오래된 제출·초안 변경 후 재확인 통과 |
| Phase 4 — 교사 수업 운영 | 모둠 상세, 힌트, 전체/모둠 pause, 복구 코드, 이탈·합의 미완, 종료·삭제 | 끊김·기기 교체·진행자 이탈·다른 교사 세션 접근 거부, 보관 만료 정리 검증 |
| Phase 5 — 교실 적용 | 실제 아이패드와 학교 Wi-Fi 리허설, 학생21+교사1 접속, 40분 수업 관찰 | 기존 Pages 링크 정상, 실시간에서 정적 버전으로 전환 가능, 운영 조건과 교육 관찰 기록 완료 |

예상 개발 일수는 아직 산정하지 않는다. 인증·학교 네트워크 리허설 결과에 따라 범위가 달라진다. Phase 0에서 학습 흐름이 성립하지 않으면 서버 기능을 늘리기 전에 콘텐츠를 수정한다.

## 10. 검증 계획

신규 앱 구현 시 수행할 검사이며 이번 문서 작성에서 통과했다고 주장하지 않는다.

- 상태·권한: 학생이 다른 역할/모둠/세션 자료를 요청하거나 교사 API를 호출할 때 거부. 다른 교사 세션 ID 추측 접근도 거부.
- 동시성: 같은 입장 슬롯을 두 기기가 동시에 요청, 마지막 동의와 초안 수정 경합, 전원 제출 직후 이중 전이, 일시정지와 늦은 제출 경합.
- 복구: 최초 판단 후 새로고침, 아이패드 잠금·백그라운드·Wi-Fi 재연결, 인증 정보 삭제·교사 재발급, 진행자 이탈.
- 가변 인원: 3/4/5인 공통 정보 집합 확인, 21명·19명·22명·25명 배정, 3명 미만 처리, 접속 끊김을 자동 퇴실로 간주하지 않음.
- 회귀: 신규 앱의 typecheck·build·서버 규칙 테스트·브라우저 핵심 흐름. 기존 허브 링크 수정 시 기존 `scripts/06_validate_static_assets.py` 및 실제 정적 페이지 연결 확인. 기존 엔진까지 변경하지 않았다면 불필요한 전체 콘텐츠 재작성·테스트 추가는 하지 않음.

## 12. 다음 구현 작업 준비

이번 추천을 검토한 뒤 첫 슬라이스를 하나의 구현 목적 단위로 확정한다. 저장소 위치, 교사 인증 방식과 서비스 프로젝트·환경, 보관 기간, 실제 교과서와 선행학습, 네트워크를 확인한다. 3/4/5인 카드와 선택·이유 문안은 교사 관점에서 검토한다. 다른 교사 초대 UI·장기 연구 로그를 이 첫 작업에 섞지 않는다.

현재 확인된 학생 수·40분·무작위 편성·본인 학급 우선은 추가 확인 없이 다음 설계에 그대로 이어받는다.
