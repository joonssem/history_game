# Regular MUD 게임성 레드팀 교차검증

> 기준: `origin/main` `9b12513` (2026-09-10)
> 선행 감사: [`regular_interaction_diversity_audit.md`](./regular_interaction_diversity_audit.md)
> 범위: 실패, 판정, 난이도, 긴장, 에이전시, 재도전 가치. 역사 사실·화면 미술 평가는 제외한다.
> 성격: 읽기 전용 감사. 게임 코드와 MUD JSON은 수정하지 않았다.

## 판정

레드팀 분석은 **“현재 게이트가 역사적 이해가 아니라 조작 완료를 판정한다”**는 핵심을 정확히 짚었다. 그러나 “좌표 암기”, “게임 전체에 실패·점수·보상이 전무”, “시대순 난이도 상승이 필요”라는 표현은 코드와 제품 구조보다 강하다.

현재 문제를 가장 정확하게 표현하면 다음과 같다.

> Regular MUD는 학생이 서로 다른 표시를 한 번씩 눌렀는지는 확인하지만, 단서 사이의 관계를 이해하거나 근거를 사용해 판단했는지는 확인하지 않는다.

이는 단순 UI 반복을 넘어선 게임성·학습 판정의 구조 문제다. 다만 해결책은 감점·속도 경쟁이 아니라 **판단의 약속(commitment), 근거 기반 수정, 여러 유효 경로, 결과의 질적 차이**여야 한다.

## 1. 주장별 교차검증

| 레드팀 주장 | 판정 | 코드·데이터 근거 |
|---|---|---|
| 시뮬레이터 오입력에 리스크가 없다 | **대체로 사실** | 잘못된 순서·빈 공간 클릭은 상태·진행도를 바꾸지 않고 시도 횟수도 기록하지 않는다. 소리·문구와 실제 소요 시간 외 비용이 없다. 다만 이후 역사 선택지의 오답은 IF 단계로 이동한다. |
| 판정이 역사 이해가 아니라 좌표 암기다 | **핵심은 사실, 표현은 과장** | 히트 테스트는 좌표 거리만 보며 feedback 읽기를 요구하지 않는다. 그러나 원 안에 라벨이 보이고 동일한 DOM 대체 버튼도 제공되므로 순수한 좌표 기억 시험은 아니다. 정확한 표현은 “표시 찾기·라벨 수집”이다. |
| 좌·중·우 배치가 반복된다 | **사실** | JSON 핫스팟 102개 중 76개가 정확히 같은 세 좌표를 사용하고, custom radius는 0개다. |
| 함정 단서가 없다 | **ordered-hotspot에서는 사실** | JSON 핫스팟을 가진 `ordered-hotspot` 55개 모두 sequence가 전체 hotspot 집합을 정확히 덮는다. sequence 밖의 distractor를 가진 단계는 0개다. 나머지 discovery 계열은 정의상 표시된 모든 단서가 유효하다. |
| 난이도 곡선이 평탄하다 | **기계적 난이도는 사실** | 28개 Regular 중 19개는 모든 필수 단계의 target이 3이고, 20개는 모든 필수 단계가 원형 핫스팟 계열이다. 다만 역사 내용의 읽기 난이도까지 같다는 뜻은 아니다. |
| 시간·점수·콤보·보상이 전무하다 | **Regular 시뮬레이터 성과 판정에는 사실, 앱 전체에는 거짓** | Regular 시뮬레이터에는 시간·점수·연속 성공 지표가 없다. 그러나 퀴즈에는 타이머·점수·등급이 있고 앱에는 유물·배지가 있다. |
| 에이전시가 없다 | **시뮬레이터에는 거의 사실, MUD 전체에는 부분적** | 두 주요 interaction은 하나의 완료 상태로 수렴한다. 역사 선택지는 오답 IF 분기가 있지만 결국 같은 정답 경로로 돌아오며, 화면 표시 순서는 섞인다. |
| 재도전 가치가 없다 | **낮다는 평가는 타당, 0은 과장** | 증거·좌표·결말은 고정이고 재획득 보상도 없다. 다만 선택지 위치 셔플, 미방문 IF 분기, 학습 복습 가치는 남는다. |

## 2. 실패와 리스크

`processOrderedHotspot()`은 다음 세 경우를 구분한다.

1. 빈 공간: 진행 없음, 안내 문구
2. sequence 밖 단서: 진행 없음, 오답 소리
3. 순서가 이른 단서: 진행 없음, 선행 단서 안내

정답일 때만 `state.found.push()`와 진행도 증가가 일어난다. 잘못된 시도는 `simActionCount`에도 들어가지 않고 별도 attempt·mistake 상태도 남지 않는다. 따라서 학생은 가능한 위치를 비용 없이 순회할 수 있다.

그러나 여기서 곧바로 감점·초기화·시간 제한을 넣는 것은 권하지 않는다.

- 읽기 속도가 느린 학생을 불리하게 만들 수 있다.
- 역사적 피해·전쟁 소재에서 콤보·속도 보상은 내용과 어긋날 수 있다.
- 숨은 규칙을 틀렸다는 이유로 진행도를 잃으면 역사 추론보다 UI 규칙 학습이 앞선다.

필요한 실패 비용은 **처벌 비용**이 아니라 **판단 기록의 결과**다. 첫 판단을 먼저 남기고, 근거를 본 뒤 수정했는지 비교하며, 부족한 근거에는 추가 단서가 열리는 방식이 적절하다.

## 3. 좌표 판정과 이해 판정

레드팀이 찾은 가장 중요한 결함은 히트박스 자체가 아니다. 터치 화면은 어떤 방식이든 좌표 판정이 필요하다. 문제는 좌표 입력 뒤 완료 여부가 다음만 확인한다는 점이다.

- 서로 다른 hotspot ID를 눌렀는가
- 정해진 sequence를 따랐는가
- target·minActions를 채웠는가

확인하지 않는 것은 다음이다.

- 두 단서가 어떤 관계인지
- 어느 단서가 주장에 더 적합한지
- 반례·제한 조건을 구분했는지
- 근거를 사용해 처음 판단을 수정했는지

따라서 “좌표 암기 게임”보다 **“근거를 읽지 않아도 통과되는 표시 수집 게이트”**가 더 정확한 진단이다.

## 4. 함정 부재보다 더 큰 문제: 오답의 질이 없다

JSON 기반 ordered-hotspot 55개는 모두 `hotspots == sequence` 집합이다. 화면에 보이는 세 단서는 전부 언젠가 눌러야 한다. 틀릴 수 있는 것은 오직 순서뿐이다.

함정 단서를 무작정 추가하는 것도 충분한 해결이 아니다. 학생이 “그림에 섞인 가짜 원 찾기”를 잘하게 될 뿐 역사적 판단이 늘지 않을 수 있다. 필요한 것은 다음과 같은 **그럴듯하지만 근거가 약한 대안**이다.

- 같은 시대지만 현재 주장과 직접 관련 없는 자료
- 사실이지만 원인과 결과의 방향이 뒤바뀐 연결
- 한 사례를 전체 시대로 일반화한 주장
- 자료가 말해 주는 범위를 넘어선 단정

오답은 좌표 함정이 아니라 역사적 오개념을 드러내고 교정해야 한다.

## 5. 난이도 곡선은 어디에 있어야 하는가

Regular MUD는 포털에서 차시별로 선택할 수 있고, 반드시 선사→근현대 순서로 플레이하는 캠페인이 아니다. 따라서 전체 시대 순서에 따라 조작 난이도를 올리는 설계는 비선형 진입과 충돌한다.

난이도는 각 MUD 안에서 다음처럼 상승해야 한다.

```text
1단계 관찰 → 2단계 분류·순서화 → 3단계 인과·공간 추론 → 4단계 주장·근거·반례
```

현재는 많은 MUD가 네 단계 모두 `세 단서 누르기`로 구성돼 이 내부 곡선이 없다. 기계적 난이도 평탄화의 실제 단위는 “96개 장면 전체”보다 **각 10분 MUD의 4단계 구조**다.

## 6. 시간·점수·콤보를 바로 넣지 않는 이유

퀴즈 모듈에는 이미 15초 타이머, 점수, 등급, 최고점, 배지가 있다. 따라서 앱이 게임 피드백을 구현할 능력이 없다는 진단은 틀렸다. Regular MUD가 그 방식을 의도적으로 사용하지 않는 것이다.

역사 MUD에는 속도 대신 다음 질적 피드백이 적합하다.

| 일반 게임 요소 | 역사 탐구형 대안 |
|---|---|
| 목숨·감점 | 최초 판단과 수정 판단의 차이 기록 |
| 속도 점수 | 근거 충분도: 단서 확인 → 관계 연결 → 반례 검토 |
| 콤보 | 여러 단계에서 같은 주장에 일관된 근거를 사용했는지 |
| 랜덤 정답 | 사실은 고정하되 자료 조합·관점·초기 조건을 변화 |
| 실패 초기화 | 오개념에 맞는 추가 자료·대조 피드백 제공 |

목표는 긴장 자체가 아니라 다음 세 가지다.

```text
불확실성: 어떤 근거가 더 중요한가?
결과: 내가 고른 근거가 설명을 어떻게 바꾸는가?
에이전시: 하나 이상의 타당한 근거 경로가 있는가?
```

## 7. 재도전 가치

현재 동일 MUD 재플레이에서 바뀌는 것은 주로 선택지 표시 순서다. 단서 세트·관계·결말·보상은 고정이다. 첫 플레이 후 위치와 정답을 기억하면 조작 난이도가 급격히 낮아진다는 지적은 타당하다.

다만 재도전 가치를 위해 역사 사실 자체를 무작위화하면 안 된다. 안전한 변형 후보는 다음이다.

- 동일 자료군에서 이번에 비교할 자료 3개를 바꾼다.
- 서로 다른 두 타당한 주장 중 하나를 선택하고 근거를 구성한다.
- 첫 플레이와 다른 인물·지역·자료 관점에서 같은 사건을 다시 본다.
- 이전에 쓰지 않은 근거를 사용해야 추가 배지를 얻는다.

재플레이는 “좌표가 달라짐”이 아니라 “설명에 쓰는 근거와 관점이 달라짐”으로 만들어야 한다.

## 8. 수정된 파일럿 권고

앞선 감사는 서로 다른 시대의 대표 단계 3개를 제안했다. 레드팀 검토 후에는 **한 Regular MUD 전체를 수직 슬라이스로 바꾸는 방식**이 더 적절하다고 판단한다. 그래야 4단계 내부 난이도 곡선과 재도전 가치를 함께 시험할 수 있다.

1차 후보는 `regular_goryeo_culture`다.

| 단계 | 현재 | 파일럿 후보 |
|---|---|---|
| 1 팔만대장경 | 단서 3개 발견 | 핵심 특징 관찰 — 기존 discovery 유지 |
| 2 직지·금속활자 | 단서 3개 발견 | 제작·전파 과정 카드 순서화 |
| 3 벽란도·교류 | 단서 3개 발견 | 지도 지점·교역 근거 선택(`hotspot-choice` 재사용 검토) |
| 4 문화 종합 | 자료 3개 강제 순서 | 주장–근거 배치 + 과도한 일반화 구분 |

이 후보는 민감한 피해·전쟁 주제가 아니며 관찰·절차·공간·종합이라는 서로 다른 사고 행동을 한 편 안에 배치할 수 있다.

### 파일럿 수용 기준

- 인접한 두 단계가 같은 interaction family를 반복하지 않는다.
- 최소 한 단계는 여러 타당한 근거 경로를 허용한다.
- 오입력 횟수 자체보다 어떤 오개념을 골랐는지 로컬 상태에 기록한다.
- feedback을 읽거나 근거 관계를 확인하지 않으면 완료되지 않는다.
- 속도 점수·콤보·목숨은 넣지 않는다.
- 캔버스 없이도 44px 이상 DOM 버튼으로 모든 활동을 완료할 수 있다.
- 기존 10분 이내 목표를 유지한다.
- 학생 3명 이상에게 기존판과 파일럿을 비교해 이해·재미·완료 시간·재시도 의향을 관찰한다.

- 학습 저하·지루함의 직접 인과: 미검증
- 권고: 기존 P1 후보 유지
- 다음 단계: 사용자 승인 후 `implementation_plan_regular_interaction_diversity_pilot.md`에서 대상 MUD와 계약을 확정한다.
