## P0 — 동일 좌석 재시도 멱등화

- [x] 클라이언트가 서버 요청 전 256비트 좌석 토큰을 만들고 탭 세션에 저장한다.
- [x] QR `joinWithEntryKey`가 좌석 토큰을 전달하도록 한다.
- [x] 수동 `joinWithCode`가 별도 rate-limit `attemptId`와 좌석 토큰을 구분해 전달한다.
- [x] Convex 입장 함수가 같은 세션·토큰의 활성 참가자를 새 좌석 생성보다 먼저 반환한다.
- [x] 응답 유실 후 같은 코드·토큰 요청은 원래 참가자 ID와 자격으로 수렴한다.
- [x] 제외된 참가자의 자동 재활성화를 거부한다. 세션 범위 조회로 다른 세션 좌석을 재사용하지 않으며 종료 세션 진입은 거부한다.
- [x] 정원 초과 판단 전 기존 좌석 재시도를 허용하고 신규 참가자만 제한한다.

## P0 — 복구 안내

- [x] QR 실패 후 같은 탭에서 재시도할 수 있는 동작과 오류 안내를 추가하고, 대기 중인 QR 입장키를 성공 전까지 탭 저장소에 두어 새로고침을 지원한다.
- [x] 교사 자료에 동일 탭 새로고침, 수업 코드 재시도, 분실 시 teacher-issued code 순서를 추가한다.
- [x] 12자리 코드의 개별 전달·5분 만료·1회용·토큰 회전·좌석 보존을 안내한다.
- [x] 서버 오류 원문, 학생 이름·학번·개인 답을 운영 기록으로 요구하지 않는다.

## 회귀 검증

- [x] QR 동일 토큰 2회 요청 뒤 `players` 행이 하나다.
- [x] 수동 코드 동일 토큰 2회 요청 뒤 `players` 행이 하나다.
- [x] 참가자 한도에 도달한 뒤 같은 좌석 토큰 요청은 성공하고, 새 토큰은 거부한다.
- [x] 동시 반복 mutation이 한 좌석으로 수렴한다.
- [x] 같은 좌석의 수업 진행 중 재접속, 새 토큰의 진행 중 입장 거부, 잘못된 코드의 rate-limit 경계를 자동 검사한다.
- [x] 제외된 자리의 이전 토큰은 거부하고, 교사 복구 코드는 같은 자리를 보존하며 이전 토큰을 무효화한다.
- [x] 서버에는 토큰 해시만 저장하며 기존 세션 정리 절차로 참가자 데이터를 삭제한다.
- [x] `npm run check`와 production build를 통과한다.
- [ ] Preview의 반복 입장·재시도·4~8대 리허설을 기록한다.
- [x] 자동 검증 결과·미완료 수동 확인 범위를 `walkthrough.md`와 `BACKLOG.md`에 기록한다.
