# blast-radius — 변경 영향 범위 증명

출처: cursor/plugins의 `pstack` 중 `/blast-radius` 개념을 이 저장소에 맞게 새로 쓴 것이다(원문 복사 아님).

핵심: 그럴듯한 설명은 증거가 아니다. 변경의 안전이 기대는 사실 하나를 골라 **코드를 실행해 증명**한다. 이 스킬은 **audit** 역할이라 저장소 파일을 고치지도, 새로 만들지도 않는다. 임시 스크립트는 Claude 세션 scratchpad에만 두고, 저장소의 추적되는 `scratch/`는 쓰지 않는다.

## 증거 사다리 (약 → 강)

1. 근거 없이 주장
2. 특정 `파일:줄`을 가리킴
3. 단계별로 추론
4. 스크립트·테스트로 실행
5. 실제 앱에서 재현(`.claude/launch.json`의 `static-server`(8791)만 현재 폴더를 서빙한다. 다른 구성은 워크트리를 가리키므로 쓰지 않는다. 절차는 `docs/product/BROWSER_REGRESSION_CHECKLIST.md`)

보고서의 모든 "안전하다" 주장 옆에 현재 단계를 적는다. 3단계 이하는 "미증명"으로 표시한다.

## 절차

1. **변경 읽기**: `git status --short`로 미추적 파일까지 범위를 정하고, 미커밋 `git diff`와 변경 파일 전체를 읽는다. 이미 커밋된 변경이면 사용자가 지정한 `<base>..HEAD`를 쓴다. diff에 안 보이는 동작(공유 상태, 호출 순서)도 포함한다.
   - 완료 기준: 무엇이 바뀌었는지 두 문장으로 말할 수 있다.
2. **안전 사실 찾기**: 이 변경이 안전하려면 참이어야 하는 사실 하나를 고른다. 그게 참이면 위험 여러 개가 한꺼번에 해소된다.
   - 완료 기준: 그 사실을 한 문장으로 쓸 수 있다.
3. **grep 너머 보기**: 이 저장소의 함정만 확인한다. 환경 전반은 `project_context.md`를 본다.
   - 공용 `cooperative-mud/episode.js`·`cooperative.css`·`pacing.js`는 모든 협동 활동 편에 영향을 준다.
   - `data/mud/*.json`은 검증 스크립트가 `next` 연결, 시간 길이, 카탈로그를 가정한다.
   - localStorage 키 이름을 바꾸면 기존 학생 진행 데이터가 끊긴다.
   - 모바일·터치 입력, 좁은 화면 레이아웃.
   - 배포는 GitHub Pages(루트 `404.html`, 상대 경로)다. Vercel은 목표 경로일 뿐 현재 운영이 아니다.
4. **위험 평가**: 위험마다 가능성과 비용을 적는다. 실제 `파일:줄`만 인용하고, 없는 호출자나 API를 지어내지 않는다.
   - 완료 기준: 모든 위험에 `파일:줄` 또는 "근거 없음" 표시가 있다.
5. **실행으로 증명**: 안전 사실을 건드리는 가장 작은 검사를 돌린다. 검증은 `project_context.md`의 검증 절과 `.github/workflows/quality-gate.yml`을 따른다.
   - `scripts/02_fix_missing_next.py`는 데이터를 고치므로 실행하지 않는다.
   - 07, 10, 11, 13, 14, 17, 18은 실행하면 보고서 파일을 다시 쓴다. 돌렸다면 `git status`로 생긴 diff를 확인하고 되돌린다.
   - 완료 기준: 실행한 명령과 결과를 적었고, `git status`가 실행 전과 같다.
6. **보고**: 아래 항목을 이 순서로 쓴다.
   - 변경 요약
   - 안전 사실과 증명 결과(또는 "미증명")
   - 확인된 위험
   - 해소된 위험
   - 진짜 버그를 잡을 가장 싼 검사 하나

## 주의

- 변경이 크거나 넓으면 사용자에게 `/interrogate`를 제안한다.
- 발견한 추가 개선점은 현재 작업에 섞지 않고 BACKLOG 등록을 제안한다.
