## 1. 문서화 단계

- [x] CSS·HTML 기준으로 정적 협동 MUD와 역사 탐구 패널을 대조했다.
- [x] 팔레트가 이미 대체로 유사하고, 변수 네임스페이스·터치 높이·반응형 경계가 차이임을 기록했다.
- [x] 수업 진행 차단 증거가 없어 P2로 분류했다. P0·P1로 올리지 않았다.
- [x] 두 화면의 목적에 따른 레이아웃은 유지하고, 공통 디자인 기준만 맞추는 범위를 정했다.
- [x] 실시간 협동 앱의 테마 변경과 콘텐츠·기능 변경을 범위에서 제외했다.
- [x] 구현 파일을 수정하지 않고 계획·체크리스트만 작성했다.

## 2. P2-1 — 기준 화면과 공통 토큰 결정

- [ ] 320×568, 390×844, 820×1180, 1180×820, 1366×768 화면에서 현 상태를 확인한다.
- [ ] 포털 공통 색상·글꼴을 기준으로 삼고, 정적 협동 MUD 단독 실행 때도 같은 값이 적용되는 변수 방식을 정한다.
- [ ] 선택 상태의 초록색, 오류 상태의 색 등 상태 전달 색은 별도 의미 토큰으로 유지한다.
- [ ] 공통 토큰 적용이 CSS 의존성이나 기존 화면 로드를 깨지 않는지 확인한다.

**완료 조건:** 협동 활동과 역사 탐구에서 배경·본문·강조·조작 색을 같은 기준표로 설명할 수 있고, 독립 페이지에서도 스타일이 정상 표시된다.

## 3. P2-2 — 터치 조작과 상태 표현

- [ ] 주요 선택·진행 버튼의 최소 높이를 48px로 맞춘다. 예외는 공간·내용 근거를 기록한다.
- [ ] 주요 버튼의 모서리·테두리 두께·글자 굵기를 맞춘다.
- [ ] 선택됨·비활성·오류·키보드 포커스가 색상 하나에만 의존하지 않게 확인한다.
- [ ] 터치 후 선택 상태가 즉시 보이고, 중복 탭이나 비활성 버튼이 오작동하지 않는지 확인한다.

**완료 조건:** 손가락 조작이 가능하고, 현재 상태를 색상 외의 테두리·문구·포커스 표시로도 구별할 수 있다.

## 4. P2-3 — 모바일·태블릿 반응형

- [ ] 600px와 620px 주변 폭을 대조해 모바일 전환 기준을 정한다.
- [ ] 정적 협동 활동은 헤더·단계·선택 카드가 작은 폭에서 한 열로 이어지는지 확인한다.
- [ ] 역사 탐구는 왼쪽 이야기·선택지와 오른쪽 탐구 도구가 작은 폭에서 읽기 순서에 맞게 쌓이는지 확인한다.
- [ ] 역사 탐구 패널 내부 스크롤과 하단 고정 제출 버튼이 함께 작동하는지 확인한다.
- [ ] 지정 뷰포트에서 가로 넘침, 겹침, 잘린 글자·버튼이 없는지 확인한다.

**완료 조건:** 지정 뷰포트에서 핵심 안내와 다음 행동이 가려지지 않으며 두 화면의 본래 진행 흐름이 유지된다.
