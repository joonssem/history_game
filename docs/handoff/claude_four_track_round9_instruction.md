## §0-2 확정 데이터 형식 (모든 창이 이 모양을 쓴다)

```json
{
  "version": 1,
  "note": "정규 32편만. 심화·협동·확장 활동은 넣지 않는다(D-036).",
  "entries": [
    {
      "order": 1,
      "mudId": "regular_paleolithic",
      "unitId": 1,
      "lessonNumbers": [2],
      "eraLabel": "구석기",
      "eraRange": "약 70만 년 전~",
      "shortTitle": "주먹도끼"
    }
  ]
}
```

- `order`는 1부터 32까지 빈틈없이 이어진다. **단원을 넘어 계속된다.**
- `eraLabel`은 띠에 보이는 시대명이다(예: 구석기, 신석기, 청동기, 고조선, 삼국, 통일신라, 발해, 고려, 조선 전기, 조선 후기, 개항기, 일제강점기, 광복·대한민국).
- `eraRange`는 띠 아래에 작게 보이는 연대다. **대조실이 검증한 표기만 쓴다.**
- `shortTitle`은 좁은 화면에서 쓰는 6자 안팎의 짧은 이름이다.

## §1 관문 설계실 — `data/lesson_track.json` 작성

- `data/mud/_index.json`에서 `tier`가 `regular`인 32편을 뽑아 `unitId`·`lessonNumbers` 순으로 정렬한다.
- **같은 차시에 두 편이 있는 경우의 순서를 정하고 이유를 적는다.** 현재 2단원 7차시에 `regular_joseon_diplomacy`와 `regular_myeongnyang`이 있다.
- `eraLabel`을 붙인다. **띠에서 같은 시대가 연달아 나오면 학생이 한 시대로 묶어 읽게 된다.** 시대 구분이 교과서 흐름과 어긋나지 않게 한다.
- `eraRange`는 **초안만** 적고, 대조실이 검증한 값으로 2단계에서 맞춘다. 초안에는 `"eraRangeDraft": true`를 함께 둔다.
- `shortTitle`은 학생이 보고 어느 편인지 알 수 있어야 한다. "1차시", "MUD 3" 같은 번호식 이름은 쓰지 않는다.
- 산출물에 32개가 다 있는지, `order`가 1~32 연속인지 직접 확인한다.

## §2 대조실 — 시대 구분과 연대 표기 검증

- 산출물: `docs/audits/lesson_track_era_review.md`
- **연대표는 화면에 연도를 직접 보여 준다.** 틀리면 학생이 틀린 연도를 외운다. 라운드 4~8과 같은 기준으로 공식 출처와 대조한다.
- 검증할 것
  1. 각 `eraLabel`의 연대 범위 표기. 예: 삼국(기원전 57~668), 통일신라(676~936), 고려(918~1392)
  2. 시대 경계가 겹치거나 비는 곳. 예를 들어 발해(698~926)와 통일신라는 같은 시기이므로 **띠에서 앞뒤로 놓는 것이 맞는지** 판단해 적는다.
  3. "약 70만 년 전" 같은 표현. 라운드 5에서 전곡리 연대를 "수십만 년"으로 낮춘 판단과 어긋나지 않게 한다.
  4. 선사 시대 구분(구석기·신석기·청동기)의 연대 표기를 원문이 어디까지 말하는지
- 확정할 수 없는 연대는 **범위를 넓히거나 연도를 빼는 쪽**을 제안한다. 띠에는 연도가 없어도 된다.
- `data/lesson_track.json`은 직접 고치지 않는다. 수정 제안 표만 남긴다.

## §3 연결 공방 — 화면·문구 사양서

- 산출물: `docs/plans/implementation_plan_lesson_track_ui.md`
- 정할 것
  1. **띠의 위치와 동작**: 어느 화면에 나오는가(MUD 완료 화면, 진도표, MUD 진행 중 중 어디). 스크롤·접힘 동작.
  2. **현재 위치 표시 방법**과 상태 3종의 구분: 완료한 편 / 지금 편 / 아직 안 한 편. 색만으로 구분하지 않는다(색각 이상 고려).
  3. **문구**: 앞뒤 이동 버튼 문구, 띠의 제목, 아직 안 한 편을 눌렀을 때의 안내.
  4. **태블릿 기준**: 1180×820에서 32칸이 어떻게 보이는가. 터치 목표 크기(최소 44px), 좁은 화면(390px)에서의 동작.
  5. **하지 않을 것**: 자유 이동 게임, 애니메이션 과다, 진도 강제.
- 코드는 쓰지 않는다. 조작대가 이 문서를 보고 구현한다.

## §4 조작대 — 구현과 검증 스크립트

1. **`scripts/16_validate_lesson_track.js`**(먼저 만든다)
   - `data/lesson_track.json`이 위 형식과 맞는가
   - 32개가 모두 `_index.json`의 `tier: regular`와 일대일로 대응하는가(빠짐·중복·유령 id 없음)
   - `order` 1~32 연속, `unitId`·`lessonNumbers` 오름차순
   - 심화·협동 편이 섞여 있지 않은가
   - 대상 파일이 없으면 건너뛰고 통과한다(관문 설계실과 병렬 작업)
2. **`js/lessonTrack.js`**: 띠를 그리고 현재 위치를 표시하며, 누르면 그 편으로 이동한다. 진행 상태는 기존 진도 저장 방식을 그대로 읽는다. **새 저장 키를 만들지 않는다.**
3. **`js/mudEngine.js` 완료 화면**에 앞뒤 차시 연결을 넣는다. 진도표로 가는 기존 버튼은 그대로 둔다.
4. `css/style.css`에 스타일을 **덧붙이고**, `index.html`에 새 스크립트와 캐시버스터를 넣는다.
5. 연결 공방 사양서가 아직 없으면, 기본 동작으로 먼저 만들고 사양서가 나온 뒤 맞춘다.
6. **브라우저에서 직접 확인한다.** 1180×820과 390×844 두 크기에서 띠가 보이는지, 32칸이 넘치지 않는지, 완료 화면의 앞뒤 이동이 실제로 동작하는지 확인하고 결과를 보고에 적는다.
