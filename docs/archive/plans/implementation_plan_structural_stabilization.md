# 전문가 통합 진단 기반 MUD 수정보완 계획서

> 대상: `history_game` 전체 · 관점: 초등 역사 교육, 인터랙티브 구조, UI/UX  
> 상태: 사용자 환경 확인 반영 — 제품 코드는 아직 수정하지 않음  
> 확인 환경: 2022 개정 교육과정 · 학생 개인 활동 · iPad 10세대 · 수업 마무리 활동 · 교사용 대시보드 제외

## 1. 종합 판단

이 프로젝트의 강점은 48차시를 역할극·선택·연대기·시뮬레이터·유물 수집으로 연결한 범위, 일관된 시각 정체성, 데이터 기반 MUD 확장 기반이다. 최근 선택지 순서 무작위화와 구석기 분기 확장도 학생의 위치 암기와 지나치게 짧은 체험을 줄이는 방향으로 유효했다.

그러나 반복되는 `NaN`, 설명과 화면 불일치, 배경 누락, 구형/신형 활동 충돌은 개별 JSON 문제가 아니라 다음 구조적 결함의 증상이다.

1. 시나리오 데이터, 활동 상태, 렌더링의 계약이 없다.
2. `mudEngine.js`, `mudSimulators.js`, JSON의 `buttonsHtml`이 같은 행동을 서로 다르게 제어한다.
3. 검증이 JSON 문법 중심이며 실제 클릭 순서·표시 결과·접근성을 검사하지 않는다.
4. 역사 내용의 출처·불확실성·교육과정 버전이 데이터에 기록되지 않는다.
5. README의 “100%”, “완벽 지원”을 뒷받침할 측정 기준과 배포 검증이 없다.

따라서 **콘텐츠 전면 확장 전에 엔진 계약과 검증 체계를 안정화**해야 한다. 단, 구조 작업만 장기화하지 않도록 구석기·고조선·근현대 대표 MUD 3종을 수직 파일럿으로 함께 검증한다.

## 2. 확인된 기준선

- 전체 MUD JSON 32종: Regular 28종, Deep-dive 4종
- Regular 단계 185개: 본 경로 99개, 실패·보충 분기 86개
- 필수 활동 선언 25개, interaction 선언 단계 27개
- 구형 시뮬레이터 분기 약 113개
- 130자 미만의 짧은 실패 분기 42개
- 핵심 JavaScript 약 3,100줄
  - `mudSimulators.js` 약 939줄
  - `mudEngine.js` 약 591줄
- `.github/workflows`, 정식 브라우저 테스트, 접근성 테스트 없음
- `_index.json`에 단원 내 차시 번호와 과거 전체 번호가 혼재하고 `app.js`의 대형 fallback에 의존
- 라이브 불 피우기 활동에서 오답 후 `NaN/3`, `NaN%` 재현

단계 수 자체는 적지 않다. 활동 시간이 짧은 핵심 원인은 단계의 사고 깊이, 실패 분기의 의미, 시각 단서의 교육적 기능이 약한 데 있다.

## 3. 전문가 평가

### 3.1 초등 역사 교육

장점:

- 역사 인물·집단의 역할을 맡아 선택하므로 수동 읽기보다 몰입 가능성이 높다.
- 연대기가 선택 결과와 사건 순서를 반복해서 보여준다.
- 구석기 주거·불·도구 같은 생활사는 초등학생의 구체적 사고에 적합하다.
- 국보 도감과 MUD의 연결은 반복 학습 동기를 만들 수 있다.
- 선택지 번호와 무작위 순서는 첫 번째 버튼 찍기 습관을 줄인다.

고칠 점:

- “얼음검”, “나무젓가락”, “잔혹한 독재”처럼 터무니없는 오답은 역사적 추론을 요구하지 않는다.
- 많은 실패 분기가 짧은 설명 후 정답 경로로 복귀해 의미 있는 분기로 느껴지지 않는다.
- 한 번의 선택이 복합적인 역사 변화를 결정하는 표현은 인과를 지나치게 단순화한다.
- 전쟁·노동·신분제·식민지 역할극은 가해 행동을 직접 보상하지 않도록 윤리적 거리 두기와 다중 관점이 필요하다.
- 사실·전승·해석이 섞인 표현이 있다.
  - 단군 기원전 2333년을 확정 사실처럼 제시
  - 전곡리 주먹도끼를 동아시아 최초로 단정
  - 고조선 8조법과 화폐를 자료보다 강하게 추론
  - 석굴암 지하수 습도 조절설 및 `1:√2` 황금비 표현
  - 여러 “세계 최초” 주장에 기준·출처·한정어 부족
- 2026년 초등 5·6학년에 적용되는 2022 개정 교육과정과 현재 2015 체계형 48차시의 관계가 불명확하다.

필수 학습 고리:

`상황 파악 → 자료/단서 관찰 → 선택과 근거 → 결과 비교 → 역사적 의미 정리`

### 3.2 인터랙티브 구조

장점:

- `interaction.type` 기반의 데이터 확장 방향이 이미 존재한다.
- 활동 완료 전 다음 단계 잠금, 진행 상태, 피드백 영역이 마련되어 있다.
- 정적·캔버스 기반이라 가볍게 배포할 수 있다.

고칠 점:

- 구형 전역 상태와 신형 `interactionState` 혼재가 실제 `NaN` 오류를 만든다.
- 시뮬레이터가 상태 계산과 그리기를 함께 맡아 재렌더링 때 상태와 화면이 어긋날 수 있다.
- JSON의 실행 가능한 `buttonsHtml`과 인라인 `onclick`이 데이터와 코드를 결합한다.
- interaction 유형별 필수 필드, 완료·재시도·리셋 규칙이 없다.

목표 구조:

```text
MUD JSON(검증 가능한 설정)
  → MudEngine(상태의 단일 소유자)
  → Interaction Registry(init/handle/isComplete/getFeedback)
  → Renderer(상태를 읽어 화면만 그림)
```

렌더러는 상태를 변경하지 않고, 클릭은 문자열 코드가 아닌 action 객체로 전달하며, 모든 캔버스 활동에는 버튼/키보드 대체 경로를 둔다.

### 3.3 UI/UX·접근성

장점:

- 전통색 계열, 카드형 레이아웃, 역할·장소·연대기의 정보 위계가 일관적이다.
- 데스크톱에서 본문과 활동을 나란히 비교하기 좋다.
- 활동 완료 전 진행을 막아 필수 활동 건너뛰기를 방지한다.

고칠 점:

- CSS에 반응형 `@media`가 없어 모바일·태블릿 “완벽 지원”을 검증할 수 없다.
- 전역 `user-select: none`은 읽기·복사·보조 기능에 불리하다.
- `:focus-visible`, 모달 포커스 관리, Esc 닫기, `aria-live`가 없다.
- 캔버스는 키보드와 스크린리더로 수행하기 어렵다.
- 시뮬레이터 안내·피드백 약 `0.75rem`은 학생과 태블릿 환경에 작다.
- 고정 높이 캔버스는 작은 화면에서 잘림·왜곡 위험이 있다.
- 포털의 긴 차시 카드 목록은 탐색 부담이 크다.
- 고조선 원형 라벨 화면은 위치를 누르게 하지만 역사 지도 맥락은 전달하지 못한다.

목표 기준:

- 터치 목표 44×44px 이상, 본문 16px 이상, 핵심 안내 14–16px 이상
- 320/768/1024/1280px에서 가로 스크롤과 정보 손실 없음
- 모든 활동에 키보드 초점·조작·완료 피드백 제공
- 색만으로 상태를 구분하지 않음
- 모달 포커스 이동·복귀 및 애니메이션 감소 설정 지원

### 3.4 GitHub·저장소·배포

장점:

- 정적 웹앱이라 GitHub Pages 운영이 단순하다.
- MUD가 JSON으로 분리되어 콘텐츠 확장 기반이 있다.
- 계획서, `walkthrough.md`, 검증 스크립트로 인수인계 흔적이 남아 있다.

고칠 점:

- CI가 없어 잘못된 데이터와 코드가 푸시 전에 차단되지 않는다.
- README 목록·수치가 수동 집계에 의존한다.
- MIT 표기와 달리 `LICENSE` 파일이 없다.
- `extracted_script.js`, `extracted_style.css`의 용도와 원본 관계가 불명확하다.
- 화면에 릴리스/데이터 버전이 없어 캐시된 페이지를 최신 배포로 오인할 수 있다.
- 대형 단일 JS와 전역 객체가 변경 영향 범위를 넓힌다.

## 4. 우선순위와 기존 계획 비교

## 5. 단계별 계획

### Decision Gate 0 — 교육과정과 범위 확정

- A: 2015 개정 5학년 2학기 유지
- **B: 2022 개정 5·6학년 체계로 전환 — 사용자 선택**
- C: 기존 콘텐츠를 보존하고 2022 교육과정 매핑을 별도 제공

제품의 공식 기준은 **2022 개정 교육과정**으로 확정한다. 기존 2015 체계형 콘텐츠는 즉시 삭제하지 않고 전수 매핑 결과에 따라 재배치·수정·보관하며, 기존 48차시 번호를 그대로 새 교육과정 번호로 간주하지 않는다.

산출물: `curriculumVersion`, 학년·단원·차시·성취기준 규칙, 48차시 번호 기준, README 지원 범위.

확인된 실제 사용 맥락:

- 기기: 학생 1인당 iPad 10세대
- 형태: 학생 개인 조작
- 수업 위치: 본 수업의 마무리 활동
- 목표 시간: 개인이 설명을 읽고 활동을 완주하는 5–10분

따라서 파일럿은 iPad Safari 세로·가로 화면을 최우선으로 검증한다. 별도 교사 설명 없이 목표·조작·완료 의미를 이해할 수 있어야 하며, 새로운 내용을 길게 가르치기보다 본시에서 배운 개념을 적용·회상·정리하도록 설계한다.

### Phase 1 — 버그 봉쇄와 배포 식별

- 불 피우기 상태 단일화 및 오답 후 정상 재시도
- 모든 진행률에 `NaN`, 음수, 100% 초과 방어
- 제목·설명·대상·렌더러 유형 일치 검사
- 구석기·신석기·고조선 클릭 순서 스모크 테스트
- 앱 버전/커밋 또는 데이터 버전 표시와 캐시 갱신 절차

완료 기준: `undefined`, `NaN`, 빈 캔버스 0건; 새 세션·재시도·다음 단계 정상.

### Phase 2 — MUD/Interaction 계약

- JSON Schema 또는 동등 규칙 도입
- 공통 필드와 interaction 유형별 필드 정의
- 단계/차시/interaction ID 고유성 보장
- `_index.json`을 시나리오 탐색의 단일 출처로 정리
- `app.js`의 파일명 fallback 점진 제거
- JSON의 실행 HTML/`onclick` 제거 마이그레이션
- 상태 생성·갱신·완료·리셋 수명주기 정의

완료 기준: 잘못된 데이터가 브라우저 실행 전에 실패하고 재렌더링이 상태를 바꾸지 않음.

### Phase 3 — Registry·Renderer 분리

- 구형 활동을 adapter로 격리
- 유형별 handler/renderer를 registry에 등록
- 상태 전이를 테스트 가능한 함수로 분리
- 배경·라벨·목표·피드백을 데이터 계약에 포함
- 반응형 좌표계와 버튼 대체 조작 구현

완료 기준: 새 interaction 추가 시 엔진 본문 조건문을 수정하지 않고, 화면 텍스트와 대상 목록을 자동 비교.

### Phase 4 — 자동 검증과 GitHub 게이트

- JS 문법, JSON, 스키마, 참조 무결성 검사
- 다음/복귀 단계, 유물, interaction 참조 검사
- README MUD 목록을 한 원본에서 생성
- 대표 3종 브라우저 E2E와 접근성 검사
- GitHub Actions에서 PR/푸시마다 실행
- `LICENSE`, 저장소 구조, 배포·롤백 문서 보완
- 추출 산출물의 제거 또는 생성물 디렉터리 격리

완료 기준: 실패 데이터가 main 전에 차단되고 Pages 배포 후 스모크 테스트 통과.

### Phase 5 — 반응형·접근성

- 1열/2열 breakpoint와 비율 기반 캔버스
- 초점 표시, 키보드 조작, `aria-live`, 모달 포커스 관리
- 글자·터치 목표·색 대비 개선
- `user-select: none`을 드래그 활동으로 제한
- `prefers-reduced-motion` 대응
- 차시 목록 접기·검색·진행 필터
- iPad 10세대 Safari 세로·가로 실기기 테스트
- 터치 조작과 페이지 스크롤 충돌 방지
- 수업 마무리용 ‘오늘 배운 내용 정리’ 결과 화면

완료 기준: 키보드만으로 대표 MUD 완주, 320–1280px 정보 누락 없음, 핵심 접근성 오류 0건.

### Gate A — 구조 안정화 승인

대표 3종 테스트, 스키마와 CI, 교육과정 기준, 출처 규칙, 학생 파일럿의 치명적 중단 0건을 모두 충족한 뒤 전체 확장을 승인한다.

### Phase 6 — 역사 목록과 출처 체계

- MUD 32종 목록을 실제 파일에서 생성
- 핵심 개념·학습 목표·예상 시간·교육과정 연결 기록
- 사실 문장에 출처 메타데이터 연결
- `fact`, `tradition`, `interpretation`, `controversy` 구분
- 우리역사넷 우선, 박물관·문화유산 기관 자료 보완
- “최초/유일/완벽” 표현 전수 점검

완료 기준: 출처 없는 핵심 주장 및 학설·전승의 사실 단정 0건.

### Phase 7 — 분기와 서사 재설계

- 터무니없는 오답을 동시대에 가능한 대안으로 교체
- 화면 자료를 관찰해야 답할 수 있도록 단서 연결
- 실패 분기를 결과 비교·재판단으로 전환
- 단일 영웅·단일 원인 서사 완화
- 전쟁·식민지·신분제에 다중 관점과 윤리적 거리 두기 적용

5–10분 권장 구성:

- 도입 45–60초
- 자료 관찰 60–90초
- 선택·결과 비교 60–90초
- 상호작용 90–150초
- 분기·재판단 60–120초
- 정리 45–60초

### Phase 8 — 대표 시뮬레이터 파일럿

1. 구석기: 주거 판단 → 불 피우기 → 도구 제작
2. 고조선: 전승/사료 구분 → 위치·영역 → 8조법 추론
3. 근현대: 사료·사진·지도 비교 → 여러 행위자의 선택과 결과

활동마다 학습 목표, 시각 단서, 학생 행동, 판단 기준, 재시도, 대체 조작, 역사적 의미, 예상 시간을 기록한다.

### Phase 9 — 학생 검증과 전체 확장

- 5학년 3–5명 관찰 테스트, 교사 2명 이상 검토
- 완주 시간, 도움 요청, 오클릭, 중단 지점, 설명 회상 수집
- 파일럿을 통과한 유형만 전체에 확대
- 5–7종 단위로 배포하고 회귀 테스트

완료 기준: 중앙 완주 5–10분, 치명적 중단 0건, 학생 80% 이상 핵심 목표 설명, 중대한 사실 오류 0건.

## 9. 교사용 대시보드 범위 결정

교사용 대시보드는 학생의 개인 활동 결과를 교사가 한 화면에서 확인하는 별도 기능이다. 접속 학생 수, MUD 완료 여부, 소요 시간, 재시도 경향, 마지막 정리 문항 등을 반별로 볼 수 있다.

현재 앱은 GitHub Pages의 정적 웹앱이므로 학생 기기의 기록을 중앙으로 받을 서버·데이터베이스가 없다. 대시보드를 추가하려면 수업 코드, 결과 전송 API, 데이터베이스, 교사 인증, 보존·삭제 정책이 필요하다.

| 단계 | 제공 기능 | 장점 | 부담·위험 |
|---|---|---|---|
| D0 로컬형 | 학생 화면의 완료 요약·결과 카드 | 서버·개인정보 없음 | 교사가 전체 결과를 자동 집계하지 못함 |
| D1 익명 수업형 | 수업 코드와 익명 번호별 완료·시간·정리 답 | 마무리 활동에 필요한 최소 집계 | 소규모 백엔드와 교사 화면 필요 |
| D2 계정형 | 이름·누적 이력·반별 통계·성취 추적 | 장기적인 개별 피드백 | 로그인·개인정보·보안·운영 부담 큼 |

이번 개발 범위에서는 **교사용 대시보드를 만들지 않는다**. 학생 활동 기록은 현재처럼 해당 기기 안에서만 사용하며 외부 서버로 전송하지 않는다. 학생 식별, 수업 코드, 교사 인증, 반별 집계, 원격 데이터베이스도 도입하지 않는다.

D0의 학생용 완료 요약은 교사용 대시보드가 아니라 학습 정리 UI이므로 유지할 수 있다. 학생이 방금 수행한 MUD의 핵심 개념과 완료 상태를 자신의 화면에서 확인하는 수준으로 제한한다.

아래 D1 흐름은 향후 참고 사항이며 현재 구현·설계·테스트 범위에서 제외한다.

D1 최소 흐름:

`교사가 수업 코드 생성 → 학생이 코드 입력 → MUD 수행 → 익명 결과 전송 → 교사가 완료 현황 확인 → 보존 기간 후 자동 삭제`

## 10. 확정된 데이터 원칙

- 외부 서버로 학생 결과를 전송하지 않는다.
- 학생 이름, 학번, 계정 등 개인 식별 정보를 수집하지 않는다.
- 교사용 집계·평가 화면을 만들지 않는다.
- MUD 진행 상태는 학생 기기 안에서만 처리한다.
- 완료 화면은 학생의 회상·정리를 위한 UI로만 사용한다.
- 향후 대시보드가 필요해지면 별도 계획과 개인정보·보안 검토를 거쳐 승인받는다.

## 11. 승인 제안

승인 후 우선 **Phase 1–4와 대표 MUD 3종의 구조 파일럿**만 실행한다. Gate A 결과를 보고 전체 확장을 다시 승인받는다. 이 방식이 반복 버그를 줄이면서 구조 개선의 실제 교육 효과를 가장 빨리 확인한다.
