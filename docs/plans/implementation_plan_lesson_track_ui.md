# 구현 사양서 — 정규 32편 연대표 띠 UI (Track3 라운드9 §3)

- 작성: Claude Sonnet 5 (연결 공방 / activity-loop, 2026-09-18)
- 근거: `docs/handoff/claude_four_track_round9_instruction.md` §0-2(확정 데이터 형식), §3. 결정: `DECISIONS.md` D-036.
- 이 문서는 **사양서다. 코드를 쓰지 않는다.** 조작대(`js/lessonTrack.js`, `js/mudEngine.js`, `css/style.css`, `index.html`)가 이 문서를 보고 구현한다.
- 데이터 소스: `data/lesson_track.json`(관문 설계실, §0-2 형식 그대로 — `order`/`mudId`/`unitId`/`lessonNumbers`/`eraLabel`/`eraRange`/`shortTitle`). 이 문서는 그 파일이 아직 나오기 전에 작성됐으므로, 필드 이름은 확정 형식을 그대로 참조만 한다.

## 1. 띠의 위치와 동작

### 1-1. 두 곳에 나온다 — 전체 띠(포털)와 앞뒤 이동(완료 화면)

같은 정보를 두 가지 크기로 보여준다. 하나로 합치면 완료 화면이 너무 무거워지고, 포털 화면에 앞뒤 이동만 두면 "내가 지금 전체 32편 중 어디에 있는지"를 알 수 없다.

| 화면 | 보여줄 것 | 이유 |
|---|---|---|
| **포털(진도표) 화면** | 32칸 전체 띠 | 학생이 "얼마나 남았는지" 한눈에 보는 곳은 여기뿐이다. 단원 탭을 넘나드는 유일한 화면이기도 하다. |
| **MUD 완료 화면**(`renderFinalReflection`) | 이전 차시·다음 차시 링크 2개만 | 방금 끝낸 차시 바로 다음 행동을 안내하는 자리다. 32칸 전체를 다시 그리면 화면이 무거워지고, 완료 축하 톤과 안 어울린다. |
| MUD 진행 중 화면 | **넣지 않는다** | 결단을 내리는 도중에 진도 정보를 보여주면 주의가 흩어진다. D-036의 "진도 강제 금지"와도 맞지 않는다 — 지금 하는 결정에만 집중하게 둔다. |

### 1-2. 포털 화면 배치

`index.html`의 단원 탭 네비게이션(`.unit-nav`) **바로 아래, 차시별 학습 카드 그리드(`#curriculum-container`) 위**에 둔다.

- 이유: 단원 탭으로 1·2·3단원 어디를 보고 있어도 띠는 항상 32편 **전체**를 보여준다(단원 탭에 따라 필터링하지 않는다) — "지금 이 단원"이 아니라 "전체 여정에서 지금 어디"를 보여주는 것이 이 띠의 역할이기 때문이다.
- 스크롤 동작: **페이지 자체는 그대로 세로 스크롤**된다. 띠는 접거나 펼치는 아코디언을 두지 않는다(§5 "애니메이션 과다" 금지와 같은 이유 — 상태를 숨겼다 보여주는 전환 자체가 불필요한 움직임이다). 항상 펼쳐진 상태로 고정 높이를 차지한다.
- **최초 진입 시 자동 스크롤 1회**: 포털 화면을 열면(또는 단원 탭을 처음 클릭하면) 페이지 세로 스크롤을 "지금 차시" 행이 화면에 보이는 위치까지 즉시 이동시킨다(`scrollIntoView({behavior:'auto', block:'nearest'})` 수준 — 부드러운 애니메이션 스크롤이 아니라 즉시 이동). 학생이 32칸을 훑어 자기 위치를 찾아야 하는 수고를 없앤다. 이후 사용자가 직접 스크롤하면 더 개입하지 않는다.

### 1-3. 완료 화면 배치

`renderFinalReflection()` 안, 기존 "진도표로 나가기" 버튼 **위쪽**에 한 줄로 둔다.

```
[◀ 이전 차시로]   [다음 차시로 ▶]
```

- 이전/다음은 `data/lesson_track.json`의 `order` 순서를 그대로 따른다(같은 차시 두 편이 있는 2단원 7차시는 관문 설계실이 정한 순서를 그대로 신뢰한다 — 이 문서에서 순서를 다시 판단하지 않는다).
- `order`가 1(맨 처음) 또는 32(맨 마지막)인 경우 해당 방향 버튼은 **숨긴다**(비활성화 회색 버튼이 아니라 아예 렌더링하지 않는다 — 누를 수 없는 버튼을 보여주는 것보다 없는 게 명확하다).
- 기존 "🚪 전체 진도표로 나가기" 버튼은 그대로 둔다(§4 지시 "진도표로 가는 기존 버튼은 그대로 둔다").

## 2. 상태 3종 구분 — 색만으로 구분하지 않는다

세 상태: **완료**(completed) / **지금**(current) / **아직**(upcoming). 아래 3개 채널을 겹쳐 쓴다 — 색은 그중 하나일 뿐, 색을 빼도 구분되게 한다(색각 이상 고려).

| 상태 | 아이콘(칸 안, 좌상단 작게) | 테두리 | 라벨(칸 아래 8~9px 텍스트) | 색(보조) |
|---|---|---|---|---|
| 완료 | ✓ | 실선 1px | "완료" | 옅은 초록 배경 |
| 지금 | 📍 | **점선 2px**(굵고 다른 선 종류) | "지금" | 옅은 주황 배경 |
| 아직 | (없음) | 실선 1px, 옅은 회색 | (라벨 없음 — 비워 둠) | 배경 없음(카드 기본색) |

- "지금"은 **테두리를 실선이 아니라 점선으로** 바꿔 완료·아직과 확실히 구분한다(굵기만 다른 건 흑백 인쇄·저시력에서 놓치기 쉽다 — 선 종류 자체를 바꾼다).
- 완료 칸의 ✓ 아이콘은 항상 표시하고, "지금" 칸의 📍도 항상 표시한다 — 아이콘 유무 자체가 첫 번째 구분 채널이라 색 없이도 완료/지금/아직 셋을 구분할 수 있다.
- 칸 안 텍스트(시대명·짧은 제목)는 세 상태 모두 같은 명도로 둔다 — "아직"이라고 글자를 흐리게 하면(예: 옅은 회색 글자) 저시력 학생에게 안 보일 위험이 있고, D-036이 금지한 "잠금"처럼 읽힐 수 있다. 안 읽었다는 사실은 아이콘 없음으로만 표현한다.

### 2-1. "지금"의 정의

`lesson_track.json`의 `order` 순서에서, **완료하지 않은 것 중 가장 앞선 차시**를 "지금"으로 표시한다. (완료 목록은 조작대가 §4-2에서 정하는 "기존 진도 저장 방식"을 그대로 읽는다 — 이 문서는 새 저장 키를 요구하지 않는다. 참고로 이 저장소의 기존 진도 신호는 `js/encyclopedia.js`의 `unlockedArtifacts`뿐이다 — 정규 MUD는 클리어 시 유물 1개를 지급하므로, `lesson_track.json`의 `mudId` → 해당 MUD의 보상 `artifactId` → `unlockedArtifacts` 포함 여부로 완료를 판정할 수 있다. 이 매핑을 새 필드로 만들지, `data/mud/<mudId>.json`의 `rewards[]`를 그때그때 읽을지는 조작대가 정한다.)

- 32편을 모두 끝낸 학생에게는 "지금" 칸이 없다 — 이 경우 마지막 칸(32번)에 완료 표시만 하고 "지금" 표시는 아예 만들지 않는다. "축하합니다, 모두 완료했어요" 같은 별도 배너를 새로 만들지 않는다(범위 밖).

## 3. 문구

| 위치 | 문구 |
|---|---|
| 띠 제목(포털 화면, 띠 맨 위) | `🧭 나의 역사 여정` |
| 띠 아래 안내 캡션(항상 표시, 팝업 아님) | `완료한 차시는 다시 볼 수 있고, 아직 하지 않은 차시를 눌러 바로 시작할 수 있어요.` |
| 완료 화면 — 이전 이동 버튼 | `◀ 이전 차시로` |
| 완료 화면 — 다음 이동 버튼 | `다음 차시로 ▶` |
| "지금" 칸의 라벨(칸 아래) | `지금` |
| 완료 칸의 라벨(칸 아래) | `완료` |
| "아직" 칸의 라벨 | (없음 — 빈 문자열) |

- **팝업·모달 안내를 두지 않는다.** "아직 안 한 편을 눌렀을 때의 안내"는 클릭 시점의 별도 확인창이 아니라, 위 캡션 한 줄로 **미리** 알려 둔다 — 눌렀을 때는 곧바로 그 차시의 MUD가 시작된다(기존 커리큘럼 카드에서 아무 차시나 눌러 시작할 수 있는 것과 같은 동작). 클릭마다 "정말 시작할까요?" 확인을 넣지 않는다 — 이미 이 앱의 다른 어떤 진입점도 그렇게 묻지 않는다.
- 완료한 칸을 누르면 **그 MUD를 처음부터 다시 시작**한다(기존 커리큘럼 카드의 "다시 플레이" 동작과 같다 — 새 동작을 만들지 않는다).

## 4. 태블릿·모바일 레이아웃

### 4-1. 단원별 3줄 레이아웃 (한 줄 32칸이 아니다)

32칸을 한 줄에 다 넣지 않는다. **단원별로 한 줄씩, 총 3줄**로 나눈다(1단원 20칸 / 2단원 14칸 / 3단원 14칸). 이유:

1. 이미 있는 단원 구분과 시각적으로 맞아떨어진다 — 학생이 이미 아는 "1·2·3단원" 개념 위에 얹는 것이라 새로 배울 게 없다.
2. 32칸을 한 줄로 이어 붙이면 1180px 폭에서도 칸 하나가 44px 미만으로 줄어든다(32칸 + 여백 31개를 1180px에 맞추면 칸당 30px대) — 터치 목표 최소 44px를 지키려면 줄을 나눠야 한다.
3. §1의 "시대가 연달아 나오면 한 시대로 묶여 읽힌다"는 관문 설계실의 우려와도 맞다 — 단원 경계 자체가 이미 자연스러운 끊어 읽기 지점이다.

각 줄 앞에 라벨을 둔다: `1단원`, `2단원`, `3단원`(기존 단원 탭 문구를 그대로 재사용하지 않고 짧게 — 탭에는 이미 "📜 1단원. 옛 사람들의 삶과 문화 (20차시)"처럼 긴 문구가 있으므로, 띠에서는 축약형만 쓴다).

### 4-2. 1180×820 (아이패드 가로) — 줄바꿈, 스크롤 없음

- 콘텐츠 폭 약 1120px(좌우 여백 제외) 기준, 칸 폭 약 62px + 간격 6px로 계산하면 한 줄에 약 16칸이 들어간다.
- 1단원(20칸)은 **두 줄로 자동 줄바꿈**(`flex-wrap: wrap`), 2·3단원(각 14칸)은 한 줄에 들어간다.
- **가로 스크롤을 쓰지 않는다** — `flex-wrap: wrap`으로 필요하면 그 단원 줄만 두 줄이 된다. 가로 스크롤 막대와 스냅 애니메이션을 새로 만들지 않는 것이 §5 "애니메이션 과다 금지"에 맞는다.
- 칸 크기: 최소 44×44px(터치 목표), 권장 60×52px(가로가 조금 더 긴 직사각형 — 안에 시대명 2~3자 + 짧은 제목이 들어가야 하므로). 칸 사이 간격 6px 이상.

### 4-3. 390px (휴대폰) — 단원별 가로 스크롤

390px에서는 한 줄에 6~7칸(칸 44px + 간격 4px 기준)밖에 못 넣는다. 줄바꿈으로 3단원 모두 펼치면 세로로 너무 길어진다(1단원만 3~4줄).

- 390px 이하에서는 **단원별 줄을 각각 독립적으로 가로 스크롤**시킨다(`overflow-x: auto`, 줄바꿈 없음). 세로 스크롤(페이지 전체)과 가로 스크롤(각 단원 줄)이 겹치지 않게, 각 줄의 가로 스크롤 영역은 명확한 경계(옅은 배경 박스)로 감싼다.
- 각 줄 오른쪽 끝에 살짝 잘린 칸이 보이게 두어(다음 칸이 있다는 시각적 힌트) 스크롤 가능함을 알린다 — 별도 화살표 아이콘이나 "더보기" 문구를 추가하지 않는다(§5 "애니메이션 과다"까지는 아니지만, 잘린 칸만으로 충분한 최소한의 신호로 본다).
- "지금" 칸이 있는 줄은 그 칸이 보이는 위치까지 가로 스크롤을 1-1의 세로 자동 스크롤과 같은 시점에 함께 맞춘다(즉시 이동, 애니메이션 없음).

### 4-4. 두 크기 공통

- 칸 터치 영역은 항상 44×44px 이상을 보장한다(칸 자체가 작아도 `padding`으로 터치 영역을 확보).
- 칸 안 텍스트는 `eraLabel`(예: "구석기") + `shortTitle`(예: "주먹도끼") 두 줄. `eraRange`(연대)는 **칸 안에 넣지 않는다** — 칸이 좁아 잘리기 쉽고, 이 사양서 배경(§0-2)에서 "eraRange는 띠 아래에 작게 보이는 연대"라고 이미 정했다. 구현: 칸을 길게 누르거나(데스크톱은 hover) 탭하면 나오는 짧은 안내(툴팁/작은 말풍선)에 `eraRange`를 보여주는 정도로 충분하다 — 상시 노출은 아니다.

## 5. 하지 않을 것 (D-036, §0 반복 확인)

- **자유 이동 게임화 금지**: 말판·캐릭터 토큰이 칸 사이를 움직이는 연출, "다음 칸으로 전진!" 같은 게임적 문구, 주사위·확률 요소를 넣지 않는다. 이 띠는 순수한 진도 표시이지 새 미니게임이 아니다.
- **애니메이션 과다 금지**: 상태가 바뀔 때(완료 직후 등) 색·아이콘이 순간적으로 바뀌는 정도(150~200ms 이하의 짧은 전환) 외에, 반복 재생되는 애니메이션·자동 캐러셀·색이 계속 움직이는 효과를 넣지 않는다. 자동 스크롤(§1-2, §4-3)도 "즉시 이동"이지 부드러운 스크롤 애니메이션이 아니다.
- **진도 강제 금지**: "아직" 칸을 회색으로 흐리게 하거나 자물쇠 아이콘을 붙이거나 탭을 막지 않는다. 언제든 어느 차시든 바로 시작할 수 있다(§3 캡션 문구가 이미 이를 알린다) — 기존 커리큘럼 카드 진입 방식과 동일한 자유도를 유지한다.
- **"이 편에서 밝힐 질문", 도감 빈 칸, 기록지 인쇄는 만들지 않는다**(D-036, 원 지시서 §0에서 이미 범위 밖으로 정함 — 이 사양서도 반복해 확인한다).

## 6. 확인이 필요한 지점 (이 문서에서 결정하지 않음)

- **§2-1 완료 판정 로직의 정확한 구현 위치**: `unlockedArtifacts` 기반 판정을 `js/lessonTrack.js`에 새로 넣을지, `js/encyclopedia.js`에 헬퍼를 추가할지는 조작대가 자기 파일 소유권(`js/encyclopedia.js`는 대조실 소유) 범위를 보고 판단한다.
- **`eraRange` 툴팁 표시 방식**(§4-4): 정확한 상호작용(탭-토글 vs hover)은 태블릿 실측(1180×820) 때 조작대가 확인하며 정한다 — 이 사양서는 "상시 노출은 아니다"까지만 정한다.
- **32편 모두 완료했을 때의 "지금" 부재 처리**(§2-1): 이번 범위에서는 별도 축하 배너를 만들지 않기로 했지만, 실제 학생이 이 상태에 도달하는 건 학기 말이라 라운드 9 검증만으로는 확인하기 어렵다 — 실제 도달 시 재검토 대상으로 남긴다.

## 7. 띠는 연표가 아니다 — 겹치는 시대 안내 (라운드9 2단계 §3, D-036 정정 반영)

라운드9 1단계 통합 결과 정규 편은 32개가 아니라 **28개**다(`data/lesson_track.json`의 `note`가 이미 밝힘). 이 문서의 나머지 절은 32라는 숫자를 예시로만 썼을 뿐 구조는 그대로다.

### 7-1. 왜 안내가 필요한가

띠는 `order`(차시를 배운 순서)로 칸을 나열한다. 학생은 가로로 나열된 것을 보면 자연스럽게 "왼쪽이 더 옛날, 오른쪽이 더 나중"이라는 **연표**로 읽는다. 그런데 `lesson_track.json`은 실제로 그렇게 정렬돼 있지 않다 — 특히 **통일신라(order 7, 676~935년)와 발해(order 8, 698~926년)는 228년을 함께 겹쳐 존재했다**(대조실 확인, 2-§1). 순서상 발해가 통일신라 "다음"인 것처럼 보이지만, 실제로는 두 나라가 같은 시기에 나란히 있었다 — 순서를 시대 계승으로 잘못 읽으면 "발해는 통일신라가 끝난 뒤 세워졌다"는 틀린 그림이 만들어진다.

### 7-2. 문구 확정

**띠 제목**(기존 §3 "🧭 나의 역사 여정"을 아래로 교체한다):

> `🧭 나의 역사 탐구 순서`

**띠 제목 바로 아래 캡션**(§3의 "안내 캡션"을 아래 문장으로 교체·보강한다 — 기존 문장 뒤에 이어 붙인다):

> `이 띠는 배운 순서예요. 실제 연대순은 아니에요 — 예를 들어 통일신라와 발해는 같은 시대에 함께 있었어요. 완료한 차시는 다시 볼 수 있고, 아직 하지 않은 차시를 눌러 바로 시작할 수 있어요.`

두 문장으로 나눠 읽어도 되게 마침표로 끊었다: (1) "순서지 연대가 아니다" + 통일신라·발해라는 **구체적인 반례**를 바로 붙여, "그냥 순서일 뿐"이라는 추상적 안내보다 훨씬 잘 기억되게 했다. (2) 기존 "완료·아직" 안내는 그대로 유지한다.

**개별 칸의 보조 설명**(칸의 `title`/`aria-label` — §4-4에서 이미 "탭·hover 시 추가 정보"로 정한 자리): 통일신라·발해 두 칸에는 **서로를 가리키는 문구를 덧붙인다.**

| 칸 | `title`/`aria-label` 문구 |
|---|---|
| 통일신라(order 7) | `통일신라 · 문무대왕릉 (676~935년, 발해와 같은 시기가 있었어요)` |
| 발해(order 8) | `발해 · 해동성국 (698~926년, 통일신라와 같은 시기가 있었어요)` |

다른 26개 칸은 이런 상호 참조 문구가 필요 없다 — 관문 설계실·대조실이 확인한 나머지 시대는 순서와 시대 계승이 실제로 일치한다(2-§1). **띠 전체에 "이 시대들은 겹칠 수 있다"는 일반 경고를 반복해서 달지 않는다** — 위 캡션 한 번으로 "이 띠가 연표가 아니다"는 원칙을 알리고, 실제로 겹치는 단 한 쌍에만 구체적 반례를 붙이는 편이 "모든 칸에 주의 문구"보다 학생이 읽는다.

### 8-1. 종합 판단

가장 크게 걸리는 것은 **위치(포털 화면 미배치)** 와 **레이아웃(단원별 3줄 없음, 항상 가로 스크롤)** 두 가지다 — 나머지(아이콘·라벨·캡션)는 문구·CSS 몇 줄 조정으로 끝나지만, 이 둘은 구조 자체가 달라 다시 짜야 한다. 다만 완료 화면에 접이식으로 넣은 1단계 구현도 "새 저장 키를 안 만든다", "44px 터치 목표", "완료 칸 재도전" 같은 핵심 제약은 잘 지켰다 — 완전히 새로 만들 필요는 없고, 조작대가 2-§4에서 반영 우선순위를 정해 좁혀 가면 된다고 본다. 우선순위는 이 창이 강제하지 않는다(조작대 소관).

## 9. 다음 단계

조작대가 이 사양서와 `data/lesson_track.json`(관문 설계실)이 모두 나온 뒤 `js/lessonTrack.js`를 구현한다. 이 문서와 실제 구현이 달라지면(예: 터치 크기 재조정), 조작대가 완료 보고에 이유를 적고 이 문서를 갱신 요청한다 — 이 창(연결 공방)이 문서를 최종 수정한다.
