# 구현 계획 — Deep-dive 난이도 상향·분기 확장 (D-019 실행)

작성: Claude (2026-09-04) — **계획서만. D-019가 명시적으로 "범위 밖"이라 밝힌 실제 콘텐츠 제작은 이 문서에서 진행하지 않는다.** 사용자 확인 후 별도로 착수한다.

## 0. 근거 문서

- `DECISIONS.md` D-019 — "정답 판단이 서사의 도덕적 톤만으로 풀리지 않도록, 역사 지식이 있어야 구분되는 판단 지점을 늘리는 것을 우선 검토한다." "범위 밖(이 결정만으로는 진행하지 않음): 실제 분기 확장·난이도 상향 콘텐츠 제작."
- `INBOX.md` 2026-09-04 — 한국사능력검정시험 준비생 학생의 "너무 쉬워요" 리포트(어느 Deep-dive 파일인지는 원문에 명시되지 않음 — §5-1에서 확인 필요).
- `docs/plans/implementation_plan_deep_dive_redesign.md` — 이번 세션 앞부분에 이미 "선택지가 단서를 인용" 패턴을 설계·검증했다. 이 문서는 그 작업의 다음 단계다.

## 1. 진단 — 지금 "너무 쉬운" 이유는 게이팅이 아니라 선택지 설계다

이번 세션에 4개 Deep-dive 파일 전체에 게이팅·단서 인용을 이미 적용했다(커밋 `e04496f`~`22cb5a2`). 그런데 그 작업도 D-019가 지적하는 문제를 풀지 못한다 — **정답 선택지는 협상·포용·과학적 판단처럼 도덕적으로 온화하고, 오답은 폭정·무모함·고립처럼 도덕적으로 가혹하다.** 역사 지식이 전혀 없어도 서사 톤만으로 정답을 고를 수 있다.

예시(`deep_prehistoric` 4번, 이미 인용형으로 고친 뒤에도 여전히 톤으로 풀림):
- 정답: "곰 부족을 주 파트너로 맞아들여 연합한다"
- 오답: "다른 부족과의 연합을 일절 거부하고 고립되어 살아간다"

"고립"이 나쁘다는 건 역사를 몰라도 안다. **이게 D-019가 말하는 "서사의 도덕적 톤" 문제의 정확한 사례다.**

## 2. 설계 원칙 — 무엇을 바꿔야 "지식이 있어야 구분"되는가

톤을 지우고 **사실이 있어야만 구분되는 두 개의 그럴듯한 선택지**를 만든다. 셋 다 이번 세션에 이미 검증된 인용형 패턴 위에 얹을 수 있다.

### 2-1. 톤 중립화 — 오답도 "합리적으로 들리게" 쓴다

지금처럼 오답에 "무조건", "일절 거부", "아무것도 하지 않고" 같은 극단적 부사를 쓰지 않는다. 대신 **실제로 역사학계에서 논쟁이 있었거나, 그럴듯하지만 사료와 어긋나는 해석**으로 오답을 구성한다.

### 2-2. "더 똑똑해 보이는 오답" — 상위권 학생을 위한 함정

D-019가 원하는 "여러 수준의 학생이 재도전"하려면, 상위권 학생이 성급하게 정답으로 오인할 만한 **정교한 오답**이 필요하다. 예: 실제로 있었던 소수설·이설을 오답으로 배치하되, 단서 카드에 왜 통설이 더 근거가 있는지 밝힌다. 이건 국사능력검정시험 준비생 같은 학생에게 실제 변별력을 만든다.

### 2-3. 분기 확장 — 오답이 "죽은 재시도"가 아니라 "다른 유효한 경로"가 되게

지금 오답은 전부 `X-fail` → 설명 → 원래 스테이지로 복귀다. D-019는 "재도전해 성공"을 원하므로, 일부 오답을 **부분 성공 분기**(다른 근거로 다른 결말에 도달하되 `ending_normal`처럼 하위 등급)로 바꾸는 걸 검토한다 — 이미 8번 스테이지들의 3분기 엔딩 구조가 이 패턴이다. 이걸 중간 판단 지점까지 확장하는 것.

## 3. 적용 대상 확인 필요 (착수 전 사용자 확인)

`INBOX.md`의 "너무 쉬워요" 리포트에는 어느 Deep-dive 파일인지 적혀 있지 않다. 4개 파일 전부 같은 설계 결함(톤으로 풀림)을 공유하므로 전부 대상이 될 수 있지만, **파일럿은 1개로 시작**하는 게 이번 세션 내내 지켜온 원칙과 맞다.

| 후보 | 이유 |
|---|---|
| `deep_prehistoric` | 이번 세션에서 제가 가장 깊이 다뤄 구조를 가장 잘 알고 있어 위험이 낮다 |
| 학생이 실제로 리포트한 파일 | 리포트가 그 파일에 대한 것이라면 가장 직접적인 피드백 루프가 된다 — **어느 파일인지 사용자 확인 필요** |

## 4. 제안 파일럿 범위 (승인 시)

1. 파일 1개, 판단 스테이지 2~3곳만 우선 재설계(§2-1·2-2 톤 중립화 + 함정 오답).
2. 분기 확장(§2-3)은 더 큰 구조 변경이라 2단계로 미룬다 — 1단계 결과를 보고 결정.
3. 신규/수정 서술에 들어가는 모든 구체적 사실은 기존 `sources` 필드 수준의 출처 확인을 거친다(D-005). "더 똑똑해 보이는 오답"이 실제로는 사실 오류가 되지 않도록 이 부분을 가장 엄격히 검증한다.
4. 완료 후 `scripts/12_audit_choice_bias.py`로 새 선택지가 다시 길이 편향을 만들지 않는지 확인(이번 세션에 4개 파일에서 반복한 절차).
5. 이 리포트를 준 학생에게(가능하다면) 재도전 기회를 줘서 실제로 변별력이 생겼는지 확인 — EXPERIMENTS.md 가설로 승격 검토.

## 5. 결정 필요한 것 (착수 전)

1. **§3 파일 선택**: 어느 Deep-dive MUD부터 시작할지.
2. **오답의 "함정" 강도**: §2-2처럼 상위권 학생을 실제로 헷갈리게 할 정도로 만들 것인가, 아니면 톤만 중립화(§2-1)하는 선에서 먼저 시험할 것인가 — 후자가 더 안전한 1차 시험이라고 제안한다.
3. **분기 확장(§2-3) 포함 여부**: 이번 파일럿에 넣을지, 톤 중립화 결과부터 보고 2단계로 미룰지.

이 세 가지에 대한 답을 받은 뒤 실제 스테이지 재작성에 착수한다.
