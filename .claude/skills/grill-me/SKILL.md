# grill-me — 구현 전 질문 라운드

출처: mattpocock/skills의 `grill-me`·`grilling`을 이 저장소의 문서 우선 흐름(`INBOX → BACKLOG → implementation_plan`)에 맞게 옮겼다.

목표: 계획을 **결정 트리**로 보고, 모든 가지를 방문해 아무것도 조용히 가정하지 않은 상태에서 사용자와 공동 이해에 도달한다. 그 전에는 코드·데이터를 고치지 않는다.

## 절차

1. **대상 파악**: 사용자가 따질 대상(활동 설계, 콘텐츠 초안, 기능 계획 등)을 한 줄로 요약한다. 관련 `INBOX.md` 항목, `BACKLOG.md` 항목, `DECISIONS.md` 결정, `implementation_plan_*.md`를 먼저 읽는다.
   - 완료 기준: 대상과 이미 확정된 결정(D-번호)을 구분해 말할 수 있다.
2. **라운드 진행**: 매 라운드마다 **프런티어**(선행 결정이 모두 정해져 추측 없이 물을 수 있는 결정 전부)를 한 번에 묻고, 사용자 답을 기다린다.
   - 앞 질문의 답에 따라 달라지는 질문은 다음 라운드로 미룬다.
   - 답을 받으면 확정된 결정이 풀어 준 하위 질문으로 프런티어를 다시 계산한다.
3. **사실과 결정 구분**
   - 사실(파일 내용, 교과서 쪽수 매핑, 기존 활동 구조, 검증 스크립트 결과)은 직접 도구로 찾아 확인한다. 찾을 수 있는 것을 사용자에게 묻지 않는다.
   - 결정(교육적 의도, 활동 길이, 학생 화면 문구 방향, 범위)은 사용자 몫이다. 반드시 묻고 기다린다.
4. **종료**: 프런티어가 비면 확정된 결정을 번호 목록으로 요약하고 "이 이해가 맞는지" 확인받는다.
   - 완료 기준: 사용자가 공동 이해를 명시적으로 확인했다.
5. **기록**: 확인받은 결과를 `INBOX.md`에 원문 보존 형식(`사용자 원문`·`상태`·`분류`)으로 남기고, 승격할 대상(`BACKLOG.md`, `DECISIONS.md`, `implementation_plan_*.md`, `EXPERIMENTS.md`)을 제안한다. 승격 자체는 사용자 확인 뒤에 한다.

## 질문 형식

각 질문은 아래 형식을 따른다. "예"라고 답하면 추천안을 받아들이는 문장으로 쓴다.

```markdown
❓ **Q1. 짧은 제목**: 질문 본문(여러 문단·선택지 가능)
➡️ 추천: 추천 답과 근거 한 줄

---
```
