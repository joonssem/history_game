# 조선 후기 협동 탐구 — 교사용 sticky-wall 운영 자료

- 작성: 연결 공방(activity-loop), 라운드7 §3
- 근거: `docs/handoff/claude_four_track_round7_instruction.md` §3-3, `implementation_plan_joseon_late_cooperative_live_vertical_slice.md` §6
- 이 문서는 **앱 데이터가 아니다.** 라운드6 초안에서 `data/cooperative/joseon_late_packet.draft.json`의 `questionFrames` 필드로 들어 있던 내용을 여기로 옮겼고, 라운드8 §4(D-035)에서 패킷 초안을 지우면서 역할별 `sharePrompt`도 함께 옮겼다. 앱 계약(`docs/handoff/claude_joseon_late_runtime_scenario.json`)에는 `sharePrompt`·질문 틀 필드가 없다 — "자기 자료를 말로 설명했는가"는 앱이 `share` 단계에서 학생의 확인 버튼만으로 판정하고(계획서 §5 `share → synthesis` 관문), 무엇을 말할지 안내하는 문구 자체는 교사가 이 문서를 보고 진행하거나 화면 밖에서 안내한다.

## 0. 역할별 말하기 안내 문구(`sharePrompt`)

한 사람씩 자기 자료를 공유할 때 교사가 (또는 화면 밖 안내지로) 읽어 주는 문장이다. 앱의 `share` 단계 자체에는 이 문구가 표시되지 않으므로, 진행자가 미리 익혀 두거나 인쇄물로 함께 배부한다.

| 역할 | 말하기 안내 |
|---|---|
| 농민(`farmer`) | "내가 짓는 농사법이 내 살림과 이웃의 살림을 어떻게 바꾸었는지 설명해 보세요." |
| 보부상(`bobusang`) | "장시와 화폐가 물건을 사고파는 방식을 어떻게 바꾸었는지 설명해 보세요." |
| 수공업자(`craftsman`) | "장시에서 물건을 만들고 파는 내 생활이 예전과 어떻게 달라졌는지 설명해 보세요." |
| 기록관(`recordkeeper`) | "기록에 남아 있는 것과 남아 있지 않은 것을 구분해 설명해 보세요." |
| 품팔이(`laborer`, 5인만) | "땅을 빌려 농사짓지 못하게 된 뒤 내 생활이 어떻게 달라졌는지 설명해 보세요." |

## 1. 다른 모둠에게 던질 질문 틀 3종

발표를 들은 다른 모둠이 아래 세 틀 중 하나 이상을 골라 질문하도록 안내한다. 정답을 찾는 질문이 아니라 해석을 검증하는 질문이다.

| 구분 | 질문 틀 |
|---|---|
| 대상 질문 | "그 해석은 [ ]에게는 좋은 변화라고 했는데, [ ]에게는 어땠을까요?" |
| 근거 질문 | "그렇게 생각한 근거 중 하나를 다시 말해 줄 수 있나요? 그 근거가 왜 그 대상과 연결되나요?" |
| 한계 질문 | "이 자료만으로는 알 수 없다고 한 것은 무엇인가요? 왜 알 수 없나요?" |

- 세 틀은 앱 계약(`claude_joseon_late_runtime_scenario.json`)의 `sharedPrompt.connections`(누구에게 어떤 영향)·`sharedPrompt.policies`(어떤 변화를 근거로 골랐는지)·`sharedPrompt.limitations`(자료로 알 수 없는 것)와 각각 짝을 이룬다 — 발표 모둠이 고른 것을 그대로 두고, 듣는 모둠은 그 선택에 대해서만 되묻는다.
- 진행 순서(계획서 §0-3): `발표 → 대상 질문 1개 이상 → 근거 질문 1개 이상 → 한계 질문 1개 이상 → 발표 모둠이 필요하면 해석 수정`.

## 2. sticky-wall 인계 문자열 형식

계획서 §6 그대로다. 모둠이 공동 해석을 완성하면 아래 형식으로 옮겨 적어(또는 화면에서 복사해) sticky-wall에 붙인다.

```text
[조선 후기 협동 탐구 · N모둠]
처음 해석: …
근거: ① … ② …
자료의 한계: …
질문해 주세요: 누구에게? 어떤 근거로? 어디까지 말할 수 있나요?
```

- `N모둠`만 식별자로 쓴다. 학생 이름·학번·역할 배정·세션 ID·수업 코드·토큰은 어떤 형태로도 포함하지 않는다.
- "처음 해석"은 모둠이 고른 `sharedPrompt.connections` 문장(들), "근거"는 고른 `sharedPrompt.policies`의 `label` 2개 이상, "자료의 한계"는 고른 `sharedPrompt.limitations`의 `label`이다.
- 마지막 줄의 세 물음표는 위 §1의 질문 틀 세 가지를 요약해 보여 주는 것으로, 다른 모둠이 이 포스트잇을 보고 바로 질문을 떠올리게 하는 역할이다.

## 3. 운영 순서 (한 모둠 기준)

1. 역할별 비공개 자료 확인 → 개인 최초 판단(혼자, 역할별 `firstChoices`) → 한 사람씩 말로 자료 공유(§0 안내 문구 참고)
2. 모둠 공동 해석 작성(`sharedPrompt`: 정책 2개 + 연결 문장 1개 이상 + 한계 1개 이상) → 모둠원 전원 확인
3. 위 §2 형식으로 sticky-wall 문자열을 만들어 게시판에 붙인다
4. 다른 모둠을 순회하며 §1의 질문 틀로 질문·반론을 남긴다(포스트잇 옆에 붙이거나 구두로 전달)
5. 발표 모둠은 질문을 반영해 필요하면 해석을 수정하고 다시 게시한다

## 4. 실시간 장애 시 대체

`implementation_plan_...md` §6 마지막 항목대로, sticky-wall(물리 게시판이든 별도 온라인 게시판이든) 사용이 막히면 같은 세 형식(§1·§2)을 교사 화면이나 칠판에 그대로 띄워 발표·화이트보드로 진행한다. 질문 틀·문자열 형식 자체는 실시간 앱 상태와 무관하게 항상 쓸 수 있도록 이 문서에 독립적으로 남겨 둔다.

## 5. 도입·개입·발표 발문 (2026-09-29 초안, 라운드 12 §3-2)

앱 화면에는 없는 교사용 말이다. 정답을 묻지 않고, 학생이 가진 자료로 돌아가게 하는 질문만 쓴다.

### 5-1. 도입 발문 2개 (활동 시작 전, 전체에게)

1. "5일마다 시장이 서고, 동전으로 물건을 사고팔게 되면 마을 사람들의 하루는 어떻게 달라질까요?"
2. "같은 변화가 사람마다 똑같이 느껴졌을까요? 오늘은 서로 다른 처지의 사람이 되어 자료를 읽어 봅니다."

- 2번 뒤에 "먼저 내 자료만 읽고 처음 생각을 종이에 적습니다"로 이어 간다(최초 판단은 앱이 저장하지 않으므로 종이에 남긴다).

### 5-2. 막힌 모둠에게 던질 발문 3개 (앱 `interventions`와 겹치지 않게 상황별로)

| 막힌 모습 | 발문 |
|---|---|
| 자료를 서로 말하지 않고 각자 화면만 봄 | "각자 자료에서 '달라진 점' 하나와 '어려워진 점' 하나를 짧게 말해 볼까요?" |
| 근거를 한 친구의 자료에서만 고름 | "지금 고른 근거는 누구의 자료에서 나왔나요? 다른 친구의 자료에도 이어지는 이야기가 있나요?" |
| "모든 사람이 그랬다"고 쓰려 함 | "우리 자료는 한 고을 이야기예요. 다른 고을도 똑같았다고 말하려면 무엇이 더 있어야 할까요?" |

### 5-3. 발표 사례를 고르는 기준

점수·순위를 매기지 않는다. **"처음 해석 → 질문 → 수정"이 드러난 모둠**을 먼저 고른다.

1. sticky-wall에 다른 모둠의 질문이 붙어 있다.
2. 그 질문을 받고 해석·근거·한계 중 하나를 고친 흔적이 있다(새로 적은 포스트잇이나 지운 자국).
3. 근거 두 개 이상이 **서로 다른 역할의 자료**에서 나왔다.
4. 자료로 알 수 없는 것을 밝힌 문장이 있다.

- 1~2가 있으면 3~4가 조금 부족해도 먼저 고른다 — 수정 과정이 보이는 것이 이 활동의 핵심이다.
- 발표는 "무엇이 바뀌었나요? 왜 바꿨나요?"를 먼저 묻는다.
- 위 기준이 한 모둠에도 없으면, 근거를 가장 또렷하게 말한 모둠을 골라 "아직 질문이 없는 부분이 어디일까요?"를 학급에 묻는다.

## 6. 종이 역할 카드 인쇄용 형식 (실시간 앱이 안 될 때, 정적 폴백의 최소형)

앱과 같은 활동을 종이로 하는 최소 형식이다. 새 화면·새 코드가 필요 없다.

### 6-1. 카드 본문은 JSON에서 그대로 옮긴다

`docs/handoff/claude_joseon_late_runtime_scenario.json`의 `roles[]`에서 `name`, `privateInfo`, `interest`, `evidence[0].label`을 **문구를 바꾸지 않고** 복사한다. 앱과 종이의 문장이 달라지면 안 된다(낱말 풀이 괄호도 그대로 둔다).

- 3인 모둠은 `farmer`·`bobusang`·`recordkeeper` 카드 + 아래 공통 자료 한 줄(`commonEvidenceByGroupSize.3`)
- 4인 모둠은 `farmer`·`bobusang`·`craftsman`·`recordkeeper`
- 5인 모둠은 4인 + `laborer`

### 6-2. 카드 한 장 형식 (A4를 반으로 잘라 한 장, 가로 글씨 14pt 이상)

```text
┌──────────────────────────────────────┐
│ {icon} {name}          (이 카드는 나만 봐요)   │
│                                              │
│ 내 자료                                       │
│ {privateInfo}                                 │
│                                              │
│ 내가 중요하게 생각하는 것                       │
│ {interest}                                    │
│                                              │
│ 모둠에 말할 근거 한 줄: {evidence[0].label}     │
│                                              │
│ ▶ 내 처음 생각 (자료를 읽은 뒤, 친구 자료를 보기 전에)  │
│   □ 많은 사람의 살림이 전반적으로 나아졌을 것이다     │
│   □ 사람에 따라 좋아진 점과 어려워진 점이 함께 있었을 것이다│
│   □ 예전과 크게 달라지지 않았을 것이다             │
│   이유: ________________________________        │
└──────────────────────────────────────┘
```

- 처음 생각의 세 선택지는 JSON `roles[].firstChoices`(모든 역할 동일)를 그대로 쓴다.
- 카드 뒷면은 비워 둔다. 5장 1세트(모둠당 4~5장)를 **모둠 수만큼 인쇄해 두 번 접은 봉투에** 넣어 나눠 준다. 카드는 서로 보지 않고 자기 것만 읽는다.

### 6-3. 모둠 해석 시트 (모둠당 한 장, A4)

```text
[조선 후기 협동 탐구 · ___모둠]

① 우리가 고른 변화 두 가지 (○표)
   □ 장시(5일장)가 늘어난 변화
   □ 화폐(상평통보)를 쓰게 된 변화
   □ 농사짓는 방법(모내기법)이 바뀐 변화

② 누구에게 어떤 영향을 주었나 (한 가지 고르기)
   □ 넓은 논을 짓는 농민이 늘었지만, 땅을 구하지 못한 이웃 가운데 일부는 품삯을 받으며 살아가야 했다
   □ 보부상은 상평통보 덕분에 여러 장시를 오가며 거래하기 편해졌지만, 동전이 모자란 때는 돈을 받기 어려웠다
   □ 수공업자는 스스로 만들어 파는 자유를 얻었지만, 장이 안 서는 달에는 살림이 불안정해질까 걱정했다

③ 이 자료만으로는 알 수 없는 것 (한 가지 이상)
   □ 우리 이야기만으로 조선 후기 모든 지역·사람이 똑같이 달라졌다고 말할 수 없다
   □ 우리 자료는 한 고을·한 장시의 사례이며 다른 지역은 달랐을 수 있다
   □ 화폐와 장시가 퍼진 정확한 시기는 이 자료만으로 알 수 없다

④ 근거는 서로 다른 친구의 카드에서 두 개 이상:  ______________ / ______________
⑤ 모둠원 전원이 읽고 "확인" 표시:  □ □ □ □ □
```

- ①~③ 선택지는 JSON `sharedPrompt.policies`·`connections`·`limitations`의 `label`을 그대로 옮긴 것이다. 이 시트를 완성하면 §2의 sticky-wall 문자열 형식으로 옮겨 적어 붙인다.
- 실시간 앱의 "전원 확인"은 ⑤의 표시로 대신한다. 한 사람이라도 표시하지 않으면 sticky-wall에 붙이지 않는다.

### 6-4. 종이로 전환할 때 알려 줄 것

- "화면이 안 돼서 종이로 합니다"라고 사실대로 말한다. 앱이 곧 복구될 것처럼 말하지 않는다.
- 최초 판단·근거 두 개 이상(서로 다른 역할)·자료로 알 수 없는 것의 세 가지는 종이에서도 빠지지 않는다.
- 이 형식은 앱 데이터가 아니라 교사 자료다. JSON이 바뀌면(예: Codex가 낱말 풀이를 고치면) 이 절도 같이 갱신한다.
