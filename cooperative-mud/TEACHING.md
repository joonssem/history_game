## 수업 전 준비

1. **모둠을 정하고 번호를 부여한다.** 학생은 앱에서 `모둠 번호`와 `내 번호`를 직접 고른다. 앱은 이름·학번을 받지 않으므로 교사가 대응표를 갖고 있어야 한다.
2. **모둠 번호와 개인 번호를 교실 앞 화면에 띄운다.** 2026-09-04에는 이 방식이 잘 통했다.
3. **결석·조퇴를 그날 반영한다.** 학생이 실제 인원 3·4·5명을 직접 고르면 좌석과 역할이 그에 맞게 만들어진다. 3인일 때는 빠진 역할의 자료가 모두에게 공통으로 공개된다.
4. **활동 길이를 정해 알려 준다.** 5분형과 10분형이 있고, 10분형에는 한 단계가 더 붙는다.

## 수업 중

- 학생은 **자기 화면을 친구에게 보여 주지 않는다.** 말로 설명해야 활동이 진행된다. 이것이 이 활동의 핵심이다.
- **7·8차시는 친구 이야기를 듣기 전에 각자 판단을 먼저 고른다.** 학생이 `최초 판단` 화면에 있을 때는 아직 설명하지 않도록 안내한다. (6차시는 순서가 반대다. 아래 참조.)
- 모둠의 최종 결정은 말로 합의한 뒤 **대표 기기 한 대**에 기록한다. 기기 사이는 연결되어 있지 않다.
- 진행 바 아래에 작은 배지가 뜰 수 있다. 느린 모둠에는 질문형 힌트가, 빠른 모둠에는 심화 질문이 나온다. 화면을 덮지 않고 학생이 눌러야 펼쳐진다.
- 교사는 순회하며 관찰한다. 앱에는 교사 화면이 없다.

## 무엇을 볼 것인가

2026-09-04 수업에서 확인된 것은 여기까지다 — 비대칭 정보가 실제 대화를 만들었고, 모둠 결과가 하나로 수렴하지 않았다. 아직 확인되지 않은 것을 본다.

- [ ] 네 자료(또는 네 이야기)가 모두 모둠에서 실제로 발화되었는가
- [ ] 공유 전 최초 판단이 학생마다 달랐는가
- [ ] 친구 말을 듣고 판단을 바꾼 학생이 있었는가 — **7·8차시에서만 제대로 측정된다**
- [ ] 한 학생이 모둠 결정을 독점하지 않았는가
- [ ] 5인 모둠의 다섯째 학생이 방관자가 되지 않았는가
- [ ] 타이머 배지가 너무 자주 떴는가, 아니면 한 번도 안 떴는가
- [ ] 실제 소요 시간은 몇 분이었는가

관찰은 [`EXPERIMENTS.md`](../EXPERIMENTS.md)에 `EXP-006`과 같은 형식(`관찰 → 가설 → 결과 → 다음 결정`)으로 남긴다. 학생 이름·발언 원문은 적지 않는다.

## 알아 둘 것

- **6차시는 화면 순서가 다르다.** 고조선 편은 `모둠에 이야기했어요`를 누른 뒤에 최초 판단을 고르게 되어 있다. 그래서 기록된 "최초 판단"이 이미 친구 설명을 들은 뒤의 값이다. 판단 변경을 보려면 7·8차시를 쓴다. (`BACKLOG.md` P2-COLLAB-02)
- **기록은 그 기기에만 남는다.** 서버로 가지 않고, 다른 기기와 합쳐지지 않는다. 브라우저 기록을 지우면 사라진다.
- **개인형 MUD와 연결되지 않는다.** 유물 도감·완료 상태에 반영되지 않는다.
- **인터넷이 필요하다.** GitHub Pages에서 받아 오므로 학교 인터넷이 끊기면 열리지 않는다.
- 활동 중 문제가 생기면 완료 화면의 `이 기기 기록 지우고 다시 하기`로 처음부터 다시 할 수 있다.
