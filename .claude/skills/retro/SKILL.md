# retro — 세션 회고와 에이전트 환경 개선

출처: mattpocock/skills의 `retro`와 `writing-for-agents`를 이 저장소의 문서 체계에 맞게 옮겼다.

대상 세션: 사용자가 지정한 세션, 없으면 현재 세션.

## 절차

1. **1차 자료 읽기**: 세션 로그(`~/.claude/projects/D--codexwork-history-game/<세션 ID>.jsonl`)와 그 세션의 커밋(`git log`·`git show --stat`)을 읽는다. 기억에 의존하지 않는다.
   - 완료 기준: 세션에서 시간을 많이 쓴 지점, 되돌린 수정, 사용자 정정 발언을 목록으로 뽑았다.
2. **개선 후보 찾기**: 아래 범주를 모두 훑는다.
   - **길 찾기**: 정보를 찾는 데 오래 걸렸다면, 그 위치를 가리키는 한 줄 안내를 `project_context.md`나 `AGENTS.md`에 둘 후보로 만든다.
   - **자동 검사**: 검사로 잡을 수 있었던 실수를 찾는다. 먼저 `scripts/`의 기존 검증과 `.github/workflows/quality-gate.yml`을 확인한다. 기계적으로 판정되는 규칙은 문서 지시가 아니라 `scripts/` 검사나 CI 단계 후보로 만든다. 검사가 없는 것 자체가 발견 사항이다.
   - **콘텐츠 기준**: 판단이 필요한 규칙(연령 적합성, 사실성)만 문서 규칙으로 남긴다. `DECISIONS.md`의 콘텐츠 규칙과 겹치면 그쪽을 가리킨다.
   - **AGENTS.md 다이어트**: AGENTS.md는 매 세션 컨텍스트에 실린다. 지난 이력, 쓰지 않는 역할 체계, 다른 문서와 중복된 내용은 해당 문서로 옮기거나 지우는 후보로 만든다.
   - **무효 지시**: 에이전트가 기본으로 이미 하는 일을 시키는 문장, 행동을 바꾸지 않는 문장을 지울 후보로 만든다.
   - **도구 비용**: 반복된 비싼 탐색·긴 출력·불필요한 재실행을 줄일 방법을 찾는다.
   - **정보 접근**: 에이전트가 없어서 막힌 정보(서버 로그, 배포 상태, 실제 기기 결과)를 줄 방법을 찾는다.
3. **보고**: 후보를 심각도 순으로 사용자에게 제시한다. 각 후보에 근거(세션 내 지점), 제안 변경, 대상 파일을 붙인다.
   - 완료 기준: 모든 범주를 확인했고, 해당 없는 범주는 "해당 없음"으로 적었다.
4. **기록**: 이 저장소의 문서 우선 원칙에 따라 바로 고치지 않는다. 사용자가 고른 후보를 `BACKLOG.md`에 문제·목적·영향·변경 범위·관련 파일과 함께 등록한다. P0만 예외로 즉시 수정할 수 있다.

## 에이전트용 문서를 쓸 때의 원칙

AGENTS.md·스킬·안내 문서를 고칠 때 적용한다.

- **안내는 조건과 위치만**: "X를 할 때 → `파일`을 본다"처럼 트리거 단어를 앞에 두고, 본문을 옮겨 적지 않는다.
- **진실의 원천은 하나**: 같은 의미를 여러 문서에 복제하지 않는다. 원문은 `INBOX.md`, 결정은 `DECISIONS.md`, 현재 상태는 `project_context.md`에 둔다.
- **환경을 다시 적지 않는다**: 스크립트 목록·디렉터리 구조처럼 찾을 수 있는 사실은 생략하고, 찾을 수 없는 관례·이유·함정만 적는다.
- **긍정형으로 쓴다**: 원하는 행동을 적는다. 금지는 꼭 필요한 안전장치(예: 교과서 PDF 업로드 금지)에만 쓰고 대신 할 행동을 함께 적는다.
- **단계마다 완료 기준**: 끝났는지 판정할 수 있는 기준을 붙인다.
- **오래된 내용은 지운다**: 바뀐 역할 분담, 끝난 Phase 이력은 `walkthrough.md`·`DECISIONS.md`에 맡기고 상시 문서에서 뺀다.
