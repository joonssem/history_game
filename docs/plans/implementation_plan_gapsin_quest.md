# 구현 계획: 갑신정변 역사 체험(2019 오프라인 활동의 하이브리드 이식)

- 상태: `진행 중` — 정답이 필요 없는 부분(카드·암호·팀 확인·미션 이야기·밀지·마무리)은 구현·검증 완료(2026-11-04). 자가 점검 미션 5종도 구현·검증 완료(같은 날).
- 작성: 2026-11-04, Claude
- 시기: 2단원 마지막 차시(2단원 수업 진행 중, 날짜 미정)
- 원본: 교사 제작 2019년 오프라인 활동(`갑신정변_역사체험` 폴더의 HWP·PDF·PPTX, 저장소 밖). 원본 파일은 저장소에 복사하지 않는다.

## 목표

종이 미션지 사용을 최대한 줄이고, 교사가 일본 NPC와 관찰에 집중하게 한다. 이동·팀 결성·일본 거절은 오프라인으로 유지한다.

## 사용자 결정(2026-11-04 질문 라운드)

- 기기 역할: 개인 카드 + 암호 + 자가 점검 미션.
- 종이 미션지는 최대한 줄인다.
- 팀 구성은 2019년과 같다(4·4·4·5·5명, 암호 5종: 실학·탕평책·강화도조약·병인양요·신미양요). 이번 학급 인원이 다르면 사용자가 알려 준다.
- 마무리 화면 주제: 실제 갑신정변의 실패 이유, 일본에 의존한 선택 성찰, 개혁안과 민중 입장, 활동 소감.

## 원본 활동 흐름(PDF 텍스트·화면으로 확인)

1. 개인 카드: 이름 수수께끼(역할 4~5종, 예: 김옥균·서재필 등). 역할 능력은 "급진개화파의 리더 / 일본어에 능숙 / 개화를 잘 앎 / 변화에 두려움 없음" 등.
2. 암호 질문(예: 실용 학문의 이름 = 실학)의 답이 같은 사람끼리 팀이 된다.
3. 팀 미션 6개: 일본에 도움 요청(백자 틀린그림) → 폭탄 뇌관 찾기(사다리타기) → 왕 모셔오기 → 개혁안 발표(실제 개혁안 4개 고르기) → 궁궐 수비(방위표대로 지도에 병력 표시) → 일본에 보내는 밀지 쓰기.
4. 마지막에 교사가 일본 역할로 사소한 이유를 들어 병사 파견을 거절하고, 정변은 실패한다.
5. 학생은 "결과는 어떻게 되었나요?"를 적는다.

## 최소 범위

새 정적 페이지 `cooperative-mud/gapsin-quest/`를 만든다. 기존 `episode.js`의 화면 흐름은 맞지 않으므로 `gojoseon-law/app.js`처럼 자체 `app.js`를 두고 `cooperative.css`는 재사용한다. DB·로그인·서버·외부 API는 쓰지 않고 기기별 `localStorage`만 쓴다.

| 화면 | 기기가 하는 일 | 종이를 대체하는 것 |
|---|---|---|
| 개인 카드 | 학생이 번호를 고르면 자기 이름 수수께끼 카드 표시, 정답 입력으로 정체 확인 | 개인 카드 |
| 암호 | 암호 질문과 입력, 같은 암호끼리 모이라는 안내 | 암호 쪽지 |
| 팀 확인 | 동지 역할 구성이 맞는지 교사에게 보이는 확인 화면 | 교사의 팀 확인 |
| 자가 점검 미션 | 사다리타기(뇌관), 개혁안 7개 중 4개 고르기, 궁궐 수비 지도 점 찍기, 백자 틀린그림(이미지 확보 시) | 미션지 4장 |
| 밀지 쓰기 | 팀이 쓴 글을 화면에 쓰고 교사에게 보여 주기(저장은 기기 안에서만) | 밀지 종이 |
| 일본 거절 | 교사가 일본 역할을 오프라인으로 수행한다. 화면은 "교사에게 가서 밀지를 보여 주세요" 안내만 | 변경 없음 |
| 마무리 | 실제 실패 이유 3~4개, 의존 선택 성찰, 개혁안과 민중 입장, 소감 입력 | 결과 적기 칸 |

교사 확인이 필요한 곳(팀 확인, 밀지)은 기존 방식대로 교사가 화면을 보고 확인한다.

## 검증 필요(구현 전 사용자 확인 사항)

- (해결) 개혁안 정답은 가·다·마·바다. 14개조 정강 1조(청에 대한 조공 폐지)·2조(문벌 폐지, 능력에 따른 관리 임명)·3조(지조법 개혁)와 대조했다. 처음 추정한 "사"(학교와 은행)는 틀렸고, "바"(청나라를 받들어 모시지 않는다)가 맞다.
- 뇌관 사다리의 정답 경로, 백자 틀린그림의 개수·위치, 궁궐 수비 방위표의 정답은 이미지로만 있어 텍스트 추출이 안 된다. 사용자가 정답을 알려 주거나 PDF 이미지를 그대로 쓴다.
- 역할 카드 이름과 수수께끼는 4인·5인 팀 구성별로 PDF에 있다. 역할 수와 이름 대응표를 구현 전에 확정한다.
- 역사 서술 정확성: 원본에 "큰 흐름만 비슷하다"는 교사 주석이 있다. 마무리 화면은 교과서 서술과 맞추고, 교과서 범위를 넘는 내용은 교사 안내로 둔다. 원문은 `primary_data/`에서 확인한다.

## 작업 단계

1. 위 확인 사항에 답을 받는다.
2. `gapsin-quest/index.html`, `app.js`, `quest.js`(시나리오 데이터)를 만든다. 엔진·역사 내용은 `quest.js`에 둔다.
3. 교사용 보기: 팀 편성표, 암호 대응표, 미션 정답, 일본 역할 대사 예시를 `cooperative-mud/teacher/`의 기존 형식에 맞춰 인쇄용으로 만든다.
4. `cooperative-mud/index.html` 목록에 항목을 추가한다.
5. 검증: `node --check`, 기존 `scripts/` 검증, 가로·세로 모바일 폭 확인, 실제 수업에서 시간을 재서 EXPERIMENTS.md에 기록한다.

## 범위 밖

학생이 AI와 직접 대화하는 기능, 서버 저장·실시간 동기화, 교과서 원문 복제, 원본 PPTX·HWP 파일의 저장소 반입.
