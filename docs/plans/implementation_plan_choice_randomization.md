# MUD 선택지 정답 위치 편향 개선 계획

## 현재 상태

- 상태: `completed` (2026-08-26 기능 구현·정적 검증·브라우저 회귀 완료)
- 후속 항목: 선택지 길이·구체성 편향은 `implementation_plan_choice_quality_batch.md`와 `choice_bias_audit.md`에서 별도로 관리한다.

## 1. 작성 목적

MUD를 시작하면 정답 선택지가 항상 첫 번째에 표시되는 문제를 개선한다.
이번 계획은 선택지 데이터의 의미와 분기 경로를 보존하면서, 학생이 선택지 위치만으로 정답을 추측할 수 없도록 하는 것을 목표로 한다.

## 2. 현재 상태와 확인된 근거

- 전체 MUD 선택지 중 `correct: true`인 항목은 238개이다.
- 선택지가 2개 이상인 실질적 판단 단계는 113개이다.
- 113개 단계 모두 정답 선택지가 배열의 첫 번째 항목이다.
- 당시 [js/mudEngine.js](../../js/mudEngine.js)의 `renderStage()`는 `stage.choices` 배열을 JSON 순서 그대로 렌더링했다.
- 선택지의 실제 결과는 `correct` 필드가 아니라 각 선택지의 `next` 값으로 결정된다.
- [scripts/02_fix_missing_next.py](../../scripts/02_fix_missing_next.py)는 누락된 `next`를 보완하는 스크립트이며, 선택지 순서는 변경하지 않는다.

## 3. 목표

### 기능 목표

1. 선택지 위치만으로 정답을 추측할 수 없게 한다.
2. 정답·오답 선택지의 기존 `next` 분기를 그대로 유지한다.
3. MUD를 새로 시작하거나 다음 단계로 이동할 때 선택지 표시 순서를 무작위화한다.
4. 선택지가 하나뿐인 IF 재시도 단계는 불필요하게 처리하지 않는다.

### 비기능 목표

1. JSON 콘텐츠를 대량 수동 수정하지 않는다.
2. 선택지 객체 자체를 원본 데이터에서 직접 재배열하지 않는다.
3. 모바일·터치 UI의 기존 버튼 동작과 스타일을 유지한다.
4. 새 패키지나 프레임워크를 추가하지 않는다.

## 4. 실행 단계

### 단계 1 — 렌더링 시 선택지 무작위화

대상 파일: `js/mudEngine.js`

작업 내용:

- `stage.choices`를 직접 변경하지 않고 복사본을 만든다.
- 복사본에 Fisher-Yates 셔플을 적용한다.
- 선택지 수가 2개 이상일 때만 셔플한다.
- 셔플된 배열을 사용해 버튼을 생성한다.
- 각 버튼의 `onclick`/이벤트 핸들러는 기존 `ch.next`를 그대로 사용한다.

예상 결과:

- 정답이 1번·2번·그 외 위치에 무작위로 표시된다.
- 선택지 텍스트, 사운드, IF 경로, 엔딩 경로는 변경되지 않는다.

### 단계 2 — 선택지 편향 검증 로직 추가

대상 파일: `scripts/03_validate_mud_integrity.py`

작업 내용:

- 다중 선택지 단계에서 `correct` 필드의 위치를 집계한다.
- 정답 위치가 한 위치에만 몰리는 경우 경고를 출력한다.
- 선택지가 2개 이상인데 정답 또는 오답이 없는 경우 오류로 처리한다.
- `next` 기반 실제 분기 검증은 기존 로직을 유지한다.

주의:

- 런타임에서 셔플하므로 데이터 파일의 정답 위치가 균등하지 않아도 기능상 문제는 없다.
- 따라서 분포 편향은 기본적으로 오류가 아니라 콘텐츠 품질 경고로 취급한다.

### 단계 3 — 콘텐츠 선택지 품질 점검

대상: `data/mud/*.json`

작업 내용:

- 정답만 지나치게 길거나 구체적인 문장인지 확인한다.
- 오답이 역사적으로 명백히 말이 안 되는 선택지인지 확인한다.
- 정답·오답의 문장 길이와 표현 형식을 가능한 범위에서 균형화한다.
- 자동 생성된 IF 단계의 설명이 단순 재시도 문구에 그치는지 별도 목록화한다.

이 단계는 1·2단계 완료 후 별도 콘텐츠 검수로 진행하며, 기능 정상화와 분리한다.

## 5. 검증 계획

### 정적 검증

```bash
python scripts/01_validate_game_data.py
python scripts/03_validate_mud_integrity.py
```

```bash
node --check js/mudEngine.js
git diff --check
```

### 브라우저 검증

1. Regular MUD를 여러 번 시작한다.
2. 동일한 단계에서 첫 번째로 표시되는 선택지가 매번 달라지는지 확인한다.
3. 정답 선택 시 정상 다음 단계로 이동하는지 확인한다.
4. 오답 선택 시 기존 IF 재시도 단계로 이동하는지 확인한다.
5. Deep-dive MUD에서 `ending_true`, `ending_normal`, `ending_bad` 경로가 유지되는지 확인한다.
6. 모바일 폭과 일반 데스크톱 폭에서 버튼 클릭이 정상인지 확인한다.
7. 브라우저 콘솔 오류가 없는지 확인한다.

### 회귀 기준

- MUD 시작 화면이 열려야 한다.
- 선택지 버튼 수와 텍스트가 원본과 일치해야 한다.
- 선택지의 표시 순서만 달라져야 한다.
- 기존 보상, 도감 언락, 성찰 일기, 시뮬레이터가 영향을 받지 않아야 한다.

## 6. 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| JSON 원본 배열을 직접 섞어 이후 단계가 달라짐 | 복사본만 셔플하고 원본은 보존 |
| 무작위 테스트가 간헐적으로 실패함 | 테스트에서 여러 번 실행하거나 셔플 함수를 주입 가능하게 설계 |
| 한 개짜리 IF 선택지가 불필요하게 이동함 | 선택지가 2개 이상일 때만 셔플 |
| `correct`와 `next`가 불일치하는 콘텐츠 발견 | 기존 무결성 검사에 불일치 경고를 추가하고 콘텐츠 검수 목록화 |
| 정답 위치 편향을 고쳤지만 오답이 지나치게 쉬움 | 단계 3에서 선택지 문장 품질을 별도 검수 |
