# 구현 계획 — 협동 활동·역사 탐구 디자인 정렬

- 작성일: 2026-09-30
- 문서화 작업: `TASK-20260930-COOP-INQUIRY-DESIGN-PLAN`
- 우선순위: **P2 — 사용성·시각 일관성 개선**
- 상태: **계획·체크리스트 작성 완료 · 구현 승인 대기**
- 실행 체크리스트: [`tasks_cooperative_inquiry_design_alignment.md`](./tasks_cooperative_inquiry_design_alignment.md)

## 1. 목적

정적 협동 MUD와 포털의 역사 탐구 패널이 공유하는 색·글꼴·조작부 기준을 맞춘다. 두 화면은 이미 따뜻한 역사 수업 계열의 색을 사용하므로, 전체 재설계가 아니라 CSS 변수와 주요 터치 기준을 정리한다.

## 2. 현재 기준선

| 구분 | 현재 구조 | 확인된 차이 |
|---|---|---|
| 정적 협동 활동 | 별도 페이지, 최대 폭 820px, 소개에서 역할·활동 단계로 이어지는 흐름 | `--coop-*` 변수를 자체 정의. 배경·먹색·적토색·청록색 값은 포털 팔레트와 대체로 일치 |
| 역사 탐구 | MUD 화면 우측 인터랙티브 카드 안의 도구 패널 | 포털 공통 변수를 사용. 최대 높이 `min(54vh, 440px)`의 내부 스크롤과 하단 고정 제출 버튼을 가짐 |
| 조작부 | 두 화면 모두 카드·선택 버튼 중심 | 협동 활동 주요 조작부는 대체로 48px 이상, 탐구 버튼은 최소 44px |
| 반응형 기준 | 독립 페이지와 임베디드 패널 | 협동 활동 600px, 탐구 패널 620px에서 모바일 규칙 적용 |

정적 확인 기준 파일은 [`cooperative.css`](../../cooperative-mud/cooperative.css), [`style.css`](../../css/style.css), [`index.html`](../../index.html)이다. 이전 브라우저 시각 확인은 URL 판별 제한으로 완료되지 않았으므로, 실제 CSS 변경 전에 현재 화면을 지원 뷰포트에서 다시 확인한다.

## 3. 우선순위와 근거

- **P0 없음:** 현재 비교에서 수업을 막거나 콘텐츠를 가리는 확정 장애는 확인되지 않았다.
- **P1 없음:** 터치 크기·색 계열은 이미 상당 부분 비슷하며 긴급한 회귀 수정 근거가 없다.
- **P2 — 이번 제안:** 중복된 팔레트 정의를 정돈하고 터치·반응형 규칙을 맞춰 두 도구 사이의 전환을 예측 가능하게 한다.
- **별도 후보:** `apps/cooperative-live`는 Next 앱의 남색·파랑·금색 테마를 가진 별도 제품면이다. 이번 디자인 정렬 범위에 포함하지 않는다. 추후 공통 사용성 기준이 필요할 때만 별도 계획한다.

## 4. 제안 범위

### 포함

- 포털 역사 탐구와 정적 협동 MUD의 역사 수업 팔레트·글꼴 기준 기록 및 정렬
- 주요 터치 선택·진행 버튼 최소 높이 48px 기준 검토
- 버튼 모서리·테두리·선택·비활성·키보드 포커스 표현의 일관성 검토
- 모바일 전환 기준을 620px로 통일할지 실제 콘텐츠 폭에 맞춰 결정
- 정적 협동의 단계형 단독 화면과 역사 탐구의 임베디드 패널 레이아웃 보존
- 역사 탐구의 내부 스크롤과 하단 고정 제출 버튼 보존

### 제외

- 실시간 협동 앱 `apps/cooperative-live`의 색상 테마 전면 변경
- MUD 콘텐츠, 문구, 역사 서술, 진행 로직 변경
- 새 CSS 프레임워크·패키지 도입 또는 포털 전체 재설계
- 사용성 근거 없이 두 화면의 레이아웃을 똑같이 만드는 작업

## 5. 구현 순서

1. **기준 화면 확인:** 현재 CSS·HTML과 실제 표시를 휴대전화·태블릿·데스크톱 폭에서 대조한다.
2. **토큰 정렬:** 색상·글꼴·테두리 기준을 정하고, 독립 페이지가 포털 CSS에 의존하지 않도록 변수 연결 방식을 결정한다.
3. **조작부 정렬:** 최소 터치 높이와 모서리·선택·포커스 표시를 적용한다. 의미 상태 색상(성공·오류)은 팔레트 정렬 과정에서도 구분을 유지한다.
4. **반응형 정렬:** 600px/620px 경계의 실제 폭을 대조한 뒤 공통 기준을 정한다. 각 화면의 고유 배치는 유지한다.
5. **화면 검토:** 320×568, 390×844, 820×1180, 1180×820, 1366×768에서 잘림·가로 넘침·제출 버튼 접근성을 확인하고 결과를 기록한다.

## 6. 완료 기준

- [ ] 정적 협동 MUD와 역사 탐구 패널에서 본문·강조·주요 조작 색의 기준이 설명 가능하고 일치한다.
- [ ] 포털에서 진입하거나 정적 페이지를 단독으로 열어도 색상·글꼴 토큰이 빠지지 않는다.
- [ ] 주요 선택·진행 버튼이 최소 높이 48px 기준을 만족하거나, 예외가 필요한 항목에 근거가 기록된다.
- [ ] 선택·비활성·오류·키보드 포커스 상태가 서로 구분된다.
- [ ] 휴대전화 폭에서 두 화면 모두 가로 넘침 없이 한 열로 읽힌다.
- [ ] 역사 탐구 패널은 내부 스크롤 중에도 제출 버튼에 접근할 수 있다.
- [ ] 정적 협동 MUD의 독립 페이지 흐름과 역사 탐구의 임베디드 배치가 유지된다.
- [ ] 지정 뷰포트의 화면 확인 결과와 변경 파일·이유가 체크리스트에 기록된다.

## 7. 착수 조건과 승인 경계

이 문서는 비교 결과를 우선순위화하고 구현 범위를 제안하는 단계다. 현재 CSS·HTML·스크립트 파일은 수정하지 않았다. 구현은 사용자가 별도로 승인한 뒤 시작한다. 변경 후에는 문서의 시각 확인 체크리스트를 수행하며, 역사 콘텐츠·실시간 협동 기능·배포 범위를 추가하지 않는다.
