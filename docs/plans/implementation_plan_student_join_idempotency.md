## 문제와 원인

전체 학생 테스트에서 중복 접속으로 학생이 입장하지 못하는 사례가 보고됐다. 오류 전문과 발생 횟수는 아직 없으므로 단일 원인으로 단정하지 않는다. 복구 기준 `f71ca7d`에서 다음 구조적 위험을 확인했다.

- QR 입장 `joinWithEntryKey`와 수동 코드 입장 `joinWithCode`는 매 성공 호출마다 새 참가자 행을 만든다.
- 수동 입장의 `attemptId`는 실패 횟수 제한에만 쓰여 성공 응답 유실 뒤 같은 요청이 재전송돼도 같은 참가자 자리를 찾지 않는다.
- QR 입장에는 재시도를 식별할 클라이언트 키가 없다.
- 새로 발급된 학생 토큰은 응답을 받은 뒤에야 `sessionStorage`에 저장된다.

네트워크 재시도나 중복 제출이 좌석 중복으로 이어질 수 있다. 별도 기기에서 독립적으로 시작한 서로 다른 요청이 동일 학생인지 식별할 근거는 없으므로, 그 경우는 교사 발급 자리 복구로 처리한다.

## 목표

1. 같은 브라우저 탭의 같은 수업 입장 재시도는 새 참가자 행을 만들지 않고 기존 자리를 돌려준다.
2. 요청 응답이 유실돼도 클라이언트가 이미 보관한 동일 좌석 토큰으로 재시도할 수 있다.
3. 동일 좌석 토큰 재시도는 수업 인원 한도 검사보다 먼저 기존 자리를 찾는다.
4. 학생 기기·탭 저장 정보가 사라진 경우 교사 발급 12자리 일회용 코드로 같은 역할·모둠·진도를 복구한다.
5. 중복 방지 키는 URL·localStorage에 저장하지 않고, 서버에는 해시만 둔다.

## 제안한 재접속 절차

### 같은 기기·같은 탭

1. 먼저 같은 활동 탭을 새로고침한다. 성공한 입장 토큰이 있으면 기존 호·모둠·역할·단계가 복구된다.
2. 입장 화면으로 돌아왔으면 같은 수업 코드로 다시 시도한다. 이 탭에서 입장 전에 저장한 좌석 토큰이 기존 서버 자리를 찾아 중복 행을 만들지 않는다.

### 탭·브라우저 데이터·기기를 잃은 경우

1. 학생이 교사에게 현재 대시보드의 호/모둠을 알려 준다. 학생 이름·학번은 받지 않는다.
2. 교사는 대시보드에서 해당 좌석의 `자리 다시 연결`을 눌러 코드를 발급한다.
3. 학생은 `/join`에서 6자리 수업 코드와 12자리 재연결 코드를 입력하고 `같은 자리로 돌아가기`를 누른다.
4. 코드는 5분 뒤 만료되고 한 번만 쓸 수 있다. 성공하면 새 토큰을 발급하고 이전 토큰을 폐기하며 역할·모둠·진도를 보존한다.
5. 코드는 학생에게 개별 전달하고 공개 프로젝터에 띄우지 않는다.

위 교사 발급 복구 흐름은 `f71ca7d`에 이미 구현되어 있다. 이번 작업은 QR·수업 코드 재시도에서 중복 행이 생기지 않게 하고, 위 절차를 교사용 자료에서 찾기 쉽게 만든다.

## 구현 범위

- 클라이언트는 입장 요청 전에 256비트 좌석 토큰을 생성해 `sessionStorage`에 저장한다. 네트워크 재시도와 QR·수동 코드 경로에서 동일 토큰을 사용한다. QR 입장키도 주소창에서 제거한 뒤 성공할 때까지만 같은 탭 저장소에 보관해 새로고침 뒤 재시도할 수 있게 한다.
- Convex는 이 토큰의 해시를 세션 범위 인덱스로 찾는다. 기존 활성 자리가 있으면 세션 상태와 좌석 한도에 새 좌석을 만들기보다 그 자리를 반환한다.
- 신규 참가자 생성은 기존 토큰 확인 뒤 수행한다. 같은 ID의 동시 mutation은 Convex 트랜잭션 직렬화와 좌석 키 확인으로 1행에 수렴시킨다.
- 기존 삭제·제외 좌석을 같은 join 토큰으로 자동 복구하지 않는다. 제외된 좌석은 교사가 발급한 1회용 재연결 코드만으로 재활성화한다.
- 학생 오류 안내는 같은 탭·같은 코드 재시도를 먼저 알려 주고, 저장 정보 분실 시 교사 자리 복구 절차를 안내한다.
- 실제 오류 문구와 원인은 다음 리허설에서 개인정보 없이 추가 기록한다. 일반 네트워크 장애 자체가 절대 발생하지 않는다고 표현하지 않는다.

## 범위 밖

- 서로 다른 기기/브라우저에서 새 좌석 키로 요청한 두 사람을 같은 학생으로 자동 합치기. 학생 계정·이름을 수집하지 않으므로 서버가 신원을 추론하지 않는다.
- 동시 로그인된 두 기기를 실시간으로 쫓아내는 세션 관리.
- 그룹 인원수·역할 자료·교사 master 진행 동작 변경.
- 외부 계정, Auth0 또는 공개 Preview 설정 변경.

## 수용 기준과 검증

- 같은 좌석 토큰·QR 재요청과 같은 좌석 토큰·수업 코드 재요청 모두 참가자 행을 1개만 만든다.
- 요청 응답 유실을 흉내 내 재시도해도 같은 세션·학생 토큰으로 돌아온다.
- 같은 토큰은 참여자 수 한도에 도달한 뒤에도 자기 자리를 재조회할 수 있지만, 새 토큰은 기존 한도를 넘겨 입장하지 못한다.
- 입장 성공 뒤 `alias`, 모둠, 역할, 단계·완료 표시가 중복 행에 의해 달라지지 않는다.
- 제외된 좌석의 자동 재활성화, 다른 세션 토큰 재사용, 만료·삭제 세션 재진입은 거부한다.
- 교사 1회용 재연결 코드는 같은 자리를 보존하고 이전 토큰을 무효화한다.
- 서버 저장에는 좌석 토큰 원문이 없고, 세션 종료 때 참가자·시도 데이터가 삭제된다.
- `npm run check` 및 production build 통과 뒤, Preview에서 QR·코드 연속 제출과 같은 탭 새로고침 재접속을 확인한다.
- 실기기 수업 시험 전 단계에서는 교사 1명·학생 역할 기기 4~8대 리허설을 수행한다.
