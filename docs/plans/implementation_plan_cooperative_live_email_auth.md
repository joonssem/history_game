# 실시간 협동 활동 교사 이메일 인증 전환 계획

> **상태: 보류·대체됨(2026-10-05).** Auth0 및 이메일 인증 계획은 교사 한 명용 비밀번호 로그인으로 대체되어 운영 반영됐다. 여러 교사의 개별 로그인이 실제 요구가 되기 전까지 이 계획을 재개하지 않는다.

- 날짜: 2026-10-05
- 상태: 계획·구현 승인 대기
- 원문: [`INBOX.md`](../../INBOX.md)의 2026-10-05 항목
- 대상: `apps/cooperative-live` 교사 대시보드. 학생 QR·코드 입장은 변경하지 않는다.

## 현황과 원인

`app/providers.tsx`는 Auth0 React와 `ConvexProviderWithAuth0`를 결합한다. `components/LiveTeacherConsole.tsx`는 Google 로그인으로 진입하고, `convex/auth.config.ts`는 Auth0 토큰을 검증한다. `convex/security.ts`는 `TEACHER_AUTH0_SUBS`에 등록된 `subject`만 허용한다. `sessions.ownerSub`에도 그 값이 저장된다. 따라서 UI 문구만 바꾸거나 이메일 형식만 검사하면 교사 권한이 보호되지 않는다. Preview URL마다 Auth0 callback을 등록해야 하는 현재 방식은 실제로 2026-09-29 리허설의 차단 요인이었다.

## 제안

1. 교사는 이메일 주소를 입력하고 해당 주소로 발송된 짧은 유효기간의 일회용 코드를 입력한다. 전송 성공 또는 주소 형식만으로 로그인 처리하지 않는다.
2. 인증은 기존 Convex 연결과 통합되는 이메일 OTP 공급자를 사용한다. 첫 구현 후보는 Convex Auth의 이메일 OTP와 별도 메일 발송 서비스다. Convex Auth의 Next.js 지원·패키지 버전·메일 공급자 설정은 구현 시작 시 공식 문서와 설치 환경으로 재확인한다. Auth0와 Google 연결은 성공적인 전환 뒤 제거한다.
3. 서버는 검증된 이메일과 배포 환경의 허용목록을 대조한다. 클라이언트가 보낸 이메일을 권한 근거로 사용하지 않는다. 주소는 정규화하고 교사 소유 식별자는 인증 공급자가 발행한 안정적 ID로 삼는다. 실제 허용 주소와 발송 비밀키는 저장소에 넣지 않는다.
4. 기존 Auth0 `subject`가 소유한 열린 세션은 전환 전 종료·삭제하거나, 관리자 검증 후 명시적으로 소유자를 이전한다. 자동으로 이메일 문자열에 매핑하지 않는다.
5. 학생은 계정을 만들지 않고 현행 QR·코드 및 세션 한정 토큰을 계속 사용한다. 실제 학생 운영에 대한 개인정보·배포 게이트는 인증 전환과 별개로 확인한다.

## 구현 단위

- 인증 공급자·환경변수·발송 설정을 교체하고, `/teacher`에 이메일 입력·코드 입력·재전송·로그아웃·오류 안내를 만든다.
- `requireTeacher`와 서버 권한 검사를 검증된 이메일 허용목록 기반으로 전환하고, 기존 세션 소유권과 마이그레이션 경로를 점검한다.
- 미인증·비허용 이메일·만료/틀린 코드·재전송 제한·로그아웃·새로고침 후 복구·교사 세션 생성/재개/종료·학생 QR 입장을 검증한다.
- `.env.example`, `README.md`, 교사용 운영 문서와 기존 Auth0 callback 대기 상태를 결과에 맞게 갱신한다. 별도 Preview에서 실제 메일 송수신과 4~8대 기기 리허설을 수행한다.

## 착수 전에 확정할 값

- 이메일 발송 공급자와 인증 메일의 발신 주소/도메인
- 교사 대시보드 접근을 허용할 이메일 주소(배포 환경변수에만 등록)
- 기존 Auth0 교사 세션을 모두 종료할 수 있는지, 진행 중 세션이 있다면 이전 방식

실제 발송과 접속 확인은 위 값과 배포 비밀키가 준비되어야 완료할 수 있다. 메일 서비스 추가는 개인정보 처리 문서의 공급자 범위도 함께 확인한다.

## 수용 기준

- Auth0 Google 로그인 없이 허용된 교사 이메일의 수신·코드 확인만으로 교사 화면에 접속한다.
- 미확인 주소와 비허용 주소는 Convex 교사 함수에 접근하지 못한다.
- 기존 교사 세션의 소유권이 잘못 연결되지 않으며, 학생 입장·진행·종료 흐름이 유지된다.
- `npm run check`와 인증 경계 회귀 검사, Preview 실제 메일 송수신 및 교실 기기 리허설을 통과한다.
