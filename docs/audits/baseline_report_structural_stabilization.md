## 4. 인덱스·배포 기준선

### 로컬 인덱스

`data/mud/_index.json`은 32개 MUD 파일을 모두 참조하지만 번호 체계가 섞여 있다. 단원 최대 차시를 1단원 20, 2·3단원 14로 볼 때 범위를 벗어난 매핑은 7건이다.

- `regular_sejong`: 2단원 24, 25
- `regular_independence`: 3단원 38, 39
- `regular_korean_war`: 3단원 44, 45, 46

### 라이브 Pages

- `https://joonssem.github.io/history_game/data/mud/_index.json` 요청이 JSON이 아닌 `data/mud/index.html`로 이동한다.
- 라이브 콘솔: `_index.json` 파싱 시 `Unexpected token '<'` 오류
- 결과적으로 `app.js`는 인덱스 기반 탐색이 아니라 하드코딩 fallback으로 동작한다.
- 저장소에 `.nojekyll`이 없으며, underscore 이름의 파일 배포 처리와 404 리다이렉트가 원인 후보다.

이는 로컬 무결성 검사 통과와 실제 배포 성공이 다르다는 가장 분명한 기준 사례다.

## 5. 라이브 UI 기준선

### 포털 반응형 측정

| 뷰포트 | 카드 열 | 가로 넘침 | 문서 높이 |
|---|---:|---:|---:|
| 320×700 | 1 | 없음 | 7,640px |
| 768×1024 | 2 | 없음 | 4,129px |
| 1024×768 | 3 | 없음 | 3,482px |
| 1280×800 | 3 | 없음 | 3,482px |

CSS에 `@media`는 없지만 `auto-fit/minmax` 계열 그리드가 기본 열 전환을 수행한다. 따라서 ‘반응형이 전혀 없음’이 아니라 **포털 카드 그리드는 반응하지만 MUD 활동·접근성·iPad 조작은 별도 대응이 없다**가 정확한 기준이다.

### iPad 10세대 세로 기준(820×1180)

- MUD 본문과 시뮬레이터가 2열로 유지되어 각 열이 약 340–380px가 된다.
- 본문·연대기·시뮬레이터가 한 화면에 보이는 장점이 있으나 학생용 본문과 버튼 폭이 좁다.
- 시뮬레이터 안내와 피드백은 약 `0.75rem`이다.
- 캔버스는 접근 가능한 버튼/링크 역할을 노출하지 않아 키보드·보조기술로 수행할 수 없다.
- 구석기 환경 탐색에서 두 단서를 누르면 하단 피드백이 남은 ‘트인 평야’ 지점을 시각적으로 가린다. 2/3 상태에서 남은 목표를 찾기 어려워진다.
- 선택지는 필수 캔버스 활동이 끝날 때까지 비활성화되므로 캔버스 조작에 실패하면 진행 대체 경로가 없다.
