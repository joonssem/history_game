# 설계안 — `perspective` 탐구 문법 (입장이 갈리는 사건)

> 이 문서는 설계만 담는다. 코드는 조작대(트랙 1-B)가 사용자 확인 후 구현한다. 관문 설계실(트랙 1-A)은 `js/`를 수정하지 않는다.

## 상태

- 상태: 설계안 제출, 구현 대기 (사용자 확인 필요)
- 근거: 원 지시서(`claude_track1a_gate_grammar_instruction.md`) §5, 라운드 2 지시서(`claude_four_track_round2_instruction.md`) §1-2
- 관련 결정: `DECISIONS.md` D-027(조건이 실패할 수 있는가), D-028(코드에 조건이 있다고 동작이 보장되지 않는다), D-029(화면 문구는 코드가 아니라 데이터가 갖는다)

## 1. 왜 새 문법이 필요한가

현재 4종(`commit-revise`/`sequence`/`map-evidence`/`claim-evidence`)은 모두 **정답이 하나로 수렴하는 구조**다. 관찰 → 순서화 → 공간 추론 → 종합, 어느 단계도 "이 판단이 옳다"는 기준점이 명확하다.

전쟁·외교·신분처럼 **당대에도 입장이 갈렸던 사건**은 이 구조에 억지로 끼워 넣으면 왜곡이 생긴다. 예를 들어 병자호란의 척화·주화 논쟁을 `commit-revise`로 만들면 "주화가 정답, 척화가 오답"(또는 그 반대) 같은 승자 서사가 되어 버린다. 실제로는 **두 입장 모두 각자의 근거와 감수하려던 위험이 있었고**, 그 구조 자체를 이해하는 것이 학습 목표다.

## 2. 다루지 않는 것 — 판정 원칙

- **"어느 쪽이 옳았는가"로 판정하지 않는다.** `correct: true/false`가 입장에 붙지 않는다. 두 입장 모두 선택 가능한 정당한 시작점이다.
- 완료 조건은 "올바른 입장을 골랐는가"가 아니라 **"고른 입장의 근거를 이해했고, 반대 입장의 근거도 확인했는가"**다.
- 학생에게 가해자·피해자 역할극을 시키지 않는다는 `implementation_plan_sensitive_history_interactions.md`의 원칙을 그대로 따른다 — 여기서는 "전쟁을 미화하거나 희화화하지 않는다"로 치환한다. 척화론자를 "고집불통", 주화론자를 "비겁자"로 그리는 식의 단정적 인물평을 쓰지 않는다.
- 반대 입장을 "틀렸지만 이해해 줄 만한" 톤으로 쓰지 않는다. 두 입장 모두 같은 무게로 서술한다.

## 3. 상호작용 흐름 (4단계)

| 단계 | 학생 행동 | 게이트 |
|---|---|---|
| 1. 입장 선택 | 두 입장 중 하나를 먼저 고른다 | 선택해야 다음 단계가 열림 |
| 2. 내 입장의 근거 확인 | 고른 입장이 근거로 삼은 자료 2~3개를 연다 | 전부 열어야 다음 단계가 열림 |
| 3. 반대 입장의 근거 확인 | **고르지 않은 입장의 근거도 2~3개 연다** | 전부 열어야 다음 단계가 열림. 원 지시서 §5가 명시한 필수 요구사항 |
| 4. 감수하려던 것 질문 | "이 입장을 선택했다면 무엇을 감수해야 했을까?"에 답한다(선다형) | 정답 판정 아님 — 두 입장 각각에 대해 "그 입장이 실제로 감수하려 한 것"을 고르는 이해도 확인. 오답은 그 입장의 실제 입장과 다른 진술(예: 척화론을 "청과 즉시 교역을 확대하자는 입장"으로 오해) |

3단계가 이 문법의 핵심이다. 반대 입장의 근거를 열지 않으면 관문이 열리지 않는다 — 이게 "정답을 고르시오"가 아니라 "두 입장을 다 이해하시오"로 학습 목표를 바꾸는 지점이다.

4단계의 판정 대상은 "어느 입장이 맞는가"가 아니라 "그 입장이 실제로 무엇을 주장했는가"라는 사실 확인이다. 예를 들어 척화론을 골랐다면 "명분과 의리를 지키려면 전쟁의 피해를 감수해야 한다"가 정답이고, "청과 손잡으면 손해볼 게 없다"는 것은 척화론의 실제 논리와 다르므로 오답이다. 이는 입장의 우열이 아니라 **그 입장을 정확히 이해했는지**를 검사한다.

## 4. 데이터 스키마 (초안)

```json
{
  "type": "perspective",
  "labels": {
    "position": "1. 입장을 하나 고르세요",
    "ownEvidence": "2. 고른 입장의 근거를 확인하세요",
    "otherEvidence": "3. 반대 입장의 근거도 확인하세요",
    "reflection": "4. 각 입장이 감수하려 한 것을 연결하세요"
  },
  "prompt": "<이 편 전용 문장>",
  "positions": [
    {
      "id": "position-a",
      "label": "<입장 A 한 줄 요약>",
      "stance": "<입장 A가 실제로 주장한 것, 1~2문장>",
      "risk": "<입장 A가 감수하려 한 것>",
      "evidence": [
        { "id": "a-evidence-1", "label": "...", "detail": "..." },
        { "id": "a-evidence-2", "label": "...", "detail": "..." }
      ]
    },

      "risk": "<입장 B가 감수하려 한 것>",

  ],

      { "id": "risk-strawman", "label": "<두 입장 어디에도 없는 왜곡된 진술>", "correct": false, "feedback": "..." }
```

`map-evidence`처럼 `labels`를 필수로 둔다(D-029). 완료 메시지는 별도 필드를 만들지 않고 **그 단계의 `completion.successText`를 그대로 쓴다** — 코드 쪽에서 `taskCompleteMessage()` 헬퍼(이미 `evaluateSequence`/`evaluateMapEvidence`에 있음)를 `evaluatePerspective`에도 그대로 적용하면 된다. `evaluateCommitRevise`가 이 헬퍼를 아직 안 쓰고 있다는 문제가 라운드 2에서 발견됐으므로(`BACKLOG.md` 2026-09-11 기록), `perspective`를 새로 만들 때 처음부터 헬퍼를 쓰게 하면 같은 실수를 반복하지 않는다.

## 5. 계약 검증 초안 (`scripts/04_validate_mud_contract.py`에 추가할 것 — 구현 시점에 작성)

- `positions`는 정확히 2개.
- 각 `position`은 `id`/`label`/`stance`/`risk`가 비어 있지 않은 문자열, `evidence`는 최소 2개.
- `reflectionQuestion.options`는 최소 3개, `correct: true`가 정확히 1개(`require_single_correct` 재사용 가능).
- `labels`에 `position`/`ownEvidence`/`otherEvidence`/`reflection` 4개 키 필수(`check_task_labels` 패턴 재사용).
- **두 입장이 대칭적인지**는 자동 검증이 판단할 수 없다(D-028과 같은 한계) — "한쪽 입장의 근거가 3개, 다른 쪽이 1개"처럼 무게가 다르면 검증기를 통과해도 실제로는 편향이다. 이 균형은 **실제로 열어서 읽어 봐야** 확인할 수 있다.

## 6. 1차 적용 후보 — `regular_joseon_diplomacy` 2단계

`data/mud/regular_joseon_diplomacy.json`의 2단계(병자호란과 남한산성)는 이미 narrative에 "척화·주화 논쟁이 왜 생겼는지 생각해 보세요"라고 적혀 있다 — 구조가 아직 `ordered-hotspot`일 뿐, 콘텐츠는 이미 이 문법을 염두에 두고 쓰여 있었다.

- **입장 A(척화, 김상헌 등)**: 명과의 의리를 지키고 청의 요구에 굴복하지 않아야 한다. risk: 전쟁과 그로 인한 피해(식량 부족, 백성 피해, 항복 뒤의 굴욕)를 감수한다.
- **입장 B(주화, 최명길 등)**: 실리를 취해 화친하고 나라와 백성의 목숨을 우선 지켜야 한다. risk: 명분과 의리를 포기했다는 비판, 청과의 군신 관계라는 굴욕적 조건을 감수한다.
- 기존 2단계 hotspot 3개(`fortress`/`food`/`people`)는 "전란이 군사 문제만이 아니다"라는 근거로 두 입장 모두에 걸쳐 재사용할 수 있다 — 척화 쪽 근거로는 항전의 명분과 의지, 주화 쪽 근거로는 식량 부족·백성 피해라는 실리적 이유로 다시 배치하면 새 역사 서술을 짓지 않고도 두 입장에 근거를 배분할 수 있다.
- **주의**: 기존 1·3·4단계는 이미 "한 사건으로 단정하지 않는다"는 톤을 일관되게 쓰고 있다(`1-1`/`2-1`/`3-1`/`4-1`의 "다시 비교하세요" 패턴). `perspective`로 바꾸는 2단계도 이 톤에서 벗어나지 않아야 하며, 실패 분기(`2-1`)의 문구도 "전쟁은 성벽만 지키면 해결된다"는 기존의 단순화 오류 교정 톤을 유지한다.

## 7. 분량 판단 — 초등 5학년이 두 입장을 모두 이해할 수 있는가

기존 4종 문법과 분량을 비교했다.

| 문법 | 학생이 읽어야 하는 텍스트 조각 수(대략) |
|---|---|
| `commit-revise` | 옵션 3개 + 근거 2개 = 5개 |
| `sequence` | 카드 3개 + 의미 질문 옵션 3개 = 6개 |
| `map-evidence` | 장소 3개 + 근거 2개 + 한계 2개 = 7개 |
| `perspective`(설계안) | 입장 2개(각 `stance`+`risk`) + 근거 2×2=4개 + 성찰 질문 옵션 3개 = **11개** |

`perspective`는 기존 문법보다 읽을 텍스트가 거의 2배다. 두 입장을 각각 이해해야 하는 구조상 불가피하지만, 5학년이 한 관문에서 소화하기에는 많다. 다음 완화안을 제안한다.

1. **각 입장의 근거를 2개로 고정**(3개로 늘리지 않는다). 표에서 이미 이 가정을 썼다.
2. `stance`와 `risk`는 각각 한 문장으로 제한한다 — 설계 스키마의 예시처럼 "1~2문장"이 아니라 **최대 1문장**으로 더 좁히는 것을 권한다.
3. 성찰 질문(4단계)의 오답 2개 중 하나(`risk-strawman`)는 다른 세 문법의 오답 패턴(예: "한 자료만으로 전체를 설명한다")과 겹치지 않는, **입장 자체를 오해한 오답**이어야 한다 — 서로 다른 종류의 오개념을 검사하는 것이므로 줄이지 않는다.
4. 이렇게 줄여도 11개 조각은 여전히 `map-evidence`(7개)보다 많다. **한 MUD 안에서 `perspective`를 2단계 이상 연속 배치하지 않는다** — 파일럿 확장 시 이 문법은 편당 최대 1곳으로 제한할 것을 제안한다(사용자 확인 필요).
5. 실측 없이 이 분량 판단을 확정하지 않는다 — 구현 뒤 실제 학생 반응(완료 시간, 중도 이탈)을 `EXPERIMENTS.md`에 기록하고 재검토한다.

## 8. 구현하지 않는 것 (이 문서의 범위)

- `js/mudInquiry.js`의 `renderPerspective`/`evaluatePerspective` 구현 — 조작대 소관.
- `scripts/04_validate_mud_contract.py`의 `validate_inquiry_task`에 `perspective` 분기 추가 — 조작대 또는 관문 설계실이 구현 승인 뒤 진행.
- `regular_joseon_diplomacy.json` 실제 데이터 작성 — 스키마와 콘텐츠 후보만 §6에 제시했고, 실제 JSON은 사용자 확인 후 별도 작업으로 넘긴다.
