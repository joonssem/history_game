## 4. P0-1 — 활성 참가자 분모와 안전한 제외

- [x] **4-1. 참가자 상태 계약 추가**
  - `players.participationStatus`에 `active | removed`를 추가한다.
  - 기존 행의 `undefined`는 `active`로 해석해 배포 중 스키마 전환을 안전하게 한다.
  - `removedAt`, `removedBy`는 세션 한정 감사 정보로만 둔다.

- [x] **4-2. 공통 활성 참가자 선택 함수 작성**
  - 완료 수, 공유 수, 확인 분모, 방 단계, draft 근거 검증이 같은 필터를 사용한다.
  - 각 mutation이 제각기 `removed` 해석을 구현하지 않게 한다.

- [x] **4-3. 교사 참가자 제외 mutation 구현**
  - 세션 소유 교사만 실행할 수 있다.
  - 확인창에 모둠·호·현재 단계와 영향을 표시한다.
  - 제외 뒤 최소 3인 조건을 깨면 거부한다.

- [x] **4-4. 단계별 재계산 구현**
  - 역할 확인~자료 말하기에서는 활성 참가자 기준으로 방 단계를 다시 계산한다.
  - 공동 초안 이후 제외된 역할이 현재 근거에 포함되면 초안을 무효화하고 confirmation을 0으로 만든다.
  - 3인 편성으로 바뀌면 시나리오의 공통 자료 규칙을 적용한다.

- [x] **4-5. 제외 취소 구현**
  - 같은 `player` 행을 되살린다.
  - 초안 revision이 바뀌었다면 이전 confirmation을 복원하지 않는다.

- [x] **4-6. P0-1 회귀 테스트** — 제외·3인 재계산·제외 취소·초안 근거 무효화 통과
  - 한 모둠의 제외·복원이 다른 모둠의 단계·초안·확인 수를 바꾸지 않는다.
  - 세션 종료 시 상태·감사 필드가 모두 삭제된다.

완료 기준: 유령 참가자를 제외하면 해당 모둠의 관문 분모가 즉시 정확해지고, 학생 행동을 완료 처리한 것처럼 기록하지 않는다.

## 5. P0-2 — 모둠별 진행과 전체 진행 사전 검사

- [x] **5-1. 공통 gate preflight 작성**
  - 입력: 세션과 선택적 `groupNumber`.
  - 출력: 현재 관문, 실행 가능 여부, 답 내용을 제외한 미완료 인원·행동, 다음 단계.
  - query 표시와 mutation 실행이 같은 판정 함수를 사용한다.

- [x] **5-2. `advanceGroupStage` 구현**
  - 해당 모둠의 활성 참가자만 검사한다.
  - 통과한 경우 그 모둠의 가장 이른 단계 참가자와 room만 이동한다.
  - 다른 모둠의 `players`, `rooms`, `drafts`를 수정하지 않는다.

- [x] **5-3. 모둠 카드 버튼 구현**
  - `이 모둠 다음 단계`는 preflight 통과 때만 활성화한다.
  - 차단 시 `최초 판단 1명 남음`처럼 행동 가능한 문구를 표시한다.
  - 일시정지 중에는 모든 진행 버튼을 비활성화한다.

- [x] **5-4. 전체 진행 의미 교정**
  - 모든 활성 모둠이 같은 관문이고 모두 준비됐을 때만 활성화한다.
  - 비활성 상태에서 모둠별 차단 사유 요약을 표시한다.
  - 서로 다른 단계의 모둠을 각기 다른 다음 단계로 일괄 이동시키지 않는다.

- [x] **5-5. P0-2 회귀 테스트**
  - 실제 수업 코드 `859220`의 단계 분포를 익명 fixture로 재현한다.
  - 막힌 2·3모둠과 관계없이 준비된 모둠만 진행되는지 확인한다.
  - 전체 버튼의 표시와 서버 거부 조건이 어긋나지 않는지 확인한다.

완료 기준: 한 모둠의 미완료·연결 문제로 다른 모둠이나 전체 교사 화면이 작동 불능이 되지 않는다.

## 6. P0-3 — 학생 완료 멱등성과 오류 복구

- [x] **6-1. `completeFirst` 멱등화**
  - 이미 완료된 동일 학생 요청은 성공을 반환한다.
  - 이후 단계로 이동한 상태라도 기존 `submittedAt`이 있으면 완료 상태를 반환한다.

- [x] **6-2. `markShared` 멱등화**
  - 이미 `sharedAt`이 있으면 중복 호출을 성공 처리한다.
  - 응답 유실 뒤 재시도가 같은 결과로 수렴한다.

- [x] **6-3. 학생 버튼 상태 구현**
  - `저장 중…`, `설명 완료`, `다시 시도`를 구분한다.
  - 요청 중 연속 탭을 막되 실패 뒤 다시 누를 수 있게 한다.

- [x] **6-4. 오류 번역 구현**
  - 일시적 연결 오류: `연결이 잠시 끊겼어요. 다시 눌러 주세요.`
  - 이미 진행된 단계: 서버 상태 새로고침 후 현재 화면으로 이동.
  - 무효 토큰: `선생님께 자리 다시 연결을 요청하세요.`
  - 서버 오류 원문과 내부 식별자를 학생 화면에 표시하지 않는다.

- [x] **6-5. P0-3 회귀 테스트**
  - 연속 호출, 지연 응답, 성공 응답 유실, 다른 탭의 선행 진행을 검사한다.

완료 기준: 학생의 중복 탭이나 짧은 네트워크 장애가 빨간 오류와 영구 관문 차단으로 이어지지 않는다.

## 7. P0-4 — heartbeat와 같은 자리 재연결

- [x] **7-1. heartbeat 계약 구현**
  - 학생 화면이 활동 중 주기적으로 `lastSeenAt`을 갱신한다.
  - 교사 화면은 `접속 중(≤60초) / 응답 지연(≤180초) / 연결 끊김 가능(>180초)`으로 표시한다.
  - 일시적 탭 전환만으로 자동 제외하지 않는다.

- [x] **7-2. 일회용 복구 코드 발급**
  - 세션 소유 교사가 특정 참가자에만 발급한다.
  - 서버에는 해시와 5분 만료만 저장한다.
  - 코드 원문은 교사 화면에 잠시만 표시한다.

- [x] **7-3. 자리 재연결 mutation 구현**
  - 성공 시 새 학생 토큰을 발급하고 기존 토큰을 즉시 폐기한다.
  - 모둠·역할·단계·완료 상태를 유지한다.
  - 성공한 복구 코드와 만료된 코드는 다시 사용할 수 없다.

- [x] **7-4. 학생 재연결 화면 구현**
  - 일반 QR 신규 입장과 기존 자리 재연결을 명확히 구분한다.
  - 복구 성공 뒤 새 토큰을 `sessionStorage`에 저장하고 해당 활동으로 이동한다.

- [-] **7-5. 보안·삭제 회귀 테스트** — 이전 토큰·재사용·만료·다른 세션 거부와 DB 원문 비저장 통과. Preview 배포·런타임 로그 검사는 8-4에서 대기
  - 다른 세션 코드, 다른 참가자 코드, 만료 코드, 재사용 코드, 이전 학생 토큰을 모두 거부한다.
  - 로그·URL·클라이언트 번들에 복구 코드 원문이 남지 않는다.
  - 종료 뒤 복구 해시와 heartbeat 상태가 모두 삭제된다.

완료 기준: 학생이 탭이나 기기를 잃어도 같은 자리에 돌아오고, 이전 자격으로 동시에 접속할 수 없다.
