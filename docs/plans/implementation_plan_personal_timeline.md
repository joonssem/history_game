# 구현 계획 — 「역사 연표 순서 맞추기」를 개인 연표로 (Track3 P2)

- 작성: Claude Sonnet 5 (연결 공방 / activity-loop, 2026-09-11)
- 근거: `docs/handoff/claude_track3_activity_loop_instruction.md` §3 P2, `claude_four_track_overview.md`
- 이 문서는 **설계안**이다. 사용자 확인 전에는 구현하지 않는다(지시서·사용자 지시 모두 명시).

## 1. 문제

`data/timeline.json`은 3단원(선사~삼국, 고려~조선) 2세트가 **고정**되어 있다. 모든 학생이 같은 문제를 풀고, MUD 진행 상황과 무관하다 — 다른 3개 미니게임(원인과 결과 P0, 카드 짝맞추기 P1, 유물 탐정)이 이미 "그 학생이 실제로 겪은 것"을 재료로 쓰는 것과 대비된다.

## 2. 조사 결과 — 개인화에 쓸 수 있는 데이터

`js/encyclopedia.js`를 확인한 결과, MUD 완료를 직접 기록하는 필드는 없지만 **`unlockedArtifacts` 배열이 그 역할을 대신할 수 있다.**

- 모든 Regular MUD는 완료 시 정확히 유물 1개를 지급한다(`data/artifacts.json`의 `hint` 필드가 "N단원 M차시 [MUD명] 클리어 시 획득" 형식으로 이를 증명한다).
- `unlockArtifact(name)`은 `Array.push()`로만 추가하고 제거 로직이 없다 — 즉 **배열 순서 = 그 학생이 실제로 유물을 획득한(=MUD를 클리어한) 순서**가 그대로 보존된다. 새 필드나 타임스탬프 없이 기존 데이터만으로 "이 학생이 밟아온 순서"를 재구성할 수 있다.
- 문제: 이 순서는 **학생이 차시를 진행한 순서**이지 **역사적 발생 순서**가 아니다. 대부분은 커리큘럼이 이미 시대순으로 짜여 있어 둘이 일치하지만, 학생이 차시를 건너뛰거나 보충 MUD를 먼저 하면 어긋날 수 있다.

### 2-1. 역사적 순서 재구성 가능성

`hint` 필드에서 `N단원 M차시`를 정규식으로 추출해 봤다.

```
전체 36개 유물 중 31개: "N단원 M(~L)차시" 패턴 매칭 성공 → (unitId, lessonNumber)로 정렬 가능
5개 예외:
  - art_29 (협동 MUD 보상): "협동 MUD 2 [...]" — 차시 번호 없음
  - art_deep_1~4 (Deep-dive 보상): "N단원 심화 [...]" — 단원은 있으나 차시 번호 없음
```

커리큘럼(`primary_data/curriculum_grade5.json`)의 차시 자체가 이미 시대순으로 배열되어 있으므로, **(단원, 차시) 순서 ≈ 역사적 발생 순서**로 볼 수 있다. 단, 위 5개 예외는 별도 처리가 필요하다(§5-3).

## 3. 설계 옵션

| | 옵션 A — 완전 전환 | 옵션 B — 병행(추천) | 옵션 C — 보류 |
|---|---|---|---|
| 설명 | 고정 2세트 삭제, 해금 유물 기반 개인 연표로 완전 교체 | 기존 고정 2세트("기본 연표")는 그대로 두고, 해금 유물 기반 "나의 연표"를 새 하위 탭으로 추가 | 지금 상태 유지, P2 미착수 |
| 장점 | 다른 3개 게임과 철학이 완전히 통일됨. 유지보수 대상 1개 | 기존 콘텐츠(정확한 연도 학습) 보존 + 개인화 동시 확보. 실패해도 롤백 쉬움 | 리스크 0 |
| 단점 | 정확한 연도를 외우는 학습 목적이 사라짐. 되돌리기 어려움(콘텐츠 삭제) | 하위 탭이 하나 늘어 UI가 약간 복잡해짐 | 5개 활동 중 유일하게 "잡동사니 서랍" 상태로 남음 |
| 소량 해금 시 | 문제 자체가 성립 안 함(§5-2) | "기본 연표"로 계속 학습 가능 → 우회로 확보 | — |

**추천: 옵션 B.** 이유 —
1. 기존 2세트는 실제 연도(918년, 1392년 등)를 다루는 유일한 활동이다. "연도 암기가 아니라 인과 논리"를 표방하는 원인과 결과 게임과 역할이 다르다 — 지우면 이 앱에서 정확한 연도를 다루는 활동이 하나도 남지 않는다.
2. 게임 초반(해금 유물 3개 미만)에는 개인 연표가 아예 성립하지 않는데(§5-2), 옵션 A라면 그 학생은 이 미니게임 자체를 통째로 못 쓰게 된다. 옵션 B는 "기본 연표"라는 항상 열려 있는 우회로를 남긴다.
3. `js/miniGames.js`의 기존 `startTimelineGame(stageIndex)` / `renderTimelineUI` / `checkTimelineOrder`를 거의 그대로 재사용할 수 있어 구현·회귀 위험이 작다(P1에서 카드 게임에 쓴 "해금 유물 풀 필터링" 패턴을 그대로 적용).

## 4. 옵션 B 상세 설계 (사용자가 이 옵션을 확정할 경우)

### 4-1. UI

`#activity-panel-minigame`의 "📜 역사 연표 순서 맞추기" 버튼 아래, 결과 영역 진입 시 작은 서브 토글 2개를 추가한다: `기본 연표` / `나의 연표`. 스타일은 기존 `.activity-toggle-btn`을 재사용(크기만 축소)해 새 CSS 규칙 추가를 최소화한다.

- 기본값은 "나의 연표" — 해금 유물이 임계값 미만이면 자동으로 "기본 연표"를 보여주고 안내 문구를 띄운다(§5-2).

### 4-2. 데이터 흐름

```
1. unlockedArtifacts(이름 배열)를 artifacts.json과 조인해 상세 정보를 얻는다.
2. hint에서 (unitId, lessonNumber) 추출 → 정렬 키 생성.
3. 예외 5종(§2-1)은 unitId만 살리고 lessonNumber를 그 단원의 마지막 순번+0.5로 대체
   (같은 단원 안에서 정규 MUD들 뒤에 오도록 — Deep-dive/협동 MUD는 해당 단원
   정규 학습을 마친 뒤 진행하는 심화·보충 활동이라는 실제 배치를 반영).
4. 정렬된 배열에서 최근 N개(§5-1)를 뽑아 매 판 무작위로 섞어 제시한다.
5. 정답 판정은 "정렬 키 순서"와 일치하는지 확인 — 기존 checkTimelineOrder와 동일한 비교 로직.
```

### 4-3. 카드에 무엇을 보여줄까

기존 고정 세트는 `year` 필드를 명시적으로 보여준다(정답 확인 후 카드에 연도 노출). 개인 연표는 유물 대부분에 **정확한 연도가 없다**(era만 있음: "고조선", "고려 시대" 등). 따라서:

- 카드 앞면: 유물 이름 + 획득한 MUD 힌트(`artifacts.json`의 `hint`에서 "[...]" 안쪽만 추출)
- 정답 공개 시: 연도 대신 **era**를 순서대로 보여준다("선사 시대 → 고조선 → 삼국 시대 → …"). 원인과 결과 게임과 마찬가지로 "정확한 연도가 아니라 시대 순서"임을 안내 문구에 명시해, 실제로 모르는 연도를 아는 것처럼 보여주지 않는다(비허구 원칙).

### 4-4. 재플레이 가치

카드 게임(P1)과 동일하게 상한을 둔다 — 해금 유물이 많아지면 매번 무작위로 최근 N개(예: 5~6개)를 뽑아 재구성한다. 전체를 한 번에 다 보여주면 후반부에 카드가 너무 많아져(20개 이상) 놀이가 아니라 노동이 된다.

## 5. 확인이 필요한 지점 (이번 문서에서 결정하지 않음)

### 5-1. 카드 개수 상한

몇 개까지 한 판에 보여줄까? 원인과 결과·기존 연표 모두 5개 고정이다. 개인 연표도 5개로 맞출지, 해금량에 따라 3~7개로 가변할지는 실제 학생 진행 속도를 봐야 한다.

### 5-2. 최소 해금 기준

P1(카드 짝맞추기)은 3개로 정했다. 연표는 "순서"가 핵심이라 2개로는 순서 자체가 의미 없다 — **3개 이상**을 잠정 제안하되, 미만이면 자동으로 "기본 연표"를 보여주는 방식(§4-1)을 기본으로 제안한다.

### 5-3. 예외 5종(Deep-dive·협동 MUD) 처리

§4-2의 "단원 마지막 순번+0.5" 방식이 실제로 자연스러운지, 아니면 개인 연표에서 아예 제외할지 확인이 필요하다. Deep-dive는 "역사적 사고 질문" 중심이라 특정 사건 하나로 환원하기 어려운 콘텐츠도 있다(예: `art_deep_1`은 여러 사건을 아우름).

### 5-4. 기존 고정 2세트를 없앨지

이 문서는 **옵션 B(병행)를 추천**하지만, 최종 삭제 여부는 사용자 결정 사항이다. 병행으로 시작했다가 나중에 "기본 연표" 사용률이 낮으면 그때 삭제를 재논의할 수도 있다.

## 6. 이번 범위에서 하지 않는 것

- 구현하지 않는다 — 이 문서는 설계안이며, 사용자 확인 후 별도 작업으로 진행한다.
- `js/encyclopedia.js`에 새 필드(완료 타임스탬프 등)를 추가하지 않는다 — 트랙 2 소유 파일이고, `unlockedArtifacts` 순서만으로 설계가 성립한다.
- 새로운 미니게임을 만들지 않는다 — 기존 `startTimelineGame` 계열 함수를 확장하는 방식으로만 구현한다(지시서 §5 "미니게임 신규 추가 금지").
