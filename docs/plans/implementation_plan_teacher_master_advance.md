## 승인된 목표

전체 학생 테스트에서 중복 접속으로 입장하지 못한 학생이 생기고, 참가자 부족 모둠이 관문에서 멈췄다. 교사는 대시보드에서 모둠 상황을 파악하거나 진행을 복구하기 어렵다고 보고했다.

사용자 인터뷰 답변으로 아래 동작이 승인됐다.

1. 교사는 **선택한 모둠만 한 번에 한 단계씩** 마스터 진행한다.
2. 실행 전 교사가 확인하고, 진행 사유를 남긴다.
3. 개인 최초 판단·자료 설명·공동 초안 확인 값을 자동 완료 처리하지 않는다.
4. 다른 모둠의 단계·초안·확인 상태는 바꾸지 않는다.
5. 세션 범위의 진행 이력을 교사 화면에서 확인하고 세션 종료 때 함께 삭제한다.

원문: “권장안대로 진행하자, 단계가 많지 않으니 한번에 한 단계씩 넘겨도 될 것같아.”

## 구현 전 결정 대기

현재 런타임은 모둠 3~5명과 인원수별 공통 자료를 전제로 한다. 사용자의 2명 잔류 모둠 처리 인터뷰가 끝나기 전에는 최소 인원이나 pair mode를 임의로 바꾸지 않는다. 학생 도움 요청에 교사가 제공해야 할 조치도 별도 인터뷰 결정이며 이번 기능에 포함하지 않는다.

## 설계 기준

- 일반 `이 모둠 다음 단계`는 기존 관문을 그대로 적용한다. 마스터 동작은 별도 명시 버튼과 별도 서버 mutation으로 구분한다.
- 마스터 동작은 진행 중·일시정지 아님·선택 모둠·한 번의 다음 단계 조건을 서버에서 검증한다.
- 교사 확인에는 모둠 번호, 현재 단계, 다음 단계, 미완료 수와 결과를 표시한다. 수업 상황에 맞는 필수 사유를 선택하고, 현재 접속 학생의 동의를 확인했다는 표시를 남긴 뒤 실행한다.
- 불참가자의 `submittedAt`, `sharedAt`, `confirmedRevision`는 변경하지 않는다. 전원이 동의했거나 다음 단계로 갔다는 사실을 개인 과제 완료로 기록하지 않는다.
- 기록은 세션 ID, 모둠, 이전·다음 단계, 사유 코드, 시각만 보관한다. 학생 이름·호·개인 답·대화 내용은 저장하지 않는다.
- 한 모둠의 override가 다른 모둠 데이터에 영향을 주지 않는지 Convex 통합 테스트로 확인한다.
- 공동 초안 생성·수정이나 최종 확인 내용을 교사가 대신 작성·승인하지 않는다.

## 수용 기준

- 표준 진행이 차단된 경우 교사는 그 모둠만 한 단계씩, 이유를 선택하고 확인한 뒤 진행할 수 있다.
- 접속하지 못한 학생의 개인 완료 값은 빈 상태로 유지되며 해당 학생은 완료자로 집계되지 않는다.
- 마스터 진행 이력에 모둠·단계 전환·사유·시각이 보인다.
- 다른 모둠과 공동 초안·전원 확인 상태가 변하지 않는다.
- 일시정지·종료 세션, 잘못된 모둠/단계, 중복/역행 요청은 서버가 거부한다.
- 기록과 세션 데이터는 종료 시 함께 삭제되고 학생 식별 정보는 추가 저장하지 않는다.

## 검증

- Convex 통합 회귀: 정상 관문 대비 master bypass, 사유 필수, 일시정지·세션 소유권, 개인 완료 값 보존, 완료 집계, 모둠 격리, 세션 종료 삭제.
- `npm run check`와 production build.
- Preview에서 교사 UI의 확인·사유 선택과 실제 모둠 단계 변화를 확인한 뒤, 별도 승인된 4~8대 실제 기기 리허설에 포함한다.
- 2인 잔류 모둠 정책이 확정되기 전에는 해당 경우를 통과 기준으로 선언하지 않는다.
