# 구현 계획 — 실시간 협동 앱 역사 테마 정렬

- 작성일: 2026-09-30
- 계획 작업: `TASK-20260930-COLLAB-LIVE-THEME-PLAN`
- 우선순위 제안: **P2 — 시각 일관성 개선**
- 상태: **구현 완료 · 데모·자동 검사 통과 · 실학생 화면 확인은 별도 환경 필요**
- 체크리스트: [`tasks_cooperative_live_theme_alignment.md`](./tasks_cooperative_live_theme_alignment.md)

## 1. 목표

별도 Next.js 앱인 `apps/cooperative-live`의 남색·파랑 중심 테마를 정적 협동 MUD와 역사 탐구 화면의 따뜻한 역사 팔레트에 맞춘다. 교사 대시보드와 학생 화면의 정보 구조·실시간 상태 표시·터치 조작은 유지하고 표면 색, 강조색, 카드와 포커스 표현만 정리한다.

## 2. 우선순위 근거

- **P0/P1 아님:** 현재 테마가 수업을 막거나 진행 상태를 잘못 전달한다는 현장 근거는 없다.
- **P2 제안:** 정적 협동 활동·역사 탐구와 화면을 오갈 때 색과 카드 인상이 크게 달라, 시각 일관성을 높일 개선 여지가 있다.
- 테마 정렬은 실시간 활동의 인증·입장·진행 안정성 게이트를 대체하지 않는다. 실시간 수업 재개 여부는 기존 별도 운영 체크리스트를 따른다.

## 3. 현재 기준선

- 앱은 포털과 분리된 Next.js + Convex 앱이다. 포털 CSS를 직접 가져오지 않고 앱 안의 토큰으로 테마를 적용한다.
- 화면은 시작 페이지, 교사 대시보드, 학생 입장, 학생 활동으로 구성된다. 가상 데이터 모드와 연결 모드는 공통 스타일을 사용한다.
- `app/globals.css`에 `--navy`, `--blue`, `--gold`, `--ink`, `--surface` 등이 있다. 히어로는 30px, 카드 계열은 22px, 역할 카드는 18px 모서리를 사용한다.
- 기본 버튼은 최소 높이 48px, 학생 선택 카드는 54px이다. 화면은 760px에서 주요 그리드를 단일 열로 바꾼다.
- 전역 `:focus-visible` 규칙은 확인되지 않았다. 테마 변경 시 키보드 포커스 가시성을 포함한다.

## 4. 제안 팔레트와 표현

| 역할 | 제안 기준 | 적용 원칙 |
|---|---|---|
| 페이지 바탕·본문 | 포털 미색 `#F9F6F0`, 먹색 `#2C2724` | 전체 기본 화면의 따뜻한 배경과 높은 본문 대비 |
| 카드·보조면 | 흰색/아이보리, 보조 배경 `#EFEAE1`, 테두리 `#DDD4C7` | 교사 카드·모둠 카드·학생 패널을 차분하게 구분 |
| 역사 강조 | 적토색 `#8A3B29`와 짙은 적토색 `#6C2D20` | 히어로·제목·작은 강조에 사용. 파괴 동작의 상태색과 분리 |
| 주요 행동 | 청록색 `#2E5B70` | 학생 입장·공동 초안 저장 등 주요 버튼에 사용 |
| 상태 | 기존 성공 `#047857`, 오류 `#B91C1C`, 경고 금색 계열 유지 | 성공·오류·경고 의미를 장식 팔레트와 섞지 않음 |

모서리와 그림자는 토큰으로 묶고 실제 화면을 보며 조정한다. 큰 히어로의 위계는 유지하되 반복 카드의 둥근 정도와 그림자는 정적 협동 활동에 가까운 단정한 인상으로 낮춘다. Pretendard 글꼴, QR의 흰 바탕과 대비, 기존 48px 이상 조작 높이는 유지한다.

## 5. 예상 적용 범위

- 주 대상: `apps/cooperative-live/app/globals.css`
- 화면 적용 확인: 시작 페이지, `/teacher`, `/join`, `/play/[sessionId]`의 공통 클래스와 demo/live 분기
- TSX 변경은 현행 `className`만으로 상태를 구분할 수 없는 경우에만 최소 적용한다.
- 제외: 시나리오 문구·역사 서술, 로그인·Auth0, QR/입장키, Convex 데이터·진행 로직, 라우트, 운영 배포, 포털의 정적 협동 CSS

## 6. 구현 순서

1. **사전 검토:** 설치된 Next.js CSS 가이드를 읽고 CSS 토큰·기본 조작 크기·반응형 기준선을 확인했다. 가상 모드에서 시작·교사·입장 화면을 확인했다.
2. **색상 토큰:** 앱 내부 CSS 변수에 역사 팔레트와 성공·오류·경고 상태색을 분리해 정의했다. 다른 앱 CSS 의존성은 추가하지 않았다.
3. **표면 적용:** 히어로·페이지 바탕·카드·역할 카드·배지·버튼·선택 상태·진행률·안내·경고에 새 토큰을 연결했다. 라우트·데이터·화면 정보 구조는 바꾸지 않았다.
4. **접근성·반응형 확인:** 키보드 포커스 테두리, 48/54px 조작 높이, QR 흰 바탕, 네 지정 화면 크기와 760px 전환을 확인했다.
5. **검증:** 데모 교사 흐름과 네 라우트를 네 지정 화면 크기에서 확인하고 `npm run check`를 통과했다. 실제 계정·실제 학생 세션은 사용하지 않았다. 데모 `/play/[sessionId]`는 학생 역할 화면 대신 연결 안내를 보여 주므로 실학생 활동 상태의 시각 검증은 수행하지 않았다.
